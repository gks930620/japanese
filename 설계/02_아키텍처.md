## 2. 렌더링 원칙 — React CSR(SPA) 전용

**서버사이드 렌더링(Thymeleaf/JSP)은 쓰지 않는다.** 백엔드는 JSON REST만 제공하고, 화면은 전부 `frontend/`의 React가 그린다.

동작 방식:

1. 브라우저가 `/courses/2/units/3` 같은 화면 주소로 들어온다.
2. `HomeController`가 등록된 화면 경로를 **와일드카드**로 받아 `forward:/index.html` 한다.
3. `index.html`이 Vite 번들을 로드하고, React Router가 주소를 보고 화면을 그린다.
4. 화면은 `fetch`로 `/api/**`를 호출해 데이터를 채운다.

`HomeController`가 화면 경로를 **개별로 나열하지 않고 섹션 와일드카드(`/courses/**`)로 받는 이유**:
라우팅의 단일 기준은 React Router여야 한다. 서버가 화면 경로를 하나씩 나열하면 프론트가 라우트를 추가할 때마다
백엔드도 고쳐야 하고, 빠뜨린 경로는 500이 되어 사용자가 "다시 시도"만 반복하게 된다.
없는 하위 경로는 SPA가 받아 404 화면을 그린다. (반대로 없는 **API** 경로는 404 JSON — 04_API계약.md 참고.)

> SEO 요구가 들어와도 Thymeleaf/JSP로 돌아가지 않는다. React 기반 SSR/SSG(Next.js 등)를 먼저 검토한다.
> 기본값은 항상 CSR React다.

새 화면 경로를 추가할 때 손대야 하는 곳은 **세 군데**다:
`frontend/src/App.jsx`(라우트) + `HomeController`(forward 대상) + `SecurityConfig`(permitAll 화이트리스트).
셋 중 하나라도 빠지면 새로고침·직접 접근에서 깨진다.

## 4. 프론트 구조

```
frontend/src/
├── App.jsx                라우트 정의 (단일 출처)
├── main.jsx
├── components/            Layout, CourseCard, JpSentence, GrammarBody, Pagination,
│                          StateCards, ProtectedRoute, library/LibraryShell, library/ListItems,
│                          ProgressBar, BookmarkStar, ConfirmDialog, MergeBanner/InlineAlert
├── pages/                 화면 1개 = 파일 1개
├── hooks/                 useApiQuery(데이터 로딩 상태), useLibraryList(자료실 공통 목록)
├── lib/                   http(인증 fetch·토큰 갱신), courses, nav, libraryQuery,
│                          libraryChips, format, theme,
│                          userData(★게스트/회원 분기의 유일한 자리), guestStore(localStorage),
│                          progressView(진도 계산), badgeView(배지 문구)
├── constants/             site.js(사이트명·시작 코스 id), partOfSpeech.js(품사 라벨)
├── context/               AuthContext, UserDataContext(진도·보관함 상태) / userDataStore(컨텍스트·훅)
└── styles/                halo-tokens.css(토큰 단일 출처), halo-components.css, styles.css
```

원칙:

- **문자열·상수는 한 곳에서만 정의한다.** 품사 한국어 라벨은 서버가 내려주지 않으므로 `constants/partOfSpeech.js`가 단일 출처이고,
  GNB 메뉴는 `lib/nav.js`, 색은 `styles/halo-tokens.css`가 단일 출처다.
- **API 호출은 `lib/http.js`를 통한다.** 인증이 필요하면 `callApi`(401 → 토큰 갱신 → 재시도), 공개 API는 `callPublicApi`.
  에러는 raw Error가 아니라 `{status, message, errorCode, errors}` 표준 객체로 던진다.
- 목록 화면의 상태(검색어·필터·정렬·페이지)는 컴포넌트 state가 아니라 **주소 쿼리스트링**에 둔다
  → 새로고침·뒤로가기·주소 공유가 그대로 복원된다.

## 5. 빌드와 실행

### 5-1. 로컬 개발 (권장 — 두 서버를 띄운다)

```bash
./gradlew bootRun          # 백엔드 :8083
cd frontend && npm run dev # 프론트 :5173 (여기로 접속)
```

Vite 개발 서버(5173)가 `/api`, `/custom-oauth2`, `/login/oauth2`를 8083으로 프록시한다(`frontend/vite.config.js`).
화면을 고치면 즉시 반영되므로 프론트 작업은 이 방식이 기본이다.

### 5-2. Spring 하나로 SPA까지 보기 — `copyFrontendBuild` 주의 ⚠️

`gradlew test`와 `gradlew bootRun`은 **프론트 빌드 태스크를 타지 않는다.**
그래서 `bootRun`으로 8083에 접속하면 `src/main/resources/static/`에 들어 있는 **예전 번들**이 뜬다.
최신 화면을 8083에서 보려면 먼저 실행해야 한다:

```bash
./gradlew copyFrontendBuild   # npm ci → npm run build → frontend/dist → src/main/resources/static/
```

Gradle 태스크 체인:

| 태스크 | 하는 일 |
|---|---|
| `frontendInstall` | `npm ci` (package.json/lock이 그대로면 건너뜀) |
| `frontendBuild` | `npm run build` → `frontend/dist` |
| `copyFrontendBuild` | **Sync** — `dist`를 `src/main/resources/static/`에 그대로 맞춘다(`.gitkeep`만 보존) |
| `bootJar` | `copyFrontendBuild`에 의존 → 배포 산출물에는 항상 최신 번들이 들어간다 |

의도적으로 이렇게 갈라 놓은 이유(백엔드 테스트를 프론트 빌드에 묶지 않는 이유):
`gradlew test`가 npm 없이도 돌아야 하고, vite dev 서버가 떠 있을 때 파일 잠금 충돌이 나면 안 되기 때문이다.

`Delete` 태스크로 먼저 비우지 않고 `Sync`를 쓰는 것도 의도적이다 — 프론트 빌드가 실패해도
`static/`이 빈 채로 남는 사고가 구조적으로 일어나지 않는다.

### 5-3. 테스트

```bash
./gradlew test                 # 백엔드: 컨트롤러 통합 테스트만 (H2 인메모리)
cd frontend && npm test        # 프론트: Vitest (vitest run)
```

백엔드 테스트는 `src/test/java/com/test/test/integration/` 아래 컨트롤러 통합 테스트가 기본이다
(예외는 **컨트롤러를 거칠 수 없는 규칙**뿐이며 그 파일 자신이 근거를 적는다 — 현재 `common/config/RailwayDeploymentValidatorTest`(기동 거부) 1건 + `DemoApplicationTests`(컨텍스트 로드))
(코드 컨벤션 — 단위 테스트를 따로 두지 않는다).
프론트 테스트 범위는 훅·분기 로직 위주이고 **스타일/스냅샷 테스트는 하지 않는다**(깨지기 쉽고 회귀 가치가 낮다).

## 6. 로컬 H2 vs 운영 MySQL

핵심 원칙: **같은 코드가 코드 변경 없이 로컬에서도 운영에서도 돈다.** 환경 차이는 Spring 프로파일 + 환경변수로만 흡수한다.
코드 안에 `if (로컬) ... else (운영)` 분기를 넣지 않는다.

| 항목 | 로컬 (기본 프로파일, `application.yml`) | 운영 (`prod`, `application-prod.yml`) |
|---|---|---|
| DB | **H2 인메모리** `jdbc:h2:mem:devdb;MODE=MySQL` | **MySQL** (Railway), `SPRING_DATASOURCE_*` 필수(기본값 없음 = fail-fast) |
| 스키마 | `ddl-auto: create` (매 기동 초기화) | `ddl-auto: update` |
| 시드 | `sql.init.mode: always` — SQL 16개 순서대로 적재 | `sql.init.mode: **never**` — **시드가 들어가지 않는다** ⚠️ |
| 포트 | **8083 고정** | `${PORT:8080}` (Railway 주입) |
| 파일 저장 | 로컬 디스크 `./uploads` (버킷 미설정 시 자동 폴백) | S3 호환 버킷 (`BUCKET_*` 미설정 시 기동 실패) |
| 쿠키 | `Secure=false` | `Secure=true` |
| Swagger | `/swagger-ui.html` 활성 | 비활성 (API 명세 비인증 노출 방지) |
| H2 콘솔 | `/h2-console` 활성 (JDBC URL `jdbc:h2:mem:devdb`) | 없음 |
| 프로파일 활성화 | 없음(기본) | `Dockerfile` ENTRYPOINT가 `-Dspring.profiles.active=prod` 고정 |

**포트 8083은 고정값이다.** 바꾸면 세 곳을 함께 고쳐야 한다:
`application.yml`의 `server.port` / `frontend/vite.config.js`의 프록시 대상 / OAuth 콘솔에 등록한 redirect URI
(`http://localhost:8083/login/oauth2/code/{kakao|google}`).

**운영에 시드가 자동으로 들어가지 않는다**는 점이 가장 자주 발이 걸리는 함정이다 — 07_운영_배포.md를 반드시 읽을 것.

## 7. 응답 인코딩·에러 처리에 관한 전역 설정 (건드리지 말 것)

`application.yml`과 `src/test/resources/application.yml` 양쪽에 같은 값이 들어 있다.
테스트 프로파일 yml이 main을 shadow하기 때문에 **한쪽만 고치면 테스트와 운영이 갈린다.**

| 설정 | 값 | 이유 |
|---|---|---|
| `server.servlet.encoding.charset/force` | `UTF-8` / `true` | charset 미명시 응답을 클라이언트가 ISO-8859-1로 읽어 **일본어·한국어가 깨지는 것**을 막는다. 학습 콘텐츠가 일본어 원문이라 필수 |
| `spring.mvc.throw-exception-if-no-handler-found` | `true` | 미매핑 API를 500이 아니라 **404 JSON**으로 응답하게 한다. 500은 "잠시 후 다시 시도"로 읽혀 클라이언트가 성공하지 못할 재시도를 반복한다 |
| `spring.data.web.pageable.max-page-size` | `100` | `?size=1000000` 같은 과대 요청 방어 |
