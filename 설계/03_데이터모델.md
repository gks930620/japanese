# 03. 데이터 모델

> **이 문서는 무엇인가**
> 학습 콘텐츠가 DB에 어떤 모양으로 들어 있는지, 그리고 콘텐츠를 추가할 때 지켜야 하는 저장 규칙(시드 파일 체계·ID 대역)이다.
> 콘텐츠를 만들거나 쿼리를 짜기 전에 읽는다. 만드는 **내용**의 규칙은 `06_콘텐츠_제작규칙.md`에 따로 있다.

기준일: **2026-08-25** (2026-08-10 최초 작성 → 입문·N1 개통, 영어 과정 증설, 계정 관리 추가분을 반영)

---

## 1. 대전제 — 플레이리스트 구조

- **콘텐츠(문법·한자·어휘·회화)는 독립 테이블이다.**
- **유닛은 매핑 테이블로 콘텐츠를 참조만 한다.** 유닛 안에 콘텐츠 텍스트를 내장하지 않는다.
- 덕분에 자료실(한자 사전·문법 사전)과 코스가 **같은 행을 재사용**한다 — 콘텐츠를 두 번 만들지 않는다.

파생 원칙:

- **레벨은 `course.level_code` 컬럼이다 — `course_no`에서 파생시키지 않는다.** ⚠️ **2026-08-20에 뒤집힌 원칙이다(되돌리지 말 것).**
  파생이 성립하려면 "코스 번호 → 레벨"이 **하나의 함수**여야 하는데, 언어가 둘이 된 순간 성립하지 않는다 —
  일본어 `course_no=1`은 N5이고 영어 `course_no=1`은 E1이다. 입문은 라벨이 "문자"라 문자열로 코드를 만들 수도 없다.
  그래서 코드(`INTRO`·`N5`~`N1`·`E1`~`E5`)를 **DB에 직접** 두고, 표시 문구(`level_label`)와도 분리했다.
  (자료실 `level=` 필터·유닛 응답의 `levelCode`가 전부 이 컬럼 하나를 읽는다 — 단일 출처는 유지된다.)
- **학습 콘텐츠는 시드 전용이다 — 런타임 쓰기 API가 없으므로 생성/수정 시각 컬럼을 두지 않는다.**
- 매핑 테이블의 `sort_order`가 유닛 안에서의 노출 순서다(문법 스텝 순서, 한자 카드 순서, 어휘 표 순서).
- PK는 전부 `Long` + `IDENTITY`.
- **문자열 길이는 가이드 값이지만, 컬럼 존재·NULL 허용 여부·유니크 제약은 계약이다.**

## 2. 관계도

```
course (11 = 일본어 6 + 영어 5)
  └─ course_unit (127 = 일본어 125 + 영어 2) ──── dialog (127) ── dialog_line
        ├─ unit_grammar    ──→ grammar_point (일본어 295 + 영어 4) ─┬─ grammar_example
        │                                                            └─ grammar_rule   (있는 문법만)
        ├─ unit_kanji      ──→ kanji (1,350 — **일본어 전용**) ── kanji_word
        ├─ unit_expression ──→ expression (12 — **영어 전용**, 한자 자리) ── expression_example
        └─ unit_vocabulary ──→ vocabulary (일본어 2,016 + 영어 30)
```

코스별 정확한 수량은 **§5 고정 ID 계약**에 있다(2026-08-25 실측).

회화는 `course_unit.dialog_id` FK로 직접 물려 있어 **유닛당 정확히 1편**이다.
(dialog 자체는 독립 테이블이라 나중에 재사용할 여지는 남아 있다.)

`grammar_point`·`kanji`·`vocabulary`의 행 수가 매핑 수보다 조금 많은 것은 유닛에 매핑되지 않은 잔여 행 때문이다.
자료실에는 **매핑된 것만** 노출된다(자료실 목록은 매핑을 조인해 만든다).

## 3. 테이블 정의

### course (11행 — 일본어 6 + 영어 5)

| 컬럼 | 타입 | 제약 | 비고 |
|---|---|---|---|
| id | BIGINT | PK | **고정 ID 계약** (§5) |
| course_no | INT | NOT NULL, **UNIQUE(language, course_no)** | 학습 경로 순서이자 정렬 기준. 일본어 0~5 · 영어 1~5. **단독 UNIQUE가 아니다** — 일본어 1(N5)과 영어 1(E1)이 공존한다 |
| level_code | VARCHAR(10) | **NOT NULL** | `INTRO`·`N5`~`N1`·`E1`~`E5`. 자료실 `level=` 필터와 유닛 응답 `levelCode`의 단일 출처(§1 파생 원칙) |
| language | VARCHAR(2) | **NOT NULL**, DEFAULT `JA` | `JA` 또는 `EN`. 언어 분리는 **조회 조건 하나**로 끝난다 — 코스·유닛·콘텐츠 테이블을 복제하지 않는다 |
| level_label | VARCHAR(30) | NOT NULL | "JLPT N5" 등 |
| title | VARCHAR(50) | NOT NULL | "왕초보" 등 |
| target_audience | VARCHAR(100) | NOT NULL | 카드의 "이런 분께" |
| goal | VARCHAR(150) | NOT NULL | 카드의 도달점 |
| notice | VARCHAR(200) | NULL | 보조 안내. **사람이 쓴 문구다 — 상태 판정에 쓰지 않는다**(N5는 20유닛이 다 찼는데도 값이 있다) |
| planned_unit_count | INT | NULL | **계획 유닛 수**(2026-09-21 추가). NULL = 계획값 없음 = 지금 있는 유닛이 전부. 부분 공개 중인 코스만 값(E1 = 15, §5-2). 화면이 "완주"와 "열린 데까지의 끝"을 가르는 유일한 근거다(설계/04 §2-3-A · 08 C-29) |
| description | VARCHAR(300) | NULL | 코스 상세 소개. **AVAILABLE 코스는 필수** |
| status | VARCHAR(20) | NOT NULL | `AVAILABLE` \| `PREPARING` (enum `CourseStatus`) |

### course_unit (127행 = 일본어 125 + 영어 2)

| 컬럼 | 제약 | 비고 |
|---|---|---|
| id | PK | |
| course_id | FK → course, NOT NULL | |
| unit_no | NOT NULL, **UNIQUE(course_id, unit_no)** | **PK가 아니라 코스 안 순번** — URL의 `{unitNo}` |
| title | VARCHAR(100) NOT NULL | |
| dialog_id | FK → dialog, NOT NULL | 유닛당 회화 1편 |

### grammar_point / grammar_example / grammar_rule

| 테이블 | 컬럼 |
|---|---|
| `grammar_point` | `id` / `name` VARCHAR(100) NN(일본어 명칭) / `name_ko` VARCHAR(100) NN(한국어 부제) / `explanation` VARCHAR(500) NN |
| `grammar_example` | `id` / `grammar_point_id` FK NN / `sort_order` NN / `jp` VARCHAR(300) NN / `kana` VARCHAR(300) **NULL 가능** / `meaning_ko` VARCHAR(300) NN |
| `grammar_rule` | `id` / `grammar_point_id` FK NN / `sort_order` NN / `group_label` VARCHAR(50) NN / `pattern` VARCHAR(100) NN / `example_before` VARCHAR(50) NN / `example_after` VARCHAR(50) NN |

`grammar_rule`은 활용 규칙표다. **없는 문법이 정상**이고(일본어 295개 중 **87개**만 보유 — 2026-09-03 라이브 `hasRules=true` 실측, 테스트 `CourseCatalog.totalRuleTables()`와 같은 값), API는 빈 배열로 내려간다.
4개 컬럼 전부 non-null이어야 한다.

### dialog / dialog_line

| 테이블 | 컬럼 |
|---|---|
| `dialog` | `id` / `title` VARCHAR(100) NN — 장면 제목("건물에서 화장실 위치 묻기") |
| `dialog_line` | `id` / `dialog_id` FK NN / `sort_order` NN / `speaker` VARCHAR(30) NN / `jp` VARCHAR(300) NN / `kana` VARCHAR(300) NULL / `meaning_ko` VARCHAR(300) NN |

### kanji / kanji_word

| 컬럼 | 제약 | 비고 |
|---|---|---|
| `kanji.letter` | VARCHAR(4) NN **UNIQUE** | **컬럼명이 `character`가 아닌 이유: `character`는 SQL 예약어다.** UNIQUE 제약이 코스 간 한자 중복을 기동 시점에 막는다 |
| `kanji.meaning_ko` | VARCHAR(50) NN | 훈음 — "사람 인" |
| `kanji.onyomi` | VARCHAR(50) NULL | 가타카나, `・` 구분 |
| `kanji.kunyomi` | VARCHAR(50) NULL | 히라가나, `・` 구분 |
| | | **onyomi·kunyomi 둘 다 null은 금지** (앱 레벨 검증, DB 제약 아님) |
| `kanji_word` | `id` / `kanji_id` FK NN / `sort_order` / `word` VARCHAR(50) NN / `kana` VARCHAR(50) NULL / `meaning_ko` VARCHAR(100) NN | 글자당 1~2행 |

### vocabulary

| 컬럼 | 제약 | 비고 |
|---|---|---|
| `id` | PK | |
| `word` | VARCHAR(50) NN | **UNIQUE를 걸지 않는다** — §6 참고 |
| `kana` | VARCHAR(50) NULL | 전부 가나면 NULL (화면은 `─`) |
| `meaning_ko` | VARCHAR(100) NN | |
| `part_of_speech` | VARCHAR(20) NULL 허용 | **DB는 NULL을 허용하되(마이그레이션 안전) 시드는 전량 기입하고 테스트가 강제한다.** 자료실 필터에 "미분류"가 생기면 사전으로서 못 쓴다 |

### expression / expression_example — **영어 과정 전용** (2026-08-20 추가)

영어 유닛에서 **한자 자리에 들어가는 것**이 표현이다(단어보다 크고 문장보다 작은, 통째로 외워 쓰는 덩어리).

| 컬럼 | 제약 | 비고 |
|---|---|---|
| `expression.id` | PK | ID 대역 9000~9999 (§7-2) |
| `expression.text` | VARCHAR(100) NN | 예: `get up`. **UNIQUE를 걸지 않는다** — `kanji.letter`와 정반대다 |
| `expression.meaning_ko` | VARCHAR(200) NN | |
| `expression.usage_note` | VARCHAR(300) NULL | 언제·어떻게 쓰는가. 없으면 화면이 문단을 만들지 않는다 |
| `expression.ipa` | VARCHAR(100) NULL | 국제음성기호 |
| `expression.ko_approx` | VARCHAR(100) NULL | 한글 근사 표기. **IPA와 함께** 존재한다(08 F-18) |
| `expression_example` | `id` / `expression_id` FK NN / `sort_order` NN / `en` VARCHAR NN / `meaning_ko` NN | 예문 |

**`text`에 UNIQUE를 걸지 않는 이유**: 한자는 상용한자 2,136자라는 **닫힌 집합**이라 중복이 곧 오류지만,
표현은 **열린 집합**이고 같은 표현이 상위 코스에서 다른 뉘앙스로 다시 나오는 것이 정상이다.
코스 **내부** 중복만 금지이며 그것은 시드 규칙이다(06).

**영어에는 `kana`가 없다.** 발음은 `ipa` + `ko_approx` 두 컬럼이다 —
kana 계약("원문에 한자가 있을 때만")을 `KanaContract`가 강제하므로 영어를 넣으면 검증기가 거부한다.

### 매핑 4종

| 테이블 | 컬럼 | 제약 |
|---|---|---|
| `unit_grammar` | id / unit_id FK / grammar_point_id FK / sort_order | UNIQUE(unit_id, grammar_point_id) |
| `unit_kanji` | id / unit_id FK / kanji_id FK / sort_order | UNIQUE(unit_id, kanji_id) |
| `unit_vocabulary` | id / unit_id FK / vocabulary_id FK / sort_order | UNIQUE(unit_id, vocabulary_id) |
| `unit_expression` | id / unit_id FK / expression_id FK / sort_order | UNIQUE(unit_id, expression_id) — **영어 유닛 전용**(한자 매핑 자리) |

**매핑 테이블의 콘텐츠 FK에는 인덱스가 필수다** (`unit_kanji(kanji_id)`, `unit_grammar(grammar_point_id)`, `unit_vocabulary(vocabulary_id)`).
자료실이 "이 한자를 어느 유닛에서 배우나"라는 **역방향 조회를 매 요청마다** 하기 때문이다.
엔티티의 `@Table(indexes = …)`로 선언한다(H2·MySQL 공통 생성).

## 4. 계정·커뮤니티·파일 (보일러플레이트 유래)

```
users (111) ─ user_roles (전부 'USER')
            └ refresh_entity
users ─< community (30) ─< comment (36)
files      (ref_id + ref_type + file_usage 로 게시글에 느슨하게 연결 — FK 아님)
(채팅 없음 — 2026-08-17 기능 제거. chat_* 테이블·엔티티가 존재하지 않는다)
```


**`users`의 보안 관련 컬럼 2개**(2단계에서 추가 — 계정 관리):

| 컬럼 | 제약 | 비고 |
|---|---|---|
| `token_version` | BIGINT NOT NULL DEFAULT 0 | **access 토큰 무효화의 유일한 수단.** 비밀번호 변경·탈퇴가 +1 하면 그 이전에 발급된 access 토큰이 즉시 죽는다(04 §4). 리프레시에는 싣지 않는다 — 그쪽 폐기 수단은 `refresh_entity` 행 삭제다 |
| `withdrawn_at` | DATETIME NULL | **행 존재 여부가 아니라 이 값이 탈퇴 사실이다.** 탈퇴는 행을 지우지 않고 익명화한다(글·댓글이 `user_id NOT NULL FK`라 지우면 함께 사라진다) |

- 역할은 `USER` 하나뿐이다. `ADMIN`·`hasRole`·`@PreAuthorize`가 코드에 존재하지 않는다.

**`refresh_entity.token`은 VARCHAR(512)다** — 255가 아니다.
2026-08-25에 access·refresh 토큰에 `jti`를 넣자 토큰 문자열이 258자가 되어 **로그인이 500으로 터졌다**(컬럼 초과).
JWT 길이는 클레임이 늘면 같이 는다 — **이 컬럼은 여유를 두고 잡는다.**

- `files`가 FK 없이 `ref_id + ref_type`으로 연결되므로, **소유권 검증을 서비스에서 되짚어야 한다**(07 §5 참고).
- **채팅은 제거됐다**(2026-08-17, 사용자 결정 — 08 D-2 종결). 보일러플레이트의 `chat_room`과 2단계에서 잠시 만든 `chat_room_member`·`chat_message`까지 전부다. 로컬 H2는 인메모리 `create`라 엔티티가 사라지면 자연 소멸하고, 운영은 이 스키마로 배포한 적이 없다.

## 4-1. 사용자 학습 데이터 — 진도 · 보관함

> 2026-08-14 이터레이션에서 추가됐다. 학습 **콘텐츠**는 여전히 시드 전용이고, 여기 있는 세 테이블만 런타임에 쓰인다.

```
users ─┬─ user_last_position   (0..1)   마지막으로 보던 위치 — 사용자당 최대 1행
       ├─< user_unit_completion         완료한 유닛 — (course_id, unit_no)로 가리킨다
       └─< user_bookmark                보관함 — (target_type, target_id)
```

### user_last_position — 마지막 위치 (사용자당 0 또는 1행)

| 컬럼 | 타입 | 제약 | 비고 |
|---|---|---|---|
| id | BIGINT | PK, IDENTITY | |
| user_id | BIGINT | NOT NULL, **UNIQUE**, FK → users | 마지막 위치는 **사이트 전체에 하나**라는 규칙을 DB가 강제한다 |
| course_id | BIGINT | NOT NULL | |
| unit_no | INT | NOT NULL | |
| step_key | VARCHAR(40) | NOT NULL | `grammar-0` `dialog` `kanji` `vocab` `summary` (04 §7-2) |
| updated_at | DATETIME | NOT NULL | 병합 시 "더 최근" 판정 기준 |

**행이 없음 = 마지막 위치가 없음.** 전 컬럼 NOT NULL이라 "반쯤 빈 행"이 생기지 않는다.

### user_unit_completion — 완료한 유닛

| 컬럼 | 제약 | 비고 |
|---|---|---|
| id | PK | |
| user_id | NOT NULL, FK → users | |
| course_id / unit_no | NOT NULL | |
| completed_at | NOT NULL | |
| | **UNIQUE(user_id, course_id, unit_no)** | 켜기가 멱등이 된다 |
| | INDEX(user_id) | 화면마다 사용자별 전량을 읽는다 |

**행 존재 = 완료.** 취소는 행 삭제다 — `is_completed` 불리언을 두지 않는다(취소한 완료를 남길 이유가 없고, 조회마다 조건이 하나 는다).

### user_bookmark — 보관함

| 컬럼 | 제약 | 비고 |
|---|---|---|
| id | PK | |
| user_id | NOT NULL, FK → users | |
| target_type | VARCHAR(20) NOT NULL | `KANJI` \| `GRAMMAR` \| `VOCABULARY` (enum `BookmarkType`, STRING) |
| target_id | BIGINT NOT NULL | 아래 규칙 |
| created_at | NOT NULL | **"최근 담은 순" 정렬의 유일한 근거**(동률은 `id DESC`) |
| | **UNIQUE(user_id, target_type, target_id)** | 담기가 멱등이 된다 |
| | INDEX(user_id, target_type) | 목록·개수가 항상 이 조합으로 걸린다 |

**`target_id`가 가리키는 것 (★ 중요)**

| target_type | target_id | 근거 |
|---|---|---|
| `KANJI` | `kanji.id` | `letter`가 UNIQUE라 글자 하나 = 행 하나 |
| `GRAMMAR` | `grammar_point.id` | 1:1 |
| `VOCABULARY` | **표제어 대표 id** = 자료실 어휘 목록 행의 `id`(병합 그룹 `(word, kana)`에서 학습 순서가 가장 이른 `vocabulary.id`) | 담기 1단위가 **병합된 표제어 1행**이기 때문. `vocabulary` 행을 그대로 담으면 `応援`(N4·N3·N2 3행)이 보관함에서 세 줄로 갈린다 |

- **서버가 어떤 member id를 받아도 대표 id로 정규화해 저장한다.** 병합 규칙의 단일 출처는 자료실 서비스다(08 A-2·A-4).
- 그래서 유닛 학습 응답의 어휘에 `entryId`가 있다(04 §7-1) — 화면은 어디서든 같은 값으로 ★를 판정한다.

### FK를 어디에 걸고 어디에 안 거는가

| 참조 | FK | 이유 |
|---|---|---|
| `user_id` → `users.id` | **건다** | 사용자와 함께 정리돼야 하는 소유 관계다 |
| `course_id` / `unit_no` / `target_id` → 콘텐츠 | **걸지 않는다** | 콘텐츠는 **시드 전용이고 통째로 다시 적재될 수 있다**(§7). FK를 걸면 재적재가 사용자 데이터에 막히거나 사용자 데이터가 함께 지워진다. `files`의 `ref_id`와 같은 판단(§4) |

**대가는 앱이 진다 — 두 겹으로 갚는다.**

1. **쓰기 시점 검증** — 없는 코스·유닛·항목이면 저장하지 않고 404(준비중 코스는 `COURSE_PREPARING`).
2. **읽기 시점 필터** — 조회는 콘텐츠와 조인해 **지금 존재하는 것만** 내려보낸다. 콘텐츠 개편으로 사라진 유닛·항목은 조용히 빠지고 개수도 함께 준다.

> ⚠️ 읽기 시점 필터는 **API만으로 재현할 수 없다**(쓰기가 이미 막아 고아 행을 만들 수 없다). 통합테스트가 없는 유일한 규칙이며 결함이 아니다.

### 코스 제목·레벨·유닛 제목을 복제하지 않는다

`course_id`·`unit_no`만 저장한다. 화면에 필요한 이름은 공개 API에서 온다 —
**비로그인 사용자도 같은 화면을 그리므로 이름의 출처는 어차피 공개 API 한 곳이어야 한다**(§9 파생 컬럼 금지와 같은 판단).

### 동시 쓰기 — 사용자 행 잠금으로 줄을 세운다

★ 연타·완료 더블클릭이 가장 자연스러운 조작이라 같은 사용자의 쓰기가 겹친다.
"조회 후 없으면 삽입"은 그때 둘 다 "없음"을 보고 둘 다 삽입해 UNIQUE에 걸리는데,
**그 예외는 이미 롤백 대상이 된 트랜잭션 안에서 삼킬 수 없다**(= 500).

- 그래서 쓰기 진입점에서 `users` 행을 `PESSIMISTIC_WRITE`로 잠근다(`UserRepository.lockForUserDataWrite`).
  잠금 순서가 항상 "사용자 행 먼저"라 교착이 없다.
- **격리 수준을 `READ_COMMITTED`로 명시한다.** 운영 MySQL 기본값(REPEATABLE READ)에서는 잠금을 얻고 다시 조회해도
  트랜잭션 시작 시점 스냅샷을 봐서 먼저 들어간 행을 못 보고 다시 삽입한다 — 줄을 세운 의미가 사라진다.
  (H2는 이미 READ_COMMITTED라 로컬에서는 증상이 드러나지 않는다. **DB 기본값에 맡기지 않는 이유가 이것이다.**)
- 빼기·완료 취소는 엔티티를 읽어 지우지 않고 **벌크 삭제**다 — 동시에 두 번 꺼도 "이미 사라진 행"으로 실패하면 안 된다.
- **쓰기 트랜잭션은 전부 이 규칙을 따른다 — 병합(`POST /api/me/merge`)도 포함이다.** 병합은 트랜잭션을 열자마자
  콘텐츠를 먼저 읽는데, REPEATABLE READ에서는 그 순간 스냅샷이 고정돼 **뒤에 잡는 잠금이 무의미해진다.**
  실사용은 배너 [합치기] 1회지만 재시도·다중 탭이 겹칠 수 있고, 계약이 병합을 **멱등**으로 못 박았다(04 §6-5).

| 104 | 4 | `E4` | 뉘앙스 | PREPARING | 0 / 20 | — | — | — |

> 실제로 그 상태였고, 유닛 8의 표현을 일부러 지워도 테스트가 통과하는 것으로 확인했다.
> **"계획" 칸은 `course.planned_unit_count`이고 순회 범위가 아니다** — 아직 없는 유닛까지 돌면 전부 404다.

**영어 코스에는 한자가 0행이다** — `kanji`·`kanji_word`·`unit_kanji`에 영어 대역 행이 없다. 그 자리가 `expression`이다.

## 6. 유니크 제약을 어디에 걸고 어디에 안 거는가 (중요)

| 테이블 | UNIQUE | 이유 |
|---|---|---|
| `kanji.letter` | **건다** | 한자는 글자 1자이므로 같은 글자가 두 행일 이유가 없다. **코스 간 한자 중복 금지**를 기동 시점에 강제한다 |
| `vocabulary.word` | **걸지 않는다** | **어휘는 동일 표기·다른 의미가 정상이다.** `応援`(N4 "응원" / N2 "지원"), `悪い`("나쁘다" / "미안하다") — UNIQUE는 도메인상 **틀린 제약**이다 |

"한자는 되는데 어휘는 안 된다"가 아니라 **성질이 다르다.**
대신 어휘는 **코스 내부 중복만** 테스트로 금지한다(`vocabulary_is_not_duplicated_within_a_course`).
코스 간 중복이 허용되는 이유는 `08_결정기록.md`에 있다.

## 7. 시드 파일 체계

콘텐츠를 넣는 방법은 하나뿐이다: **`src/main/resources/data-*.sql`(UTF-8)에 INSERT를 쓰고 서버를 다시 띄운다.**
학습 콘텐츠용 쓰기 API도, 관리자 편집 화면도 없다.

### 7-1. 파일 구성

| 코스 | 시드 파일 |
|---|---|
| N5 | `data-course-content.sql` / `data-course-units.sql` |
| N4 | `data-course-n4-content.sql` / `data-course-n4-units.sql` |
| N3 | `data-course-n3-content.sql` / `data-course-n3-units.sql` |
| N2 | `data-course-n2-content.sql` / `data-course-n2-units.sql` |
| 입문 | `data-course-intro-content.sql` / `data-course-intro-units.sql` |
| N1 | `data-course-n1-content.sql` / `data-course-n1-units.sql` |
| 영어(코스 101~105) | `data-course-en-content.sql` / `data-course-en-units.sql` |
| 공용 | `data-courses.sql` (일본어 코스 6행. **영어 5행은 `data-course-en-content.sql`이 직접 INSERT**한다 — 공용 파일을 건드리지 않는 것이 영어 증설의 전제였다) |
| 마무리 | `data-h2-reset-identity.sql` (**H2 전용 — 운영에서 실행하지 않는다**) |

`*-content.sql`은 콘텐츠 행(문법·예문·규칙표·회화·한자·어휘)을,
`*-units.sql`은 유닛 행과 유닛↔콘텐츠 매핑을 담는다. content가 units보다 **먼저** 로드돼야 한다.

로드 순서는 `application.yml`의 `spring.sql.init.data-locations`에 정의돼 있고,
**`src/test/resources/application.yml`에도 같은 목록이 있다** — 테스트 프로파일 yml이 main을 shadow하므로 둘 다 고쳐야 한다.

### 7-2. ID 대역 규칙 ⚠️

**모든 콘텐츠 테이블에서 코스별 ID 대역을 지킨다.** 여러 담당이 병렬로 시드를 쓸 때 충돌하지 않게 하기 위해서다.

| 코스 | 대역 | 현재 실제 사용 |
|---|---|---|
| N5 | `1 ~ 999` | |
| N4 | `1000 ~ 1999` | 1001~1320 |
| N3 | `2000 ~ 2999` | 2001~2525 |
| N2 | `3000 ~ 3999` | 3001~3400 |
| 입문 | `4000 ~ 4999` | 4001~4260 |
| N1 | `5000 ~ 5999` | 5001~5900 |
| **영어** | `9000 ~ 9999` | 9001~9200 (코스 id는 `101~105`) |

대역은 `course_unit`, `grammar_point`, `grammar_example`, `grammar_rule`, `dialog`, `dialog_line`,
`kanji`, `kanji_word`, `vocabulary`, `unit_grammar`, `unit_kanji`, `unit_vocabulary` **전부에 공통 적용**된다.
코스당 최대 필요 행 수(어휘 ~500)가 대역 폭 1000 안에 넉넉히 든다.

### 7-3. H2 IDENTITY 리셋

명시 ID로 INSERT하면 H2의 IDENTITY 시퀀스가 올라가지 않아, 이후 신규 INSERT(회원가입·글쓰기)에서 PK가 충돌한다.
그래서 마지막에 `data-h2-reset-identity.sql`이 시퀀스를 올린다 — 사용자 테이블은 1000부터, **콘텐츠 테이블은 대역 전체 위인 10000부터**.
(운영은 `sql.init.mode: never`라 이 스크립트가 돌지 않는다.)

### 7-4. 파일 수정 권한 (병렬 작업 충돌 방지)

**개발자가 고치지 않는 파일 — senior-dev 관리:**

- `src/main/resources/application.yml` 과 `src/test/resources/application.yml` (시드 파일 등록 포함)
- `data-h2-reset-identity.sql`
- `data-courses.sql` (코스 6행)
- 다른 담당의 코스 시드 파일

**AVAILABLE 코스의 `description`은 `data-courses.sql`에 직접 쓰지 않는다.**
각 코스의 content 파일에서 `UPDATE course SET description = ... WHERE id = ...`로 채운다.

## 8. 새 코스를 추가할 때 (예: 입문 / N1)

1. `data-courses.sql`의 해당 행 `status`를 `PREPARING` → `AVAILABLE`로 바꾼다 (senior-dev).
2. **한자 목록을 먼저 확정한다.** 시드를 쓰기 전에 — 이유는 `08_결정기록.md` 참고. **기존 한자 전량**(2026-09 실측 1,350자)과 겹치면 안 된다 — 총량은 코스가 열릴 때마다 늘어나므로 숫자가 아니라 "현재 전량"으로 읽는다.
3. 시드 파일 2개(`*-content.sql`, `*-units.sql`)를 대역(입문 4000~ / N1 5000~) 안에서 작성한다.
4. `application.yml` 두 곳의 `data-locations`에 등록한다 — **`data-h2-reset-identity.sql`보다 앞에.**
5. 코스 소개는 content 파일에서 `UPDATE`로 채운다.
6. `06_콘텐츠_제작규칙.md`의 수량·표기 규칙을 지킨다. 테스트가 전수 검증한다.

`status`만 되돌리면 코스를 다시 감출 수 있다 — 순차 공개가 필요하면 그렇게 한다.

## 9. 성능에 관한 결정 (되돌리려 하지 말 것)

| 항목 | 결정 | 이유 |
|---|---|---|
| 학습 순서 정렬 | **매 요청 조인으로 계산.** 정렬용 파생 컬럼을 두지 않는다 | 데이터가 1,350/2,016/295건으로 작다. 파생값을 두면 **시드를 고칠 때 갱신 누락이라는 정합성 위험**이 이득보다 크다 |
| 레벨 필터 | **`course.level_code` 컬럼을 읽는다**(§1) | ⚠️ 여기만 파생을 쓰지 않는다. `course_no` 파생은 언어가 둘이 되는 순간 성립하지 않는다(일본어 1=N5, 영어 1=E1). **되돌리지 말 것** |
| N+1 | 목록은 매핑·코스·유닛을 조인해 **DTO로 직접 프로젝션**. 상세의 words/examples/rules는 단건이라 `@OrderBy` + batch fetch(`default_batch_fetch_size: 100`) | |
| 어휘 병합·가나순 정렬 | **서비스(Java)에서 처리** | DB `GROUP BY`로는 가타카나→히라가나 정규화가 불가능하고, 페이징이 병합의 함수다. 자세한 근거는 `04_API계약.md` §3-7 |
| 캐시 | **도입하지 않는다** | 읽기 전용·소규모라 필요 없고, **캐시는 무효화 규칙이라는 새 복잡도를 만든다** |

규모가 수만 건으로 커지면 `vocabulary`에 정렬용 파생 컬럼(`kana_sort`)을 재검토할 수 있다. 지금은 불필요하다.
