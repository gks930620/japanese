## 1. 최상위 규칙 — kana 표기

**세 스택 공통 계약이자 가장 자주 어기는 규칙이다.**

> **`kana` 필드는 원문(`jp` / `word`)에 한자가 포함될 때만 값이 있다. 원문이 전부 가나면 `null`이다.**

적용 대상 전부: `grammar_example.kana`, `dialog_line.kana`, `vocabulary.kana`, `kanji_word.kana`.

⚠️ **이 계약은 일본어 과정 전용이다.** 영어 콘텐츠의 `kana`는 예외 없이 `NULL`이고 발음은 `ipa`+`koApprox`가 담당한다 → **§11-3**.

| 원문 | kana | 화면 |
|---|---|---|
| `ここは 教室です。` | `ここは きょうしつです。` | 3줄 병기 |
| `ここは どこですか。` | **`NULL`** | 가나 줄을 렌더링하지 않음 |
| 어휘 `建物` | `たてもの` | 읽기 열에 표시 |
| 어휘 `トイレ` | **`NULL`** | 읽기 열에 `─` |

### 왜 이렇게 하는가

화면 규칙("원문과 같으면 읽기 줄을 생략")을 **데이터 계약(null)으로 끌어올린 것**이다.
그래야 프론트가 문자열 비교를 하지 않아도 된다.

### 위반 시 프론트가 아니라 **데이터를 고친다** ⚠️

`JpSentence`가 문자열 비교 없이 `kana != null`로만 렌더링하는 것은 **의도된 설계**다.
방어 로직을 프론트에 넣으면 계약이 무력해지고 **위반 데이터가 조용히 숨는다.**
실제로 이 규칙을 어긴 회화 대사 2건이 화면에 같은 문장을 2줄로 출력한 결함이 있었고, 데이터를 고쳐서 해결했다.

### 검증

`all_units_follow_kana_notation_contract` — 6개 코스 125유닛(입문·N1 포함)의 문법 예문·회화 대사·어휘·한자 예시 단어 **전수**에 대해:

1. 한자가 있으면 `kana`가 non-null, 없으면 null
2. **공백을 무시한 뒤 `kana ≠ 원문`** (중복 렌더 금지)

> 교훈: 계약을 문서에만 적고 테스트로 옮기지 않으면 TDD 관문이 무력해진다.
> 초기 테스트는 `has("kana")`(필드 존재)만 봐서 규칙 자체를 검증하지 못했다.
> **필드 존재가 아니라 규칙을 검증해야 한다.**

### 2-3. N5~N2 유닛 제목의 원본 — **없다 (시드가 사실)** ⚠️

입문·N1은 실라버스가 있었지만 **N5·N4·N3·N2(90유닛)의 제목은 어느 문서에도 원본이 없다.**
`설계/`·`진행사항/` 전문 검색으로 확인했고, **유일한 출처는 시드 `data-course-units.sql`·`data-course-n*-units.sql`** 이다.

- 그러므로 N5~N2 제목에 대해서는 **"실라버스와 일치시킨다"는 규칙이 적용될 대상이 없다.** 대조 대상은 시드 자신이다.
- **제목을 고칠 때 확인할 것**: 유닛 제목은 코스 상세의 유닛 목록·유닛 학습 화면 머리말·자료실 "어디서 배우나"에 **같은 값이 세 곳**으로 나간다. 서버가 한 곳(`course_unit.title`)에서 내려주므로 시드만 고치면 되지만, **테스트가 제목 문자열을 단정하고 있는지 먼저 확인**한다.
- 90개 제목을 지금 여기로 옮겨 적지는 않는다 — 원본이 없는 값을 문서에 복제하면 **두 사실이 생기고 곧 갈린다.** 옮기려면 제목 감수가 먼저다(§10).

## 3. 문법

- 문법 하나당 **예문 1개 이상**(권장 2~4개).
- 예문은 3줄 병기가 가능하도록 `jp` / `kana` / `meaning_ko`를 갖춘다(§1 규칙 준수).
- **`name`에 한국어 낱말을 섞지 않는다** (2026-09-21 QA 결함 — `〜いかん 계열`).
  "계열 · 정리 · 구분" 같은 말이 필요하면 **일본어로** 적거나(`〜の整理` · `総整理` · `の用法`) 아예 **형태를 나열**한다.
  `name`은 진단·확인 문제의 **보기로 그대로 나가고**, N2·N1 진단은 보기도 일본어다(09 §3-4) —
  다섯 보기 중 하나만 한글이면 **뜻을 몰라도 눈에 띄어** 측정이 흐려진다. 한국어로 할 말은 `name_ko`의 자리다.
- **한 문법이 여러 형태를 묶을 때의 명칭 관례** (실측 295건에서 추린 것 — 새 규칙이 아니라 이미 쓰고 있는 방식):
  - 형태 2~3개 → **`〜A・〜B`** 로 나열한다. 가장 흔하다(`〜べきだ・〜べからず` · `〜に即して・〜に則って` · `〜てあげる・〜てくれる・〜てもらう`).
  - 묶음의 **머리말이 필요할 때만** 괄호를 쓴다 — `분류명(형태·형태)`(`助数詞(〜人・〜枚・〜本)` · `書面の慣用表現(〜の段・〜のほど)`).
  - **이름은 20자 이내**로 둔다(현행 최장 20자 `論説の接続(しかるに・ゆえに・いわんや)`). 보기 자리에 서는 값이라
    혼자 길면 그것도 눈에 띈다 — 형태가 넷 이상이면 **대표형만** 이름에 두고 나머지는 `explanation`·활용표(§4)가 받는다.

## 4. 활용 규칙표 (`grammar_rule`)

활용·변형 계열 문법에만 붙인다. **서술형 문법에는 붙이지 않는다** — 규칙표가 없는 것이 정상이다(2026-08-31 실측: 문법 295개 중 **87개 보유 · 총 359행**, 나머지 208개는 `rules: []`).

### 작성 규칙

| 규칙 | 내용 |
|---|---|
| 한 행 = 한 변환 | `groupLabel` + `pattern` + 변환 예 1쌍(`exampleBefore` → `exampleAfter`) |
| **최대 8행** | 표가 예문 블록보다 커지면 안 된다 |
| 라벨은 짧게 | |
| **언어학 용어 금지** | "음편" 같은 용어 대신 **어미를 나열**한다 — "う·つ·る" |
| 4개 컬럼 전부 채운다 | non-null |
| 없으면 행이 없다 | API는 `[]`로 내려간다(null 아님) |

> 규칙표를 도입한 이유: "한 줄 설명 + 예문 2개"로는 て형의 활용 규칙 5종과 예외를 가르칠 수 없다.
> **서술형 문법에는 `explanation` 한 줄로 충분하지만, 변환 규칙 계열에는 표 형태 데이터가 필요하다.**

## 5. 회화 (`dialog`)

| 규칙 | 내용 |
|---|---|
| 유닛당 | **정확히 1편** |
| 화자 | **2명 이상** (`speaker` — 배지에 첫 글자를 쓴다) |
| 대사 줄 수 | 입문·N5·N4 **2줄 이상** / N3·N2 **4줄 이상** / N1 **5줄 이상**(실측 6) |
| 문법 사용 | **그 유닛의 문법이 실제로 쓰인 장면이어야 한다** |
| `title` | 장면 제목 — "건물에서 화장실 위치 묻기" |

### 회화에 관한 두 가지 판정 (반복 논쟁 방지)

**① 이후 유닛의 문법이 회화에 먼저 등장해도 결함이 아니다.**
요구 사항은 "그 유닛의 문법이 실제로 쓰일 것"이지 "이후 문법을 배제할 것"이 아니다.
자연스러운 일본어가 우선이고, 실제로 유닛 제목 자체가 이후 문법을 함축하는 경우도 있다
(예: N5 유닛 15 "좋았지만 비쌌어요"는 형용사 과거형이 유닛 16 소관이다).
순서 문제라면 회화가 아니라 **실라버스 수준에서 감수**할 일이다.

**② 실라버스의 "회화 주제"는 장면 계획이지 대본 사양이 아니다.**
계약은 dialog의 구조(화자 2명 이상 · 최소 대사 수 · 유닛 문법 사용)이고, 이것만 충족하면 된다.
실라버스에 "안내 방송 읽어 주기" 같은 **1인 낭독 장면**이 적혀 있으면 문답 형태로 바꿔도 된다 — 낭독은 화자 2명 계약과 구조적으로 충돌한다.

> **product-planner에게**: 앞으로 실라버스의 회화 주제는 **2인 이상 대화가 가능한 장면**으로 기술할 것.

## 6. 한자

> 영어 과정에는 한자가 없다 — 유닛의 그 자리에는 **표현(expression)** 이 들어가고 중복 규칙도 정반대다 → **§11-5**.

| 규칙 | 내용 |
|---|---|
| **코스 간 중복 0** | 누적 체계. `kanji.letter` UNIQUE가 기동 시점에 강제한다 |
| 유닛당 | 입문 **0자**(한자를 배우지 않는다) / N5 5자 / N4 10자 / N3·N2·N1 14자 |
| 읽기 | **음독·훈독 중 최소 1개 이상.** 둘 다 null 금지 |
| 표기 | onyomi = 가타카나 `・` 구분 / kunyomi = 히라가나 `・` 구분 |
| 훈음(`meaning_ko`) | "사람 인" 형태 |
| 예시 단어 | 글자당 **1~2개**(최소 1개). **코스 간 편차는 허용한다** — 아래 판정 참조 |

담당자가 실제로 지켜야 할 것은 단순하다: **앞 코스의 한자 행을 자기 유닛에 매핑하지 말고 새 글자만 등록한다.**

### 예시 단어 수의 코스 간 편차는 결함이 아니다 (2026-08-25 판정 L2)

실측(유닛 125개 전수)은 **N5 2개 / N4·N3·N2 1개 / N1 2개**다. 하한(글자당 1개)은 1,350자 전부가 지켰다.

- **소급 보강하지 않는다.** 900자에 예시 단어를 새로 붙이려면 단어 900개를 만들고 **어휘 중복 검사까지** 다시 돌려야 하는데,
  얻는 것은 "밀도가 균일해 보인다"뿐이다. 학습 효과는 하한 1개로 이미 성립한다.
- **신규·개정 콘텐츠는 2개를 권장한다**(하한은 그대로 1개). 앞으로 만드는 것만 촘촘해지면 시간이 문제를 해결한다.
- 즉 이 표의 "1~2개"는 **코스마다 균일할 것을 요구하지 않는다.** 감사에서 편차가 다시 관찰되더라도 결함이 아니다.

같은 이유로 **회화 대사 수의 코스 간 편차도 결함이 아니다**(판정 L3) — 상위 코스가 더 긴 것은 방향이 옳고,
위 §5 표의 하한만 지키면 된다. 편차 자체를 없애기 위한 소급 작업은 하지 않는다.

### 급수 이탈은 결함이 아니다

편입된 글자가 상위 급수라도 그 코스의 어휘 테마와 맥락이 맞으면 허용한다
(N2의 遵·賠·督 등은 비즈니스·법무 어휘 遵守·賠償·監督과 맞는다).
**"JLPT 급수별 한자 목록"은 애초에 공식 발표가 아니다.** 급수 이탈만으로 재작업할 근거가 없다.

### ⚠️ 새 코스 착수 전에 한자 목록을 먼저 확정한다

**콘텐츠를 다 만든 뒤에 중복이 드러나면 교체 비용이 크고, 교체가 급수 일관성을 무너뜨린다.**
실제로 N2 작업에서 N3와 109자가 충돌해 대량 교체가 발생했다.

따라서 **N1 코스는 기존 1,000자(N5 100 + N4 200 + N3 350 + N2 350)를 전부 제외한 목록을 먼저 확보하고 시작한다.**
UNIQUE 제약이 위반을 기동 시점에 잡아주긴 하지만, 그때는 이미 콘텐츠를 다 만든 뒤다.

|---|---|
| 유닛당 | **15~20개**. 유닛의 회화·문법과 같은 테마로 묶는다 |
| **코스 내부 중복 금지** | 한 코스 안에서 같은 단어를 두 번 배우는 것은 학습 설계 결함이다. 테스트가 강제한다 |
| **코스 간 중복 허용** | 상위 코스에서 다른 의미·용법으로 재등장하는 것은 정당하다. 자세한 근거는 `08_결정기록.md` |
| `part_of_speech` | **INSERT 문에 직접 기입한다.** 별도 UPDATE 스크립트를 만들지 않는다 — 단어와 품사가 한 줄에 보여야 검수·유지보수가 쉽다 |

### 표기 표준화 규칙

같은 단어가 **가나 표기와 한자 표기로 이중 등재되면 표준 표기(한자)로 통일하고 `kana`를 채운다.**
화면이 단어 + 읽기를 3줄/3열로 보여주므로 학습자가 읽기를 그대로 보게 되어 교육적 손실이 없다.

통일 예: `あいさつ→挨拶`, `うわさ→噂`, `かぎ→鍵`, `さいふ→財布`, `じしょ→辞書`, `ひま→暇`, `やさしい→優しい`.
표기 오류도 표준형으로: `引っこし → 引っ越し`.

**단, 뜻이 다른 동음이의는 통일하지 않는다** — `つく`(불이 켜지다) / `着く`(도착하다),
`ぼうし`(모자) / `防止`(방지), `やめる`(그만두다) / `辞める`(직장을 그만두다).

통일로 뜻이 좁아지면 별개 단어로 나눈다: `やさしい` → `優しい`(상냥하다)로 통일하고, "쉽다"가 필요하면 `易しい`로 따로 등재.

## 8. 품사 분류 — 7종 (`PartOfSpeech`)

> **일본어 7종이다.** 영어 과정은 `ADJECTIVE`·`PREPOSITION`·`PHRASE`를 포함한 **다른 7종**을 쓰고 서로 섞이면 400이다 → **§11-6**.

**모든 어휘에 값이 하나씩 들어간다. 빈 값도, "기타"도 없다.**
필터에 "기타"가 쌓이면 사전으로서 쓸모가 준다.

| 코드 | 대상 | 예 |
|---|---|---|
| `NOUN` | 명사 (대명사·수사·조수사 포함) | 建物, トイレ, 一つ |
| `VERB` | 동사 (사전형/ます형 어느 쪽으로 등재하든) | 行く, 食べる, する |
| `I_ADJECTIVE` | い형용사 | 高い, いい |
| `NA_ADJECTIVE` | な형용사 | 静か, 便利 |
| `ADVERB` | 부사 | とても, もう, ゆっくり |
| `CONJUNCTION` | 접속사 | でも, それから, しかし |
| `EXPRESSION` | 인사·정형 표현·구(句) 등 위 6종에 안 들어가는 것 | こんにちは, お世話になっております |

**い형용사와 な형용사를 나눈 이유**는 활용 유형이 갈리기 때문이다 — 학습상 결정적 차이다.
**세분화(자동사·타동사, 1그룹·2그룹)는 하지 않는다** — 필터 가치는 낮고 입력 비용만 몇 배가 된다.

### 8-1. 대원칙

> **표제어의 형태를 따른다.** 데이터에 적힌 그대로가 무슨 품사인지 보고 판단하며,
> **문맥상 가능한 다른 용법은 고려하지 않는다.**

애매하면 `EXPRESSION`으로 몰지 말고 **어간의 품사를 우선**한다 (`お祝い` = `NOUN`).
`EXPRESSION`은 **문장 단위로 통째 등재된 정형구**에만 쓴다.

### 8-2. 겸용 품사 판정 규칙 (담당별 편차 방지)

| 겸용 | 판정 | 근거 |
|---|---|---|
| 명사 + な형용사 (`安全` `健康` `自由`) | **`NOUN`** | `〜な+명사`가 자연스러워도 조사 `が/を`를 붙여 명사로 쓰이면 명사가 기본형이다. **명사 용법이 거의 없는 것(`静か` `きれい`)만 `NA_ADJECTIVE`** |
| 명사 + 부사 (`今日` `全部` `最近`) | **`NOUN`** | 시간·수량 명사는 부사적으로도 쓰이지만 사전 표제어로는 명사다 |
| 동사구·관용구 (`席を外す` `気をつける`) | **`VERB`** | **판정 기준은 활용 여부.** 술어로 활용하면(`外します`·`外しました`) VERB. 활용하지 않고 통째로 외우는 정형구만 EXPRESSION |
| する동사 (`勉強` `研究`) | 표제어 형태를 따른다 | 명사형으로 등재 → `NOUN` / `〜する`까지 포함해 등재 → `VERB` |

### 8-3. 데이터 정합성

- **같은 `word + kana`에는 같은 품사가 붙어야 한다.** 자료실이 병합 행의 **대표값 하나**를 쓰기 때문이다.
  갈리는 데이터가 발견되면 그것은 콘텐츠 오류이므로 **시드를 고친다.**
- **한국어 라벨은 서버가 내려주지 않는다.** `frontend/src/constants/partOfSpeech.js`가 유일한 출처다.
  서버·프론트 양쪽에 라벨이 있으면 언젠가 어긋난다.
- `CONJUNCTION`은 현재 시드에 0건이다. **분류 오류가 아니라 데이터 부재이고, enum은 유지한다** —
  제거하면 어휘를 추가할 때 계약·시드·프론트를 다시 고쳐야 한다.

## 11. 영어 과정 콘텐츠 규칙 (`language = 'EN'`)

> **§1~§10은 전부 일본어 과정(`language='JA'`) 규칙이다.** 영어 콘텐츠를 만들 때 위 규칙을 그대로 가져오면 안 된다.
> 이 절이 **영어 콘텐츠의 유일한 기준**이고, 일본어 규칙 중 무엇을 가져오고 무엇을 버리는지를 여기서 전부 정한다.
>
> 근거 문서: 기획 `진행사항/2026-08-10_영어과정_뼈대기획.md` · 계약 `진행사항/2026-08-20_입문N1영어_계약.md` §3·§B·§7 ·
> 결정 `08_결정기록.md` F-17(코스명)·F-18(발음 표기) · 2026-08-25 감사 판정 H2(퀴즈·음성 제거).
> 실측 기준: 시드 `data-course-en-content.sql` / `data-course-en-units.sql`, 라이브 `/api/en/**` (2026-08-31).

### 11-1. 한 장 요약 — 일본어와 갈리는 지점 6개

| # | 일본어 | 영어 | 이 문서 위치 |
|---|---|---|---|
| 1 | 유닛 3번째 스텝 = **한자** | **표현(expression)** — 한자 테이블에 영어 대역 행이 **0개** | §11-4 · §11-5 |
| 2 | 읽기 = `kana` (한자가 있을 때만 값) | **`kana`는 전량 NULL.** 발음은 `ipa` + `koApprox` **둘 다** | §11-3 |
| 3 | 레벨 `INTRO`·`N5`~`N1`, 화면은 `levelLabel` | **`E1`~`E5`**, 화면은 **코스명**. `levelLabel`을 쓰지 않는다 | §11-2 |
| 4 | 품사 7종(い·な형용사 포함) | **영어 7종**(ADJECTIVE·PREPOSITION·PHRASE) | §11-6 |
| 5 | 유닛 마지막에 **확인 문제**, 문장에 **음성 버튼** | **둘 다 없다** (2026-08-25 판정) | §11-9 |
| 6 | 코스 0(문자)부터 6코스 | **코스 1~5, 5개.** 문자 코스가 없다 | §11-2 |

**그대로 가져오는 것**: 플레이리스트 모델(콘텐츠는 데이터), 유닛 = 문법 2~3 + 회화 1 + (3번째) + 어휘 + 정리,
자료실은 부록(콘텐츠를 두 번 만들지 않는다), 코스 내부 중복 금지, "값이 없으면 필드가 `null`"이라는 구조.

### 11-2. 코스와 레벨 코드 — `E1`~`E5`

| 코스 id | courseNo | `level_code` | 코스명 (08 F-17 확정) | 톤 | 상태(2026-08-31) |
|---:|---:|---|---|---|---|
| 101 | 1 | `E1` | 다시 세우기 | **다시 배우기식** — "학교에서 이렇게 배웠죠? 실제로는 이렇게 씁니다" | AVAILABLE (맛보기 2유닛) |
| 102 | 2 | `E2` | 일상 말하기 | 다시 배우기식 | PREPARING |
| 103 | 3 | `E3` | 이어 말하기 | **체계식** — 규칙이 먼저 서고 예문이 뒷받침 | PREPARING |
| 104 | 4 | `E4` | 뉘앙스 | 체계식 | PREPARING |
| 105 | 5 | `E5` | 실전과 격식 | **실전식** — 상황(회의·이메일·발표)과 격식 기준을 함께 제시 | PREPARING |

- **코스 0(문자)이 없다.** 영어 학습자는 이미 로마자를 읽는다. 알파벳·파닉스 코스를 만들지 않는다.
- **`levelLabel`을 콘텐츠·화면 어디에도 쓰지 않는다.** 코스명이 곧 단계 이름이다("다시 세우기").
  시드의 `level_label`은 코드와 같은 값(`E1`)으로 채워 두지만 **표시에 쓰지 않는 값**이다.
  일본어의 `levelLabel`("JLPT N5")을 영어에서 흉내내면 3단계 qa 치명 결함(라벨을 필터에 넘겨 0건)이 재발한다.
- **CEFR(A1~C2)은 내부 난이도 참고선일 뿐 학습자에게 노출하지 않는다.** 코스 설명·목표 문구에 CEFR 코드를 적지 않는다.
- 레벨 값은 **섞이면 오류**다 — 영어 자료실에 `N5`, 일본어 자료실에 `E1`을 주면 400이다(계약 §3-2).
  콘텐츠 작업자가 알아야 할 것: **영어 콘텐츠의 레벨은 그 유닛이 속한 코스의 `level_code`에서 파생되고, 콘텐츠 행에 레벨을 직접 적지 않는다.**

### 11-3. ⚠️ kana 계약(§1)은 영어에 적용되지 않는다 — 발음은 IPA + 한글 근사 **둘 다**

> **영어 콘텐츠의 `kana`는 예외 없이 `NULL`이다.** §1의 "원문에 한자가 있으면 kana를 채운다"는 규칙은
> **일본어 전용**이며, 영어에는 한자도 가나도 존재하지 않으므로 적용할 대상 자체가 없다.

`kana`를 하나라도 채우면 kana 계약 검증기(`KanaContract`)가 **영어 데이터를 거부**한다 — 규칙을 어긴 게 아니라 문법 오류에 가깝다.

영어의 발음 표기는 **별도 컬럼 2개**이고, **둘 다 채운다**(사용자 확정 — 08 F-18).

| 컬럼 / 필드 | 무엇 | 예 | 필수 |
|---|---|---|---|
| `ipa` / `ipa` | IPA(국제음성기호), **슬래시로 감싼다** | `/ˈmɔːrnɪŋ/` `/kʌm ʌp wɪð/` | **필수** |
| `ko_approx` / `koApprox` | 한글 근사 표기 | `모-닝` `컴 업 위드` | **필수** |

- **적용 대상**: 어휘(`vocabulary`)와 표현(`expression`) 둘 다. 실측 전량(어휘 30 · 표현 12)이 두 값을 갖고 있다.
- **하나만 채우지 않는다.** IPA만 있으면 못 읽는 학습자가 있고, 한글만 있으면 잘못된 발음이 굳는다.
  둘 다 있어야 한다는 것이 확정 사항이므로 **한쪽만 채운 데이터는 미완성**으로 본다.
- **한글 근사 표기 요령**: 장모음은 `-`로 표시하고(`모-닝` `워-크` `프리-`), 단어 경계는 띄어 쓴다(`컴 업 위드`).
  실제 발음이 뭉개지는 것은 `usage_note`에 적는다(예: `kind of` → "말할 때는 카인더에 가깝게 뭉개집니다").
- **자료실에도 같은 값이 나간다.** 유닛에만 발음을 넣고 자료실에서 빼면 같은 단어가 화면마다 달라진다(계약 §7-3).
- 일본어 어휘 응답에도 `ipa`·`koApprox` 필드는 **존재하고 항상 `null`** 이다 — 필드 유무가 언어별로 갈리지 않게 한 것이므로
  일본어 콘텐츠에 이 두 값을 채우지 않는다.
- **원문 필드 이름 주의**: `grammar_example.jp` · `dialog_line.jp`는 이름이 `jp`지만 **"원문(source text)" 자리**다.
  영어 과정에서는 여기에 **영어 문장**이 들어간다. 이름과 내용의 불일치는 기록된 빚이며(계약 §7-2), 콘텐츠 작업자는 그대로 쓴다.

### 11-4. 유닛 표준 구성과 수량 규칙

```
문법(항목당 1스텝, 2~3) → 회화 1편 → 표현 → 어휘 → 정리
```

**스텝 순서와 개수는 일본어와 같고, 3번째 자리만 한자 → 표현으로 바뀐다.** (유닛 학습 화면의 스텝 진행·칩 바를 그대로 재사용한다.)

| 요소 | 계약 수량 | 맛보기 2유닛 실측 (2026-08-31) | 비고 |
|---|---|---|---|
| 문법 | **유닛당 2~3개** | 유닛당 2 (계 4) | 일본어와 동일 |
| 문법 예문 | 문법당 **1개 이상**(권장 2~4) | 문법당 3 (계 12) | 일본어와 동일 |
| 회화 | **유닛당 정확히 1편** | 유닛당 1 (계 2) | 화자 2명 이상 — §11-7 |
| **표현** | **유닛당 6~10개** | 유닛당 6 (계 12) | 한자 자리 — §11-5 |
| 표현 예문 | 표현당 **1개 이상** | 표현당 1 (계 12) | |
| 어휘 | **유닛당 15~20개** | 유닛당 15 (계 30) | 일본어와 동일 |
| 한자 | **없다 (0행)** | 0 | `kanji`·`kanji_word`·`unit_kanji`에 영어 대역 행이 없다 |
| 활용 규칙표(`grammar_rule`) | 이번 범위에서 **쓰지 않는다** | 0 | §11-8 |
| 확인 문제·음성 | **없다** | 0 | §11-9 |

- **누적 총량 목표를 두지 않는다.** 일본어 한자의 "N5 100 → 누적 1,350"에 해당하는 목표가 영어에는 없다.
  한자는 닫힌 집합(상용한자 2,136자)이지만 **영어 표현은 열린 집합**이고 총량이 실력의 지표가 아니다.
- **코스별 유닛 수는 아직 정해지지 않았다** — 콘텐츠 착수 시 확정한다(§11-12).
- **입문 코스의 "한자 0자"와 영어의 "한자 없음"은 다른 종류다.** 입문은 응답에 `kanjis: []`(빈 배열)가 있고,
  영어 유닛 응답에는 `kanjis` **필드 자체가 없고** 그 자리에 `expressions[]`가 있다. 콘텐츠 쪽에서 입문 규칙을 참고하지 말 것.
- 복습 블록 규칙(`unitNo % 5 == 0`)은 영어에도 그대로 적용되지만, 맛보기가 2유닛이라 **아직 한 번도 발동한 적이 없다.**
  코스 1을 5유닛 이상으로 채우는 순간부터 5·10·15 유닛의 정리 스텝에 복습 블록이 붙는다 — **직전 5유닛 분량이 실제로 존재해야 한다.**

### 11-5. 표현 (`expression`) — 한자 자리에 들어가는 것

> **표현 = 단어보다 크고 문장보다 작은, 통째로 외워 쓰는 덩어리.**
> **구동사·연어·관용표현을 한 종류로 다룬다** — 쪼개지 않는다.

셋으로 나누지 않는 이유: 학습자에게 `get up`(구동사)과 `take a shower`(연어)는 완전히 같은 요구다(통째로 외워 바로 쓴다).
쪼개면 데이터 3종 → 스텝 3개 → 자료실 탭 3개가 되어 **부록이 화면을 지배**한다. (일본어 품사에서 `EXPRESSION` 하나로 합친 08 A-6과 같은 논리.)

| 필드 | 내용 | 필수 |
|---|---|---|
| `text` | 표현 표기. 소문자로 쓰고 대명사·관사를 넣지 않는다 (`get up` `be good at` `come up with`) | 필수 |
| `meaning_ko` | 한국어 뜻. 괄호로 상황을 좁힌다 — `(잠자리에서) 일어나다` | 필수 |
| `usage_note` | **혼동 짝을 잡아 주는 한두 문장.** `wake up`과의 차이, `good to`와의 차이처럼 **왜 틀리는지**를 적는다 | 사실상 필수 — 실측 12/12 |
| `ipa` · `ko_approx` | §11-3 | 필수 |
| 예문 | `expression_example` — `en` + `meaning_ko`. 표현당 1개 이상 | 필수 |

- **중복 규칙이 한자와 정반대다.**

| | 일본어 한자 | 영어 표현 |
|---|---|---|
| 코스 간 중복 | **금지** (`kanji.letter` UNIQUE) | **허용** — 상위 코스에서 다른 뉘앙스·격식으로 재등장하는 것은 정당한 복습 |
| 코스 내부 중복 | 금지 | **금지** |
| 착수 전 목록 확정 | **필요** (§6 — N2에서 109자 충돌) | **불필요** — 중복 금지 제약이 없어서 사전 확정할 이유가 없다 |

- `expression.text`에 **UNIQUE를 걸지 않는다.** 걸면 코스 간 재등장이 막힌다.
- **분류 태그(구동사/연어/관용)를 두지 않는다.** 필요해지면 종류를 나누는 게 아니라 값을 붙이는 방식으로 확장한다(§11-12).
- **표현은 그 유닛의 회화·문법과 같은 테마로 묶는다.** 문법과 무관한 표현을 채워 넣지 않는다.

### 11-6. 어휘와 품사 — 영어 7종 (일본어 7종과 다르다)

**모든 어휘에 값이 하나씩 들어간다. 빈 값도 "기타"도 없다** — 이 원칙만 §8과 같고, **값의 집합이 다르다.**

| 코드 | 대상 | 예 | 일본어에 있나 |
|---|---|---|---|
| `NOUN` | 명사 | morning, meeting, weekend | 있음 |
| `VERB` | 동사 | work, live, enjoy | 있음 |
| **`ADJECTIVE`** | 형용사 — **하나로 둔다** | busy, nervous, tired | **없음** |
| `ADVERB` | 부사 | usually, early, often, instead | 있음 |
| **`PREPOSITION`** | 전치사 | near, between, during | **없음** |
| `CONJUNCTION` | 접속사 | because, but | 있음 |
| **`PHRASE`** | 위 6종에 안 들어가는 정형구 | (현재 0건 — 아래 참조) | **없음**(일본어는 `EXPRESSION`) |

- **`I_ADJECTIVE`·`NA_ADJECTIVE`를 쓰지 않는다.** い·な 구분은 **활용 유형이 갈리는 일본어 전용 사정**이고 영어 형용사에는 그런 분기가 없다.
  같은 이유로 영어에 `EXPRESSION`(일본어 코드)을 쓰지 않는다 — 영어의 대응 코드는 `PHRASE`다.
- **섞으면 서버가 400으로 거부한다.** 영어 경로에 `I_ADJECTIVE`, 일본어 경로에 `PREPOSITION`을 주면 오류다
  (`PartOfSpeech.allowedFor(language)`가 단일 출처, `EnglishPartOfSpeechContractIntegrationTest`가 고정).
- **`PHRASE`는 현재 시드에 0건이다.** `CONJUNCTION`이 일본어에서 0건인 것과 같은 성격 —
  **분류 오류가 아니라 데이터 부재이고, 코드는 유지한다.** 다만 통째로 외우는 덩어리는 대개 **어휘가 아니라 표현(§11-5)** 으로 들어가므로,
  `PHRASE`를 쓰기 전에 "이건 표현 스텝에 가야 하는 것 아닌가"를 먼저 확인한다.
- **판정 대원칙은 일본어와 같다**: 표제어의 형태를 따르고, 애매하면 `PHRASE`로 몰지 않는다.
  한 표기가 품사를 겸하면(`work` 명사/동사, `free` 형용사/부사) **그 유닛에서 가르치는 용법**의 품사를 쓰고, 뜻이 갈리면 `meaning_ko`에 병기한다(`한가한 · 무료의`).
- **코스 내부 중복 금지 · 코스 간 중복 허용**은 일본어와 같다(§7).
- **한국어 품사 라벨은 서버가 내려주지 않는다** — `frontend/src/constants/partOfSpeech.js`가 유일한 출처다(§8-3과 동일).

### 11-7. 회화 (`dialog`)

| 규칙 | 내용 |
|---|---|
| 유닛당 | **정확히 1편** (일본어와 동일) |
| 화자 | **2명 이상** — 1인 낭독 장면은 만들지 않는다 |
| 대사 줄 수 | **하한이 아직 계약으로 정해지지 않았다.** 맛보기 실측은 유닛당 **4줄** — 새 콘텐츠는 4줄을 기준으로 삼는다(§11-12) |
| 문법 사용 | **그 유닛의 문법이 실제로 쓰인 장면이어야 한다** (유닛 1 = be동사·일반동사, 유닛 2 = do/does 의문·부정) |
| `title` | 한국어 장면 제목 — "첫 출근 날, 옆자리에서" |
| `kana` | **전량 NULL** (§11-3) |

- 대사는 **영어**로 쓰고 `meaning_ko`에 한국어 뜻을 붙인다. 일본어 회화와 필드 구조가 같다.
- §5의 두 판정(이후 유닛 문법이 먼저 나와도 결함 아님 / 실라버스 회화 주제는 대본 사양이 아님)은 **영어에도 그대로 적용된다.**

### 11-8. 문법

- 유닛당 2~3개, **문법 하나당 예문 1개 이상**(실측 3개). 필드는 일본어와 같다(`name` · `name_ko` · `explanation`).
- **`name`은 영어 문법 명칭을 한국어와 섞어 쓴다** — `be동사 현재형 (am / is / are)`, `do / does 의문문`.
  `name_ko`는 **학습자가 읽는 부제**다 — `~이다 · ~에 있다`, `평소에 ~해요? 라고 묻기`. 둘 다 필수다.
- `explanation`은 최대 500자. **톤은 코스별로 다르다**(§11-2 표).
  코스 1~2의 "다시 배우기식"은 **학교에서 배운 방식을 먼저 호명하고 실제 쓰임으로 교정**하는 서술이다
  ("학교에서 표로 외웠는데도 말할 때 틀리는 이유는 …", "I am go 같은 문장은 없습니다").
- **활용 규칙표(`grammar_rule`)는 이번 범위에서 쓰지 않는다.** §4의 규칙표 지정 목록은 **일본어 전용**이다.
  영어에 규칙표가 필요해 보이면(불규칙 동사 변화표 등) **먼저 senior-dev에게 계약 확장을 요청한다** — 임의로 붙이지 않는다.

### 11-9. ⚠️ 영어 유닛에는 확인 문제(퀴즈)도 음성도 없다 (2026-08-25 판정 H2)

> **영어 유닛의 스텝은 문법 → 회화 → 표현 → 어휘 → 정리에서 끝난다. 확인 문제 스텝이 없다.**
> 영어 화면에는 `.quiz-*` · `.tts-*` 요소가 **하나도 없어야 한다.** 자료실에도 [문제 풀기]가 없다.

**콘텐츠 작업자에게 이 말의 뜻**:

- **퀴즈에 나올 것을 전제로 콘텐츠를 만들지 않는다.** "여기서 4지선다가 나가니까 오답 후보를 만들어 두자"는 작업은 하지 않는다.
- **음성으로 읽어 준다는 전제도 없다.** 발음은 **오직 `ipa` + `koApprox` 두 표기**로만 전달된다(§11-3) — 그래서 두 값이 필수인 것이다.
- 배운 것을 확인시키고 싶으면 **회화·예문·`usage_note`** 안에서 해결한다.

**왜 이렇게 됐나**: 일본어 퀴즈는 유닛 콘텐츠에서 문제를 자동 생성하는데, 그 생성기가 영어 유닛에도 켜져 있어
**영어 문장이 일본어 폰트로 조판되고 ja 음성 엔진이 영어를 읽는** 상태였다(감사 H2·H4). 기획서·화면정의서·계약은 처음부터 "범위 밖"이라고 적혀 있었고,
**문서가 이겨서 코드를 되돌렸다.** 일본어에 퀴즈·음성이 있다는 이유로 영어에 다시 켜지 않는다.

> 나중에 영어에 붙인다면 **일본어와 같은 틀로 함께** 붙인다 — 영어에서 먼저 만들지 않는다. 그때 이 절을 갱신한다.

### 11-12. 영어에서 아직 정하지 않은 것

- **코스별 유닛 수** — 일본어는 20/20/25/25. 영어도 같은 근거(제작·검수 부담 통제)가 적용되지만 값은 콘텐츠 착수 시 확정한다.
- **회화 대사 줄 수 하한** — 계약에 없다. 실측 4줄. 일본어처럼 상위 코스에서 늘릴지(N3~ 4줄 이상) 함께 정한다.
- **표현 분류 태그**(구동사/연어/관용) — 지금은 두지 않는다. 자료실에서 "구동사만 보기" 수요가 실제로 확인되면 추가하되,
  **이미 입력된 표현 전량에 태그를 소급 입력하는 비용**을 함께 계산한다.
- **어원·접사(root/prefix/suffix)** — 성질은 한자와 가장 비슷하지만 **상급에서만 효과가 있다.**
  코스 4~5의 어휘 스텝 안 보조 정보로 둘지는 상급 코스 착수 시 재검토한다. 별도 스텝으로 만들지 않는다.
- **영어 실력 진단** — 현재 `/en/start`는 **채점 없는 can-do 자기 선택 5문장**이고 콘텐츠를 재료로 쓰지 않는다.
  콘텐츠가 쌓인 뒤 문제 기반 진단을 붙일지는 그때 판단하며, 붙이더라도 자가진단을 **대체하지 않고 보완**한다.
