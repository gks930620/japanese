# 01. 제품 개요

> **이 문서는 무엇인가**
> 이 사이트가 무엇을 누구를 위해 만드는지, 그리고 콘텐츠를 어떤 구조로 쌓기로 했는지의 대전제다.
> 새 기능을 기획하거나 콘텐츠를 추가하기 전에 여기부터 읽는다 — 여기 적힌 원칙과 어긋나는 제안은 다시 생각해야 한다.

기준일: 2026-08-10 (§3 스텝 순서 · §7-8 "이어서" 정의 · §8 배지 문구는 2026-09-03 개정 / §10 영어 과정 신설 2026-09-08)

> ⚠️ **§1~§8은 일본어 과정 기준이다.** 같은 사이트에 **영어 과정**(`/en/**`)이 함께 있고, 제품 규칙이 상당 부분 다르다 → **§10**.

## 1. 무엇을 만드나

**입문(문자)부터 JLPT N1까지 단계별 코스로 배우는 일본어 학습 사이트.**

핵심 가치는 콘텐츠의 양이 아니라 **순서**다.

> **"공부를 어떤 순서로 해야 할지 모르겠다"를 사이트가 대신 해결해 준다.**
> 학습자가 스스로 커리큘럼을 짜지 않아도 되게 만드는 것 — 그것이 이 제품이 파는 것이다.

그래서 학습자가 해야 할 일은 딱 하나다: **"다음 유닛"을 누르는 것.**

- 사용자: 일본어 독학자 — 히라가나부터 시작하는 완전 초보부터 JLPT N2 수험생까지.
- 플랫폼: **웹 먼저.** 앱(Flutter)은 아직 도입하지 않았다.

**사이트의 주인공은 "학습"이다.** GNB의 첫 메뉴가 학습이고, 자료실은 어디까지나 부록이다.
이 우선순위는 메뉴 배치·화면 예산·링크 방향 모두에 걸쳐 일관되게 적용된다.

## 2. 코스 6개 = 하나의 길

코스는 병렬 선택지가 아니라 **순서가 있는 한 줄**이다. `courseNo` 오름차순이 곧 학습 경로다.

| courseNo | 코스명 | 레벨 | 유닛 | 톤 | 현재 상태 |
|---|---|---|---:|---|---|
| 0 | 입문 | 문자 | 10 | **따라하기식** — 문자부터, 한자 0자 | 공개 |
| 1 | 왕초보 | JLPT N5 | 20 | **따라하기식** — 예문 먼저, 설명 최소 | 공개 |
| 2 | 초급 | JLPT N4 | 20 | **체계식** — 설명이 먼저 서고 예문이 뒷받침 | 공개 |
| 3 | 중급 | JLPT N3 | 25 | **체계식** (회화가 길어짐) | 공개 |
| 4 | 중상급 | JLPT N2 | 25 | **시험대비식** — "접속 / 의미 / 주의(시험 포인트)" 틀 | 공개 |
| 5 | 고급 | JLPT N1 | 25 | **시험대비식** — 문어체·경어 대응표 | 공개 |

현재 공개 유닛 **125개**, 회화 125편 — **6개 코스 전부 공개**(2026-08-20 입문·N1 개통).

**톤 전환은 의도된 설계다.** 왕초보에게 문법 용어로 설명하면 이탈하고, N2 수험생에게 "따라해 보세요"라고 하면 시험에 못 쓴다.
같은 형식으로 6개 코스를 찍어내지 않는다.

### 왜 N2가 25유닛인가 (앞으로 N1·입문 설계 때 참고)

30유닛으로 늘리지 않은 이유는 **코스당 제작·검수 부담 통제**다.
유닛당 문법 밀도(2~3개, 묶음 문형 포함)와 한자 350자로 이미 앞 코스보다 무겁고,
30개로 늘리면 제작·감수·QA 대상이 20% 이상 늘어난다.
부족한 문형은 유닛 수가 아니라 **유닛당 밀도(유사 문형 묶음)로 흡수**한다.

## 3. 유닛 = 학습의 최소 단위

**매 유닛의 구성은 고정이다.** 순서도 고정이다.

```
문법 (항목당 1스텝, 2~3스텝) → 회화 1편 → 한자 → 어휘 → 확인 문제 → 정리
```

| 요소 | 유닛당 수량 |
|---|---|
| 문법 | **2~3개** |
| 회화 | **정확히 1편** |
| 한자 | 코스 안에서 균등 배분 — N5 5자 / N4 10자 / N3·N2 각 14자 (입문은 0자 → 스텝 없음) |
| 어휘 | **15~20개** (유닛의 회화·문법과 같은 테마) |
| 확인 문제 | 그 유닛 재료로 만든 최대 10문항(`09 §2`). **건너뛸 수 있다** — 풀이는 완료 조건이 아니다. 영어 과정에는 없다(`09 §5`) |
| 정리 | 배운 문법 칩·한자·어휘 수 요약 + 다음 유닛 버튼. **언제나 마지막 스텝**이고 [다음 유닛]은 여기에만 있다 — 그 앞 스텝은 전부 [다음 ›]로 바로 다음 스텝에 간다(2026-09-03 결정 D-3) |

절대 규칙:

- **회화는 반드시 그 유닛의 문법이 실제로 쓰인 장면이어야 한다.** 유닛과 무관한 회화를 붙이지 않는다.
  (단, 이후 유닛에서 배울 문법이 회화에 먼저 등장하는 것은 결함이 아니다 — 자연스러운 일본어가 우선이다.)
- **한자는 누적 체계 — 코스 간 중복 금지.** N5 100 → N4 +200(누적 300) → N3 +350(누적 650) → N2 +350(누적 1,000).
- **잠금이 없다.** 진도 개념이 없으므로 순서를 강제하지 않고, **목록의 시각적 순서로 권장 경로를 보여준다.**
- **모든 유닛은 주소로 직접 접근·공유 가능해야 한다.**
- 유닛 5·10·15·20…은 자연스러운 쉼표 지점이다. 정리 스텝에 직전 5유닛 복습 블록이 붙는다.

수량·표기의 상세 제작 규칙은 `06_콘텐츠_제작규칙.md`에 있다.

## 4. 대전제 — 콘텐츠는 페이지가 아니라 데이터다 (플레이리스트 모델)

이것이 이 제품의 구조를 결정하는 단 하나의 원칙이다.

- **문법·한자·어휘·회화는 각각 독립된 데이터**로 존재한다.
- **코스와 유닛은 그 데이터를 참조하는 얇은 매핑 층**이다 — 음악 파일과 플레이리스트의 관계와 같다.
- **자료실은 같은 데이터를 사전 뷰로 다시 보여줄 뿐**이다.

따라서:

> **자료실을 위해 만드는 새 학습 콘텐츠는 0건이다. 콘텐츠를 두 번 만들지 않는다.**

이 원칙이 실제로 판단을 가르는 지점:

| 요구 | 판단 |
|---|---|
| "자료실에 한자 획수·부수 필터를 넣자" | ❌ 데이터가 없다 → 1,350자 신규 입력 = 대전제 위반. 필요하면 별도 이터레이션으로 |
| "문법을 의미 분류로 묶어 보여주자" | ❌ 같은 이유 |
| "어휘에 품사 필터를 넣자" | ✅ 단 1,415건 입력 비용을 명시적으로 감수하고 진행한 **유일한 예외** |
| "문법 상세 화면을 자료실용으로 새로 쓰자" | ❌ 유닛 학습의 문법 스텝과 **같은 컴포넌트·같은 데이터**여야 한다 |

**자료실의 모든 항목은 "어느 코스 어느 유닛에서 배우는지"를 함께 보여준다.**
사전을 보다가 코스로 돌아갈 수 있어야 한다 — 메인은 어디까지나 코스다.

## 5. 자료실 (부록)

3종: **한자 · 문법 · 어휘.** 회화(표현) 자료실은 없다.

| | 한자 | 문법 | 어휘 |
|---|---|---|---|
| 경로 | `/library/kanji` | `/library/grammar` | `/library/vocabulary` |
| 페이지당 | 60자 | 20개 | 50개 |
| 필터 | 레벨(복수) | 레벨 + "활용표 있는 것만" | 레벨 + 품사(복수) |
| 정렬 | 학습 순서 **고정** | 학습 순서 **고정** | 학습 순서 / 가나순 |
| 상세 화면 | 있음 | 있음 | **없음** (행 확장) |

설계 근거 — 앞으로도 유효한 것:

- **GNB에는 "자료실" 단일 항목 1개, 자료실 안에서 3탭.** 한자·문법·어휘를 각각 GNB에 넣으면 메뉴가 6개가 되어
  **부록인 자료실이 GNB의 절반을 차지**한다. "학습이 주인공" 원칙과 어긋난다.
- **자료실 허브 화면을 만들지 않는다.** 카드 3장 허브는 클릭만 한 번 늘린다. "자료실" 클릭 = 바로 한자 자료실.
- **기본 탭이 한자인 이유**: 글자를 마주쳤을 때 "이게 뭐지"를 찾는 수요가 가장 잦고,
  3종 중 유일하게 **코스 밖(간판·메뉴판)에서도 검색 대상**이 된다.
- **한자·문법의 정렬을 고정하는 이유**: 한자는 획수·가나순 어느 쪽도 데이터로 불가능하거나 무의미하고,
  문법은 **명칭 대부분이 `〜`로 시작해 사전순이 의미가 없다.**
- **회화 자료실을 뺀 이유**: 회화 90편은 "장면을 통째로 읽는 것"이라 목록·필터로 훑는 사전 뷰와 성격이 다르다.
  3종이 자리 잡은 뒤 별도 기획한다.

검색 편의 규칙(콘텐츠·검색 구현에 계속 유효):
`〜てから`를 **물결표 없이 `てから`로 쳐도** 찾혀야 하고, `가능형`·`추측` 같은 한국어 부제로도 찾혀야 하며,
`たてもの`로 쳐도 `建物`이 나와야 한다(한자를 못 쓰는 학습자 배려).

## 6. 비로그인 열람 정책 (확정)

**학습에 관한 모든 것은 회원가입 없이 볼 수 있다. 진도와 보관함도 예외가 아니다.**

| 공개 | 로그인 필요 |
|---|---|
| 홈, 코스 목록, 코스 상세, **유닛 학습 전 스텝** | 마이페이지 |
| 자료실 3종 전부 (목록·상세·검색·필터·정렬·페이지) | 커뮤니티 글쓰기·수정·삭제, 댓글 작성 |
| 커뮤니티 목록·상세 열람 | (커뮤니티 글쓰기·마이페이지 등) |
| **진도 기록·표시·이어보기** (이 브라우저 한정) | **다른 기기에서 이어보기** |
| **보관함에 담기·보기** (이 브라우저 한정, 종류별 200개) | |

- GNB "학습"·"자료실"은 **어떤 상태에서도 로그인을 요구하지 않는다.**
- **로그인 여부로 기능이 갈리지 않는다. 갈리는 것은 기록이 어디까지 따라오느냐뿐이다** —
  비로그인 기록은 **그 브라우저(localStorage)에만** 남고, 브라우저 기록을 지우면 사라지며 다른 기기로 따라가지 않는다.
- **진도·보관함 UI는 로그인 여부와 무관하게 똑같이 보인다.** 진도 막대·완료 체크·★를 비로그인이라고 감추지 않는다 —
  감추면 "당신의 학습은 기록되지 않는다"는 사실이 화면에 아예 안 보여서, 사용자가 한참 뒤에야 알게 된다.
- **로그인 유도는 결과를 보여준 뒤에만, 한 번만.** 학습·열람을 막는 모달을 띄우지 않는다.
- 로그인하면 브라우저 기록을 계정에 합칠지 **묻는다**(자동 병합 금지 — 공용 PC 사고 방지).
- 유닛 학습 주소를 복사해 비로그인 창에서 열면 같은 화면이 그대로 나온다. 자료실도 필터·검색어·정렬·페이지가 주소에 담긴다.

> 이 절은 2026-08-14 진도·보관함 구현으로 개정됐다. 옛 문장 **"로그인해도 학습 화면은 비로그인과 완전히 동일하게 보인다 — 진도 UI가 아예 없기 때문이다"** 는 폐기됐다.
> 지금은 **양쪽 모두 진도 UI를 본다**(기록의 범위만 다르다).

## 7. 진도 — "다음 유닛만 누르면 된다"를 사이트가 기억한다

**진도는 두 가지를 따로 기억한다.** 하나로 합치면 "어디까지 끝냈나"와 "어디서 멈췄나"가 섞여 화면이 애매해진다.

| 개념 | 단위 | 무엇을 답하나 | 어디에 쓰이나 |
|---|---|---|---|
| **완료** | 유닛 | "이 유닛을 끝냈는가"(O/X) | 코스 카드의 진도 막대, 코스 상세의 유닛 체크, 완주 판정 |
| **마지막 위치** | 유닛 + 스텝 | "직전에 어디를 보고 있었는가" | 홈의 [이어서 학습하기], 유닛 재진입 시 스텝 복원 |

지켜야 하는 결과:

1. **완료는 정리(마지막) 스텝을 열면 켜진다.** 추가 클릭을 요구하지 않는다 — 그래야 "다음 유닛만 누르면 된다"가 안 깨진다.
   스텝바에서 정리 칩으로 건너뛰어도 완료다(잠금을 두지 않는 §3의 연장).
   정리 스텝에서 손으로 끄고 켤 수 있고, **코스 상세의 유닛 목록에서는 읽기 전용**이다(20~25행에서 오조작이 쉽다).
2. **완료를 스텝 단위로 세지 않는다.** 스텝 완료율(4/7)을 진도로 노출하면 "유닛을 채우는 게임"이 되는데,
   이 사이트가 파는 것은 **순서**이지 달성률이 아니다. (이어보기 안내의 `(4/7)`는 위치 표시일 뿐이다.)
3. **마지막 위치는 사이트 전체에 하나다.** 코스별로 여러 개 두지 않는다 — 하나의 길을 가는 제품이라 "지금 있는 곳"도 하나다.
4. **이미 완료한 유닛은 1번 스텝으로 연다.** 완료 후의 재방문은 복습이고, 복습은 처음부터가 자연스럽다
   (마지막 위치를 복원하면 "정리 스텝만 계속 뜨는" 화면이 된다).
5. **저장은 사용자가 의식하지 않는다.** 저장 버튼도, 스피너·토스트도 없다.
   자동 저장이 실패해도 학습을 막지 않는다. **손으로 누른 완료 토글만** 실패를 알린다.
6. **진도를 못 불러와도 화면은 진도 없는 상태로 정상 표시된다.** 진도 때문에 에러 카드를 띄우지 않는다.
7. **유닛 잠금은 여전히 없다**(§3). 진도는 권장 경로를 보여줄 뿐 순서를 강제하지 않는다.
8. **"이어서"는 마지막 위치(보던 곳)만 가리킨다. 아직 안 마친 가장 앞선 유닛은 "다음 유닛"이라 부른다.** 같은 말로 다른 곳에 보내지 않는다(2026-09-03 결정 D-2).
   - [이어서 학습하기]는 **홈·마이페이지**에만 있다. 보던 유닛이 미완료면 그 유닛(스텝 복원), **이미 마쳤으면 같은 코스에서 그 뒤 첫 미완료 유닛**으로 간다 — 마친 유닛 안으로 되돌려 보내지 않는다. 코스를 완주했으면 "이어서" 대신 다음 코스 안내다.
   - **코스 상세·코스 카드에는 "이어서"라는 말이 없다.** 코스 상세 주 버튼과 "여기부터" 배지는 미완료 최전선(다음 유닛)을 가리키고, 건너뛰어 보던 유닛이 따로 있으면 그 행에 "보던 중"을 회색으로 표시한다.
   - 순서대로 진행하는 사용자에게는 두 답이 항상 같다. 갈리는 것은 건너뛴 사람뿐이고, 그때 두 말은 각각 사실이다.

**자료실 링크의 새 탭 규칙**: 옛 §7은 "유닛 학습 → 자료실 링크는 반드시 새 탭"이었고 근거는 "돌아오면 첫 스텝으로 리셋되기 때문"이었다.
진도가 생겨 **근거가 사라졌으므로 같은 탭으로 바꾼다** — 단 "뒤로가기로 돌아오면 보던 스텝이 그대로"가
**인수 조건(AC-P-22·23)으로 검증된 뒤에만** 바꾼다. 그 전까지는 새 탭을 유지한다.

**보관함**(한자·문법·어휘 3종)은 진도와 짝이다 — 자료실·유닛 학습 어디서 담아도 같은 항목이고, `/bookmarks`에서 모아 본다.
유닛과 회화는 담지 않는다(유닛은 진도가 이미 답하고, 회화는 보여 줄 목록 화면이 없다).

## 8. 시작점 안내 — "여기서 시작하세요"는 계산된다

코스 카드 배지 규칙(확정) — 진도가 생기면서 판정이 한 겹 늘었다:

| 순위 | 대상 | 배지 |
|---|---|---|
| 1 | 마지막으로 학습한 AVAILABLE 코스를 아직 완주하지 않았다 | **"학습 중인 코스"** + 강조 (옛 문구 "이어서 학습하기"는 §7-8에 따라 폐기 — 카드는 코스 상세로 가므로 홈 버튼과 같은 말을 쓰지 않는다) |
| 2 | (1이 없고) 진도가 있는 코스가 하나도 없다 | **"여기서 시작하세요"** + 강조 |
| 3 | (1이 없고) 마지막 학습 코스를 완주했다 → 그 다음 AVAILABLE 미완주 코스 | **"다음 코스를 시작하세요"** + 강조 |
| — | 그 밖의 입장 가능 코스 | "바로 볼 수 있어요" + 톤다운 (진입은 동일하게 가능) |
| — | 유닛을 전부 완료한 코스 | **"완주"** + 톤다운 |
| — | 준비중 코스 | "준비중" + 비활성, 클릭해도 이동 없음 |

**강조 카드는 어떤 상태에서도 화면에 한 장뿐이다**(1·2·3은 서로 배타적이다).
마지막 위치가 사라진 코스·준비중 코스를 가리키면 그 값을 버리고 "진도가 있는 AVAILABLE 코스 중 courseNo 최솟값"으로 대신한다
— 그래야 진도가 있는데 강조 카드가 한 장도 없는 화면이 생기지 않는다.

**판정 기준은 "AVAILABLE 중 `courseNo` 최솟값"이다 — 특정 코스(N5)를 지목해 고정하지 않는다.**
입문(코스 0)이 열리면 시작 배지가 **자동으로** 입문 카드로 옮겨 가야 한다.
구현: `frontend/src/lib/courses.js`의 `entryCourseNo()`(2번 판정) + `frontend/src/lib/progressView.js`의 `courseBadges()`(전체 판정).
배지 **문구**는 `lib/badgeView.js`가 따로 갖는다 — 계산과 문구를 갈라 두면 문구가 바뀌어도 계산 테스트가 깨지지 않는다.

실력 진단(시작점 추천)은 **이미 동작한다** — `/diagnosis`, 규칙은 `09_학습도구_동작규칙.md` §3. 이 정적 안내는 진단을 건너뛰는 사람을 위해 함께 둔다.

## 10. 영어 과정 — 같은 사이트의 두 번째 길 (2026-09-08 신설)

> **이 절이 왜 있나**: §1~§8은 일본어만 설명한다. 그런데 제품에는 영어 과정이 이미 **화면과 데이터로 살아 있다**.
> 제품 개요가 제품의 절반을 모르면, 새 기능을 기획할 때마다 "영어는요?"를 되묻게 된다.
> 아래는 **사용자 눈에 보이는 사실**만 적는다 — 콘텐츠 제작 규칙은 `06 §11`, 엔드포인트는 `04 §8`이 정본이다.

### 10-1. 왜 같은 서버에 두 과정인가

이 사이트가 파는 것은 일본어라는 **과목**이 아니라 **"공부 순서를 대신 정해 준다"는 방식**이다(§1).
그 방식은 언어를 가리지 않으므로, 학습자가 "다음 유닛만 누르면 되는" 경험을 **영어에도 그대로 준다.**
코스-유닛-플레이리스트 모델(§4)·진도(§7)·자료실(§5)은 이미 만들어져 있고, 과정이 하나 늘어도 **새로 만들 화면 틀이 없다.**

**단, 그대로 복사하지는 않는다 — 사용자 결정(확정):**

> **"영어는 일본어처럼 단계를 똑같이 하면 안 되고, 영어 나름의 뼈대가 필요하다."**

이 한 줄이 아래 모든 차이의 근거다. JLPT N5~N1에 해당하는 공인 단계표를 영어에 억지로 맞추지 않고,
**"지금 무엇이 안 되는가"로 단계를 나눈다** — 문장이 안 만들어진다 → 시제가 헷갈린다 → 길게 못 잇는다 → 어색하다 → 회의·이메일에서 막힌다.
그래서 영어 코스명이 곧 단계 이름이고(`다시 세우기` `일상 말하기` …), 레벨 코드(`E1`~`E5`)는 **화면에 쓰지 않는다.**

### 10-2. 현재 상태 (2026-09-08 실측)

| courseNo | 코스 id | 코스명 | 상태 | 유닛 |
|---:|---:|---|---|---:|
| 1 | 101 | **다시 세우기** | **AVAILABLE — 맛보기** | **2** |
| 2 | 102 | 일상 말하기 | 준비중 | 0 |
| 3 | 103 | 이어 말하기 | 준비중 | 0 |
| 4 | 104 | 뉘앙스 | 준비중 | 0 |
| 5 | 105 | 실전과 격식 | 준비중 | 0 |

**코스는 5개. 문자 코스(일본어의 코스 0)가 없다** — 영어 학습자는 이미 알파벳을 읽는다.
열려 있는 것은 **코스 1의 유닛 2개뿐**이고, 코스 상세에 `"지금은 맛보기 2개 유닛만 열려 있어요"`가 안내로 붙는다.
맛보기 2유닛 안의 콘텐츠 실측: **표현 12 · 어휘 30 · 문법 4 · 회화 2편**(유닛당 표현 6 · 어휘 15 · 문법 2 · 회화 1).

> **즉 영어 과정은 "뼈대는 완성, 콘텐츠는 맛보기" 상태다.**
> 화면·주소·데이터 구조·자료실은 전부 동작하고, 채워지지 않은 것은 **콘텐츠**다.
> 준비중 코스 카드는 클릭해도 이동하지 않고, 준비중 코스 주소로 직접 들어가면 **열린 영어 코스로 가는 길**을 보여 준다(일본어 코스로 보내지 않는다).

사용자가 갈 수 있는 영어 주소:

| 주소 | 무엇 |
|---|---|
| `/en` | `/en/courses`로 바로 넘어간다 (영어 전용 홈은 만들지 않았다) |
| `/en/courses` | 영어 코스 목록 5장 |
| `/en/courses/:id` | 코스 상세(유닛 목록) |
| `/en/courses/:id/units/:unitNo` | 유닛 학습 |
| `/en/start` | 시작점 안내 — **채점 없는 자기 선택**(§10-4) |
| `/en/library/expressions` · `/grammar` · `/vocabulary` | 영어 자료실 3종 (+ 표현·문법 상세) |

### 10-3. 일본어와 갈리는 점 — 사용자 눈에 보이는 5가지

| # | 일본어 화면 | 영어 화면 | 근거 |
|---|---|---|---|
| 1 | 유닛 3번째 스텝이 **한자** | **표현(expression)** — 통째로 외워 쓰는 덩어리(`get up`, `be good at`). 한자 스텝은 **아예 없다** | `06 §11-4·11-5` |
| 2 | 한자 위에 **읽는 법(kana)** | kana가 없다. 대신 **IPA + 한글 근사** 두 표기(`/ˈmɔːrnɪŋ/` · `모-닝`)가 어휘·표현 전량에 붙는다 | `06 §11-3` |
| 3 | 유닛 끝에 **확인 문제**, 문장에 **음성 버튼** | **둘 다 없다 — 빠진 게 아니라 의도한 결정이다**(§10-5) | `09 §5` |
| 4 | 코스명 옆에 **JLPT N5 같은 레벨 라벨** | 라벨을 쓰지 않는다. **코스명이 곧 단계 이름**이다 | `06 §11-2` |
| 5 | 코스 카드에 "여기서 시작하세요" 배지가 **자동으로** 붙는다(§8) | **자동으로 붙지 않는다.** 시작점은 `/en/start`에서 사용자가 고른다 | `06 §11-2` |

**같은 것**: 코스는 순서가 있는 한 줄(§2), 유닛이 학습의 최소 단위이고 **정리가 언제나 마지막 스텝**(§3),
콘텐츠는 페이지가 아니라 데이터이고 **자료실은 부록**(§4·§5), 잠금이 없고 모든 유닛은 주소로 바로 열린다(§3),
비로그인도 전부 볼 수 있다(§6).

**자료실도 3탭인데 종류가 다르다** — 일본어는 한자·문법·어휘, 영어는 **표현·문법·어휘**다.
영어에는 한자 탭이 없고, `/en/library/kanji`는 **존재하지 않는 주소**다. 어휘는 양쪽 모두 상세 화면이 없다(행 확장).
GNB "자료실"을 눌렀을 때 기본으로 열리는 탭도 갈린다: 일본어는 한자, **영어는 표현**.

### 10-4. 두 과정을 오가는 길 — GNB 과정 스위처

**GNB 메뉴는 어느 과정에서나 3개 그대로다**(학습 · 자료실 · 커뮤니티). 메뉴를 언어별로 늘려 6칸을 만들지 않는다.
대신 헤더에 **과정 스위처(일본어 / 영어)** 가 있고, 지금 보고 있는 과정에 맞춰 **메뉴의 목적지만 갈아 끼운다.**

- 영어 화면에서 "학습" → `/en/courses`, "자료실" → 영어 표현 자료실. **영어를 보다가 자료실을 눌렀는데 일본어 한자 1,350자가 나오는 일은 없다.**
- **커뮤니티는 과정 공용이다** — 갈리지 않는다.
- 어느 과정에 있는지의 판정은 주소 `/en` 하위 여부이고, 그 밖은 전부 일본어(기본값)다.

**진도와 보관함은 영어에도 켜져 있다**(§7과 같은 규칙, 비로그인도 동일).

- 영어 유닛도 정리 스텝을 열면 **완료**로 켜지고, 코스 카드·유닛 목록에 진도가 그대로 보인다.
- **"마지막 위치"는 사이트 전체에 하나뿐이고 두 과정이 그것을 공유한다.** 영어 유닛을 보다 나가면 홈의 [이어서 학습하기]가 **영어 유닛**을 가리킨다.
  이건 의도된 결과다 — "지금 있는 곳"은 사람마다 하나다. 두 과정을 번갈아 보는 사용자에게 어떻게 보여야 하는지는 §10-6의 미결 항목이다.
- 유닛 학습 화면의 ★(보관함 담기)는 영어 문법·어휘에도 보인다.

**`/en/start`(시작점 안내)는 일본어의 `/diagnosis`와 다른 물건이다.**
문제도 채점도 없고, **"지금 무엇을 말할 수 있는가"(can-do) 문장 중 하나를 고르면** 그에 맞는 코스로 보내 준다. **결과를 저장하지 않는다.**
콘텐츠가 맛보기 2유닛뿐인 상태에서 문제 기반 진단을 만들면 낼 문제가 없다 — 콘텐츠가 쌓인 뒤 다시 판단한다(`06 §11-12`).

### 10-5. 콘텐츠를 채우기 전에 반드시 먼저 할 일 — Red 테스트 5개

영어 과정의 다음 이터레이션에서 **첫 작업은 콘텐츠가 아니다. 테스트다.**

> 지금 `gradlew test`는 영어에 대해 **코스 5개·유닛 응답 모양·품사 7종·자료실 레벨 코드**까지만 잡는다.
> 반면 **콘텐츠 내용 규칙(kana·중복·수량·발음 표기·퀴즈 미노출)을 강제하는 테스트는 0건**이다 —
> 즉 **규칙을 어긴 영어 콘텐츠를 넣어도 테스트가 통과한다.** 전수 검증이 일본어 코스만 순회하기 때문이다.

콘텐츠 착수 전 senior-dev가 먼저 실패하는 테스트로 고정해야 하는 5개 (`06 §11-11`):

1. 영어 콘텐츠의 `kana`가 전량 비어 있는가
2. 표현·어휘의 **코스 내부 중복 금지**
3. 유닛당 표현 6~10 · 어휘 15~20 · 문법 2~3 · 회화 1편(화자 2명 이상)
4. 어휘·표현 전량이 **IPA와 한글 근사 표기를 둘 다** 갖는가
5. 영어 유닛에 **확인 문제 스텝·음성 요소가 없는가**

**5번이 특히 중요하다.** 영어에 퀴즈·음성이 없는 것은 미구현이 아니라 **되돌린 결정**이다(2026-08-25 판정).
한 번 켜져 있던 것을 껐기 때문에, 테스트로 못 박지 않으면 **다음 사람이 "빠졌네" 하고 다시 켠다.**
켜지면 일본어 조판과 일본어 음성이 영어 학습자에게 노출된다 — 콘텐츠 없는 뼈대에 학습 도구를 먼저 얹지 않는다.

> 교훈 한 줄: **문서에만 적힌 계약은 지켜지지 않는다.**

### 10-6. 영어 과정에서 아직 사람이 정해야 할 것

- **코스별 유닛 수** — 일본어는 20/20/25/25. 영어는 미정이고 콘텐츠 착수 시 확정한다.
- **두 과정을 번갈아 보는 사용자의 "이어서"** — 마지막 위치가 하나뿐이라 나중에 본 과정이 항상 이긴다.
  과정별로 하나씩 기억할지, 지금처럼 하나로 둘지는 실사용이 생긴 뒤 정한다(지금은 하나로 둔다).
- **로그인 사용자가 영어 항목을 보관함에 담을 때** — 서버 보관함은 현재 **일본어 항목만 인정한다**(`04 §6-4` 판정 H1).
  ★는 영어 화면에도 보이는데 계정에는 남지 않으므로, **사용자에게 무엇이 보여야 하는지**(안내를 띄울지, 영어를 서버 보관함에 포함시킬지)를 정해야 한다.
- **영어 확인 문제·음성을 언제 켤 것인가** — "콘텐츠가 쌓이면"의 기준선(코스 1이 몇 유닛일 때)을 정해 둔다.
- **영어 커뮤니티** — 지금은 과정 공용이다. 나눌 이유가 생기는지 지켜본다.
