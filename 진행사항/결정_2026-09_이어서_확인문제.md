## 1. D-2. "이어서 학습하기"는 어디로 가는가

### 1-1. 결정

**"이어서" = 보던 곳(마지막 위치).** 사이트 전체에 하나뿐인 그 위치를 보여주는 화면 — **홈 히어로와 마이페이지** — 에서만 이 말을 쓴다.

**"다음 유닛" = 아직 안 마친 가장 앞선 유닛(미완료 최전선).** 코스 하나를 펼쳐 놓는 화면 — **코스 상세** — 는 이 말을 쓴다. 코스 상세와 코스 카드에는 **"이어서 학습하기"라는 문구가 없다.**

같은 말로 다른 곳에 보내지 않는다. 두 개념은 둘 다 필요하므로 **말을 갈랐다.**

"이어서"의 목적지는 다음 셋 중 하나다(위에서부터 판정):

| 마지막 위치 상태 | 목적지 | 히어로 문장(권장) |
|---|---|---|
| ① 보던 유닛을 **아직 안 마쳤다** | 그 유닛, **보던 스텝 복원** | "{코스} 코스 · 유닛 {n} 학습 중이었어요" |
| ② 보던 유닛을 **마쳤고**, 같은 코스에 그 뒤 미완료 유닛이 있다 | 그 뒤 **첫 미완료 유닛**의 1번 스텝 | "{코스} 코스 · 유닛 {n} 완료 · 다음은 유닛 {m}" |
| ③ 보던 유닛을 마쳤고, 그 뒤 미완료 유닛이 없다(= 그 뒤를 다 마쳤다) | 다음 코스가 열려 있으면 **다음 코스 상세**, 없으면 **코스 목록** | "{코스} 코스를 완주했어요" |

버튼 문구: ①②는 **[이어서 학습하기]**, ③은 **[다음 코스: {코스명}({레벨}) 시작하기]** 또는 **[코스 목록 보기]**.
③에서 "이어서"를 쓰지 않는 이유 — 이어서 볼 것이 없다. 말이 사실과 어긋나면 안 된다.

> ②는 오늘 실제로 벌어지는 약한 흐름을 고친다: 유닛 2의 정리까지 보고 나갔다 오면 홈이 "유닛 2 학습 중이었어요"라며 **이미 마친 유닛 안으로** 되돌려 보내고, 사용자는 거기서 다시 [다음 유닛]을 찾아야 했다. "다음만 누르세요"가 홈에서 한 번 끊기던 자리다.

### 1-2. 이유

- 이 제품의 약속은 "순서를 대신 정해 준다"이지 "사용자가 고른 순서를 무시한다"가 아니다. **잠금이 없다**(01 §3)는 것은 건너뛰기가 정상 조작이라는 뜻이고, 그렇다면 건너뛴 사람이 돌아왔을 때 "보던 곳"으로 보내는 것이 약속을 지키는 것이다. → 홈은 **"돌아오기"** 화면이다.
- 하지만 코스 상세는 "이 코스에서 뭐가 남았나"를 펼쳐 보이는 **지도**다. 지도가 가리켜야 할 곳은 "안 한 곳"이고, 그것이 바로 "다음 유닛"이다. 이 화면이 "보던 곳"만 말하면 건너뛴 유닛 3~6이 화면에서 잊힌다.
- 두 화면이 다른 질문에 답한다면 **다른 말**을 써야 한다. 같은 말을 쓰면 사용자는 "어느 쪽이 맞지?"를 스스로 판단해야 하고, 그 순간 핵심 가치가 무너진다.
- **순서대로 진행하는 대다수 사용자에게는 두 답이 항상 같다.** ②의 판정 덕분에 "이어서"와 "다음 유닛"이 정상 경로에서는 같은 유닛을 가리킨다. 갈라지는 것은 건너뛴 사람뿐이고, 그 사람에게는 갈라진 두 말이 각각 정확하다.

### 1-3. 화면별 문구·동작

| 화면 | 지금 | 결정 후 |
|---|---|---|
| **홈 히어로** | "…유닛 7 학습 중이었어요" + [이어서 학습하기] → 마지막 위치 유닛(완료 여부 무관) | §1-1 표의 ①②③. ②③ 분기가 새로 생긴다 |
| **마이페이지 · 내 학습** | 홈과 같은 문장 + [이어서 학습하기] | **홈과 완전히 같은 문장·같은 목적지.** 홈과 마이페이지가 다르게 말하는 순간이 없어야 한다 |
| **코스 상세 · 주 버튼** | 진도 0: [유닛 1부터 시작하기] / 진행 중: [유닛 3 **이어서** 학습하기] / 완주: [처음부터 다시 보기] | 진도 0: [유닛 1부터 시작하기] / 진행 중: **[유닛 3 학습하기]**(권장 문구, "이어서" 금지) / 완주: [처음부터 다시 보기]. 목적지는 지금과 같다(미완료 최전선) |
| **코스 상세 · 유닛 행** | 최전선 행에 오렌지 "여기부터", 마지막 위치 행에는 아무 표시 없음 | 최전선 행 "여기부터"는 그대로. **마지막 위치가 이 코스의 미완료 유닛이고 최전선과 다를 때만** 그 행에 **"보던 중"**(권장) 표시 — 오렌지가 아닌 회색 텍스트, "✓ 완료"와 같은 급의 읽기 전용 표시. 두 행이 같으면 "여기부터"만. 마지막 위치 유닛이 완료됐으면 "보던 중"을 붙이지 않는다(복습은 처음부터, 01 §7-4) |
| **코스 카드 · 강조 배지** | CONTINUE = "이어서 학습하기" | **"학습 중인 코스"**(권장). 카드는 코스 상세로 가는데 배지가 홈 버튼과 같은 말을 하면 같은 말·다른 목적지가 된다. 판정 순서(01 §8)는 바뀌지 않는다 — 문구만 |
| **유닛 학습 · 진입 안내 띠** | "보던 곳부터 이어서 보고 있어요 (4/7)" | 그대로. 여기서의 "이어서"도 마지막 위치를 뜻하므로 정의와 일치한다 |

**금지 문구**: 코스 상세·코스 카드·유닛 행에 "이어서"를 쓰지 않는다. 홈·마이페이지의 [이어서 학습하기]가 **완료된 유닛**을 가리키지 않는다.

### 1-4. 예외 상황

- 마지막 위치의 코스가 사라졌거나 준비중 → 홈·마이페이지는 이어보기 문장·버튼을 **만들지 않는다**(현행 유지). 히어로는 기본 문장 + [학습 시작하기].
- 마지막 위치는 있는데 그 유닛이 사라졌다(콘텐츠 개편) → ②와 같은 판정으로 그 뒤 첫 미완료 유닛; 없으면 코스 상세로.
- 영어 과정의 마지막 위치 → 같은 규칙, 주소만 `/en/…`. 영어 코스명은 레벨 괄호 없음(현행).
- 진도를 못 불러온 상태 → 진도 없는 화면(01 §7-6). 이어보기 문장이 없을 뿐 오류 카드는 뜨지 않는다.

### 1-5. 인수 조건 (senior-dev가 테스트로 옮긴다)

- [ ] **AC-R-1** 같은 진도 상태에서 홈 [이어서 학습하기]와 마이페이지 [이어서 학습하기]는 **같은 주소**로 간다.
- [ ] **AC-R-2** 마지막 위치 유닛이 미완료면 → 그 유닛으로 가고, 유닛 화면은 보던 스텝을 복원하며 "보던 곳부터 이어서 보고 있어요" 띠가 뜬다.
- [ ] **AC-R-3** 마지막 위치 유닛이 완료됐고 같은 코스 뒤에 미완료 유닛이 있으면 → 그 중 **가장 앞선** 유닛의 1번 스텝으로 간다. (예: 1·2·3 완료, 2를 다시 보고 나옴 → 4) 히어로 문장은 "유닛 2 완료 · 다음은 유닛 4"류로 **목적지를 명시**한다.
- [ ] **AC-R-4** 마지막 위치 코스의 유닛을 전부 완료했으면 → 히어로가 "완주" 문장을 보이고, 버튼은 다음 AVAILABLE 코스 상세로(없으면 코스 목록으로) 간다. 버튼 문구에 "이어서"가 없다.
- [ ] **AC-R-5** 코스 상세 주 버튼은 "아직 완료하지 않은 가장 앞선 유닛"으로 가며, 문구에 **"이어서"가 들어가지 않는다.** "여기부터" 배지는 그 유닛 행에만 붙는다.
- [ ] **AC-R-6** 유닛 1·2 완료 후 유닛 7을 보다 나온 상태에서 코스 상세를 열면: 주 버튼 → 유닛 3, 유닛 03 행 "여기부터", 유닛 07 행 "보던 중". 오렌지 표시는 화면에 하나(03)뿐이다.
- [ ] **AC-R-7** 건너뛰기 없이 순서대로 진행한 사용자(1·2 완료, 3을 보던 중)에게는 홈 [이어서 학습하기]와 코스 상세 주 버튼이 **같은 유닛(3)** 을 가리킨다.
- [ ] **AC-R-8** 코스 카드의 강조 배지 문구에 "이어서 학습하기"가 없다. 배지 판정(CONTINUE·START·NEXT 배타, 한 장)은 변하지 않는다.

### 1-6. 버린 대안

| 대안 | 버린 이유 |
|---|---|
| 전부 **마지막 위치**로 통일 | 코스 상세가 건너뛴 유닛 3~6을 가리킬 수 없게 된다. 마지막 위치가 **다른 코스**에 있으면 이 코스 상세는 결국 최전선으로 되돌아가야 해서 "하나로 통일"이 실제로는 안 된다 |
| 전부 **미완료 최전선**으로 통일 | 홈이 "유닛 7 학습 중이었어요"라고 말할 수 없다(사실은 7에 있었다). 보던 스텝 복원과도 어긋난다. 사용자가 고른 순서를 제품이 무시하는 셈 — 잠금 없음 원칙과 충돌 |
| 코스 상세에 **[보던 곳으로] 보조 버튼** 추가 | 유닛 행이 이미 클릭 가능하다. "보던 중" 표시로 충분하고, 버튼을 늘리면 주 버튼 하나 원칙(05 §3)이 흐려진다 |
| ② 없이 "이어서 = 마지막 위치 그대로" | 유닛을 마치고 나간 사람을 마친 유닛 안으로 되돌려 보낸다. "다음만 누르세요"가 홈에서 끊기는 현행 결함을 남긴다 |

## 2. D-3. 확인 문제는 [다음 ›]만 눌러서 만나야 한다

### 2-1. 결정

**확인 문제를 정리 앞으로 옮긴다.** 유닛 스텝 순서는 이렇게 고정한다:

```
문법(2~3) → 회화 → 한자(있을 때) → 어휘 → 확인 문제(일본어만) → 정리
```

그리고 **유닛 안의 전진 규칙 하나**로 모든 과정을 설명한다:

> **정리는 언제나 마지막 스텝이다. [다음 유닛 ›](코스 마지막이면 다음 코스 / 코스 목록)는 정리에만 있다.**
> **정리가 아닌 모든 스텝의 전진 버튼은 [다음 ›]이고, 항상 바로 다음 스텝으로 간다.**
> 세는 스텝 수(칩 수, "n / N"의 N) = [다음 ›]로 갈 수 있는 스텝 수.

이 규칙 아래에서:

| 과정 | 스텝 | 마지막(= [다음 유닛]) |
|---|---|---|
| 일본어 N5~N1 | 문법 2~3 · 회화 · 한자 · 어휘 · **확인 문제** · 정리 = 7~8 | 정리 (7/7 또는 8/8) |
| 입문 | 문법 2 · 회화 · 어휘 · **확인 문제** · 정리 = 6 (한자 0자 → 칩 없음) | 정리 (6/6) |
| 영어 | 문법 · 회화 · 표현(있을 때) · 어휘 · 정리 = 5~6 (확인 문제 없음, 09 §5) | 정리 |

확인 문제는 **기본 동선 위에 있되 붙잡지 않는다** — 카드에 [문제 풀기]와 함께 건너뛰는 [다음 ›]을 둔다. 풀지 않아도 정리에 닿으면 유닛은 완료다(문제 풀이는 완료 조건이 아니다).

### 2-2. 이유

- 확인 문제는 이 제품의 **몇 안 되는 능동 학습 도구**다. "다음만 누르세요"가 공식 동선이라면, 그 동선을 따르는 사람이 확인 문제를 **반드시 한 번은 만나야** 한다. 스텝 수에서 빼는 안(②)은 "있는데 안 보이는" 기능을 "없는 것과 같은" 기능으로 만든다.
- **정리를 마지막에 두는 것이 이 제품의 두 규칙을 그대로 살린다**: "정리 = 요약 + 다음 유닛 버튼"(01 §3), "완료는 정리(마지막) 스텝을 열면 켜진다"(01 §7-1). 확인 문제를 정리 뒤에 두면(①) 이 두 문장이 둘 다 거짓이 되고, "완료됐는데 아직 스텝이 남았다"는 어색한 상태가 생긴다.
- 배우기 → 확인 → 정리 → 다음 유닛. 문제를 많이 틀린 사람은 [‹ 이전]으로 돌아가 다시 보고 정리로 올 수 있다. 정리에 닿는 것이 유닛의 끝이라는 **하나의 심상**이 입문·N1·영어 모두에 같이 적용된다.
- 클릭 수는 ①과 같다(어휘 → 확인 문제 → 정리 → 다음 유닛). 늘어나는 것은 없다.

### 2-3. 유닛 학습 화면 — 스텝별 버튼

| 스텝 | 하단 진행 줄 | 카드 안 버튼 |
|---|---|---|
| 문법·회화·한자·어휘·표현 | [‹ 이전] · 스텝 n / N · **[다음 ›]** | — |
| **확인 문제 (풀기 전)** | [‹ 이전] · 스텝 n / N (전진 버튼은 카드 안에 — 진행 버튼 두 벌 금지, 05 §3) | **[문제 풀기]**(주 버튼) · **[다음 ›]**(보조, 건너뛰기 → 정리) |
| 확인 문제 (푸는 중) | [‹ 이전] · 스텝 n / N | 보기 4개 · [다음 문제] (현행) |
| 확인 문제 (결과) | [‹ 이전] · 스텝 n / N | 점수·근거 · [틀린 문제만 다시 풀기] · **[다음 ›]**(주 버튼 → 정리). **[다음 유닛]은 여기 없다** |
| 확인 문제 (문항 0개) | [‹ 이전] · 스텝 n / N | "이 유닛에서는 아직 문제를 만들 수 없어요" + **[다음 ›]** → 정리. 스텝은 그대로 센다(칩 수가 뒤늦게 바뀌지 않게) |
| **정리 (마지막)** | [‹ 이전] · 스텝 N / N · **[다음 유닛 ›]** / [다음 코스: … 시작하기 ›] / [코스 목록으로 ›] | 완료 토글·복습 블록·로그인 안내(현행) |

- [‹ 이전]은 첫 스텝에서만 비활성(현행).
- 스텝 칩은 모두 직접 클릭 가능(현행). 칩으로 정리에 뛰어도 완료다(01 §7-1).
- 확인 문제 진행 상태는 스텝을 오가도 유지되고 유닛을 떠나면 사라진다(09 §2-4, 현행).

### 2-4. 예외 상황

- 코스의 **마지막 유닛**: 확인 문제 → 정리 → [다음 코스: {코스}({레벨}) 시작하기 ›](열려 있을 때) / [코스 목록으로 ›]. 마지막 유닛의 확인 문제를 건너뛰고 코스 밖으로 나가는 경로는 **[다음 ›]만으로는 생기지 않는다.**
- 저장된 마지막 위치가 "확인 문제" 스텝인 채 재진입 → 확인 문제 스텝으로 복원(풀기 전 상태). 저장된 위치가 "정리"인데 완료 취소된 유닛 → 정리로 복원(현행 규칙).
- 순서를 바꾼 뒤에도 예전에 저장된 스텝 위치는 **이름으로** 찾으므로 "정리"에 저장된 사람은 정리로, "확인 문제"에 저장된 사람은 확인 문제로 열린다. 없는 이름이면 첫 스텝(04 §6-2, 현행).
- 확인 문제 재료(오답 풀) 통신 실패 → 만들 수 있는 문항만으로 세트를 만든다(09 §1-4). 0개면 위 "문항 0개" 행.

### 2-5. 인수 조건

- [ ] **AC-Q-1** 일본어 유닛(N5~N1·입문)을 1번 스텝에서 열고 **[다음 ›]만** 누르면 확인 문제 스텝에 도달한다. 칩을 누르지 않아도 된다.
- [ ] **AC-Q-2** 스텝 칩 순서가 "… 어휘 → 확인 문제 → 정리"이고, 정리가 마지막 칩이다. 영어 유닛은 "… 어휘 → 정리"로 확인 문제 칩이 없다.
- [ ] **AC-Q-3** 정리가 아닌 스텝에는 [다음 유닛]·[다음 코스]·[코스 목록으로]가 없고, 정리에는 [다음 ›]이 없다. 정리의 전진 버튼은 다음 유닛 / 다음 코스(AVAILABLE) / 코스 목록 3분기 그대로다.
- [ ] **AC-Q-4** 어떤 유닛에서도 "스텝 n / N"의 N은 칩 수와 같고, 마지막 스텝(정리)에서 n = N이다. (N5 8/8, 입문 6/6, 영어 5/5 또는 6/6)
- [ ] **AC-Q-5** 확인 문제 카드(풀기 전)의 보조 버튼 [다음 ›]을 누르면 문제를 풀지 않고 정리로 간다. 결과 화면의 주 버튼 [다음 ›]도 정리로 간다. 두 버튼 어디에도 "다음 유닛"이 없다.
- [ ] **AC-Q-6** 확인 문제를 건너뛰고 정리에 닿아도 유닛은 완료된다. 확인 문제 스텝에 머무는 것만으로는 완료되지 않는다.
- [ ] **AC-Q-7** 코스 마지막 유닛에서 [다음 ›]만 누르면 확인 문제 → 정리 순으로 도달하고, 정리에서만 [다음 코스: … 시작하기 ›] 또는 [코스 목록으로 ›]가 보인다.
- [ ] **AC-Q-8** 마지막 위치가 "확인 문제"로 저장된 미완료 유닛을 다시 열면 확인 문제 스텝(풀기 전)으로 복원된다.

### 2-6. 버린 대안

| 대안 | 버린 이유 |
|---|---|
| ① 정리 → 확인 문제 → [다음 유닛] (현행 순서를 잇기만) | 정리가 마지막이 아니게 되어 01 §3·§7-1 두 규칙을 고쳐 써야 한다. "유닛 완료" 뒤에 스텝이 하나 더 남는 상태가 생긴다. 확인 문제 결과 화면이 유닛의 끝이 되면 정리(복습 블록·완료 토글)는 지나쳐 가는 스텝이 된다 |
| ② 확인 문제를 스텝 수에서 빼고 "선택 과제"로 | 능동 학습 도구를 기본 동선에서 뺀다. "선택 과제"라는 새 화면 개념이 생기고, 칩 줄 밖에 따로 놓을 자리를 또 설계해야 한다. 표시(7/7)만 맞추고 사용자의 학습은 줄이는 안 |
| 확인 문제를 **완료 조건**으로(풀어야 완료) | 잠금 없음·추가 클릭 없음(01 §3·§7-1) 원칙과 충돌. 문제 풀기를 강제하면 "유닛을 채우는 게임"이 된다(01 §7-2) |
| 문항 0개면 확인 문제 칩을 아예 빼기 | 문항 수는 오답 풀을 불러온 뒤에야 확정되므로 칩이 뒤늦게 사라진다(스텝 수가 진행 중에 바뀜). 안내 카드 + [다음 ›]로 스텝 수를 고정하는 편이 낫다 |

## 3. 핵심 가치와의 대조 (`설계/01`)

| 01의 문장 | 이 결정과의 관계 |
|---|---|
| "학습자가 해야 할 일은 딱 하나다: 다음 유닛을 누르는 것"(§1) | **강화.** D-3으로 [다음 ›]만 눌러 유닛의 모든 스텝을 지나 [다음 유닛]에 닿는다. D-2 ②로 홈의 [이어서]가 마친 유닛 안으로 되돌려 보내지 않는다 |
| "잠금이 없다 … 목록의 시각적 순서로 권장 경로를 보여준다"(§3) | **유지.** 건너뛴 사람의 "보던 곳"을 존중하고(홈), 권장 경로는 코스 상세가 "여기부터"로 계속 보여준다 |
| "정리 = 요약 + 다음 유닛 버튼"(§3), "완료는 정리(마지막) 스텝을 열면 켜진다"(§7-1) | **유지.** 확인 문제를 정리 앞으로 옮겨 정리가 실제로 마지막이 되게 했다 — 지금 코드는 이 문장과 어긋나 있었다(정리가 7/8) |
| "마지막 위치 … 홈의 [이어서 학습하기], 유닛 재진입 시 스텝 복원"(§7 표) | **유지 + 보강.** "이어서"는 마지막 위치만 가리킨다는 문장과 ②③ 판정을 §7에 추가했다 |
| 코스 카드 배지 "이어서 학습하기"(§8 표 1순위) | **문구 변경.** "학습 중인 코스"로. 판정 순서는 그대로 |

01에 반영한 것: §3 스텝 순서에 확인 문제 추가 · §7에 규칙 8("이어서"의 정의) 추가 · §8 배지 문구 수정.

## 4. 다른 문서 소유자에게 — 반영 요청

### 4-1. `설계/05` 반영 요청 (designer)

- §8 코스 상세 주 버튼 3분기 문구: "유닛 n 이어서 학습하기" → "유닛 n 학습하기"(또는 designer 안). **"이어서" 금지**가 규칙이다.
- §8 유닛 행 표시에 **"보던 중"**(회색 텍스트, 읽기 전용, 오렌지 아님) 추가 — 조건은 §1-3.
- 코스 카드 CONTINUE 배지 문구 → "학습 중인 코스"(`lib/badgeView.js`).
- §15-1 확인 문제 결과 primary: "다음 유닛(마지막이면 코스 완료 분기)" → **"[다음 ›] → 정리"**. 풀기 전 카드의 보조 버튼도 "[다음 ›] → 정리".
- 홈 히어로 문장 3분기(§1-1 표)의 최종 문구.

### 4-2. `설계/09` 반영 요청 (senior-dev)

- §2-1 첫머리에 한 줄: **"확인 문제 스텝은 어휘 다음, 정리 앞이다. 정리가 마지막 스텝이고 [다음 유닛]은 정리에만 있다."**
- §2-4 "스텝을 오가도 유지" 문장은 그대로 유효 — 순서만 바뀐다.
- §5 영어 "정리에서 끝난다"는 그대로 유효.

### 4-3. 담당·순서

1. senior-dev — §1-5·§2-5 인수 조건을 테스트로(Red). 기존 테스트 중 "정리 뒤에 확인 문제" 순서·"결과 화면 [다음 유닛]"·"유닛 n 이어서 학습하기" 문구를 전제한 것은 함께 바꾼다.
2. frontend-dev — 구현(Green). 계약(API) 변경 없음 — 전부 화면·계산 쪽이다.
3. qa — §1-5·§2-5를 체크리스트로 실물 확인. 점검 D-2·D-3 재현 절차를 그대로 돌려 **재현되지 않음**을 확인.

## 5. 미결 / 결정 필요
