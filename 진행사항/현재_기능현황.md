## 1. 한눈에 보기

입문(문자)부터 JLPT N1까지 **정해진 한 길**을 따라가는 일본어 학습 사이트다.
학습자는 코스를 고른 뒤 "다음 유닛"만 누르면 되고, 각 유닛은 문법 → 회화 → 한자 → 어휘 → 정리 → 확인 문제 순서로 진행된다.
코스에 들어간 문법·한자·어휘는 **자료실**에서 사전처럼 다시 찾아볼 수 있다(콘텐츠를 두 번 만들지 않는다).
백엔드는 Spring Boot(JSON REST 전용), 화면은 React CSR(SPA) 하나다.

## 2. 학습 기능 — 일본어

### 2-1. 코스 구조

- 코스는 **6개 고정**이고 `courseNo` 오름차순으로 하나의 길을 이룬다.
- 코스 상태는 `AVAILABLE` / `PREPARING` 두 가지. **일본어는 지금 6개 전부 `AVAILABLE`**이다.
  (`data-courses.sql`은 입문·N1을 PREPARING으로 넣고, 각 코스 콘텐츠 시드가 `UPDATE ... status='AVAILABLE'`로 전환한다 — 공용 파일을 코스별 작업자가 건드리지 않기 위한 구조다.)
- 4단계에서 `course` 테이블에 **`level_code`(자료실 필터 코드)** 와 **`language`(과정 언어, `JA`/`EN`)** 열이 붙었다.

| 2 | 1 | `N5` | 왕초보 | JLPT N5 | AVAILABLE | 20 |
| 3 | 2 | `N4` | 초급 | JLPT N4 | AVAILABLE | 20 |
| 4 | 3 | `N3` | 중급 | JLPT N3 | AVAILABLE | 25 |
| 5 | 4 | `N2` | 중상급 | JLPT N2 | AVAILABLE | 25 |
| 6 | 5 | `N1` | 고급 | JLPT N1 | **AVAILABLE** | 25 |

### 2-3. 유닛 학습 화면의 스텝

`GET /api/courses/{courseId}/units/{unitNo}` 한 번으로 유닛 데이터를 전부 받고, 프론트가 스텝으로 나눠 보여준다.

| 순서 | 스텝 | 내용 |
|---|---|---|
| 1~3 | 문법①②③ | 문법 하나당 한 스텝. 명칭·한국어 부제·설명·예문(일본어/읽기/뜻) + 활용표(있을 때만) |
| 4 | 회화 | 유닛 문법이 쓰인 대화. 화자 배지, 같은 화자 연속이면 배지 생략. **전체 듣기 버튼** |
| 5 | 한자 | 카드 그리드. 글자·훈음·음독·훈독·예시 단어. **입문 코스는 이 스텝이 없다** |
| 6 | 어휘 | 3열 표(단어·읽기·뜻). 가나뿐인 단어는 읽기 열에 `─` |
| 7 | 정리 | 배운 문법 칩·한자·어휘 수·회화 제목 + (조건부) 복습 블록 + 완료 안내 |
| 8 | **확인 문제** | 그 유닛 콘텐츠로 **매번 새로 생성**하는 4지선다 **최대 10문항** |

- 스텝 바의 **모든 칩이 클릭 가능**(자유 이동), 이전/다음 버튼도 있다.
- 스텝 전환 시 스크롤을 위로 리셋하고, 모바일에선 현재 칩이 보이게 스크롤한다.
- 스텝은 **저장된 마지막 위치로 복원**되고(같은 유닛일 때만), 없으면 첫 스텝이다.
- 정리 스텝에 도달하면 그 유닛이 **완료**로 켜지고, 정리 스텝에서 손으로 끄고 켤 수 있다.
- 문법·한자·어휘 스텝에 **★(보관함)** 가 붙는다. 별 클릭은 자료실 이동으로 번지지 않는다.
- 로딩 스켈레톤, API 에러 카드(재시도), 404/400은 "없는 주소" 화면으로 분기한다.

### 2-4. 확인 문제(유닛 퀴즈)

- 문제은행이 **없다**. `frontend/src/lib/quiz.js`가 유닛의 한자·어휘·문법에서 **매 세트 새로 생성**한다(캐시 없음).
- 배분: 문법 3 · 한자 4 · 어휘 4를 목표로 채우되 **총 10문항 상한**. 재료가 모자라면 자동으로 줄어든다.
- 오답 보기 3개는 **우선순위 그룹**(같은 품사 → 그 밖)에서 채우고, 3개를 못 채운 문항은 조용히 버린다.
- 문법 오답 보기는 유닛 문법 2~3개로 부족해서 **스텝 진입 시 오답 풀을 1회 추가 조회**한다.
- 틀린 문항은 근거가 되는 **자료실 항목으로 바로 이동**할 수 있다.
- **결과를 저장하지 않는다**(`설계/08` F-21). 오답 노트·통계가 없는 이유가 이것이다.

### 2-5. 복습 블록

- **5의 배수 유닛(5, 10, 15, 20, 25)에서만** 정리 스텝 하단에 "지금까지 배운 것" 블록이 붙는다.
- 구간은 자기 포함 직전 5유닛(예: 유닛 10 → 유닛 6~10), 내용은 그 구간 문법 명칭 칩 목록.
- 별도 시드 없이 `unit_grammar` 매핑 + `grammar_point.name` 조회로 만든다.

### 2-6. 코스 연결 (완주 동선)

마지막 유닛의 정리 스텝에서 `nextCourse` 값에 따라 분기한다.

| 다음 코스 | 화면 |
|---|---|
| AVAILABLE | "다음 코스 ○○(레벨)로 바로 이어갈 수 있어요" + 다음 코스 상세로 가는 버튼 |
| PREPARING | "다음 코스 ○○은 지금 준비하고 있어요" + 코스 목록으로 |

> 일본어는 6개가 전부 열려서 **PREPARING 분기가 실제로는 안 나온다.** 코드는 남아 있고 영어가 그 경로를 쓴다.

### 2-7. 코스 목록 / 상세 / 시작점

- **홈(`/`)**: 히어로 + "학습 시작하기" + 코스 6장 축약 카드 + **실력 진단 배너**.
- **코스 목록(`/courses`)**: 코스 6장 + 시작점 안내 + **실력 진단 배너**.
- **코스 상세(`/courses/:id`)**: 요약 바(유닛/문법/한자/어휘 집계) + "유닛 1부터 시작하기" + 유닛 목록.
- 시작점 배지는 하드코딩이 아니라 `lib/courses.js`의 `entryCourseNo()`가 **AVAILABLE 중 courseNo 최솟값**으로 계산한다 → 입문이 열리면서 시작점이 자동으로 입문으로 옮겨 갔다.

## 4. 자료실 기능

3종 모두 **비로그인 공개**이고, 목록 상태(검색어·필터·정렬·페이지)를 **주소 쿼리스트링에 담는다**
→ 새로고침·뒤로가기·주소 공유가 그대로 복원된다. 검색은 디바운스 후 히스토리를 쌓지 않고 replace 한다.

| 자료실 | 경로 | 페이지 크기 | 검색 대상 | 필터 | 정렬 | 상세 화면 |
|---|---|---:|---|---|---|---|
| 한자 | `/library/kanji` | 60 | 글자·훈음·음독·훈독 | 레벨(N5~N1 복수) | 학습 순서 고정 | ✅ `/library/kanji/:id` |
| 문법 | `/library/grammar` | 20 | 명칭·한국어 부제 등 | 레벨(입문·N5~N1) + **활용표 있는 것만** 토글 | 학습 순서 고정 | ✅ `/library/grammar/:id` |
| 어휘 | `/library/vocabulary` | 50 | 단어·읽는 법·뜻 | 레벨(입문·N5~N1) + **품사 7종** | 학습 순서 / 가나순 | ❌ 없음 (행 확장 아코디언) |

- **레벨 코드는 6개**(`INTRO`·`N5`·`N4`·`N3`·`N2`·`N1`)다. 4단계 이전의 "N5~N2 4개"는 옛말이다.
- **한자 탭만 선택지에서 `INTRO`를 뺀다** — 입문에 한자가 0자라서다. 다만 `?level=INTRO`를 주소에 직접 넣으면 **400이 아니라 200 + 0건**이고 적용 칩으로 떠서 해제할 수 있다.
- 유효하지 않은 코드(예: 영어 코드 `E1`)를 일본어 자료실에 주면 **400 + `BUSINESS_RULE_VIOLATION`** — "지원하지 않는 레벨입니다: E1 (INTRO·N5·N4·N3·N2·N1 중 하나)".
- 레벨은 저장 컬럼이 아니라 `course.level_code`에서 온다(파생 컬럼을 두지 않는 설계).
- 적용된 조건은 **칩**으로 보이고 각각 X로 개별 해제, `[초기화]`로 전부 해제.
- 0건일 때는 걸린 조건을 문장으로 되읽어 주고 힌트를 준다.
- 첫 로딩만 스켈레톤, 조건 변경으로 인한 갱신은 기존 목록을 흐리게 유지한다.
- 품사 7종(일본어): 명사·동사·い형용사·な형용사·부사·접속사·표현.

### 4-1. 자료실 퀴즈 (`/library/:type/quiz`)

- **지금 걸어 둔 필터 조건 그대로** 문제를 만든다. 예: "N3 한자만 20문제".
- 문항 수는 **10 / 20** 두 가지 선택. 출제 재료는 자료실 API의 `size` 상한(100)에 맞춰 범위에서 뽑는다.
- 유닛 확인 문제와 **같은 생성 함수**를 쓴다(규칙이 갈리지 않게).
- 자료실 목록·상세에서 진입 버튼(`QuizEntry`)으로 들어간다.

### 4-2. 어휘 자료실의 뜻 합치기

같은 단어가 여러 코스·유닛에 나와도 **표제어 1줄**로 합치고, 펼치면 뜻별로 "어디서 배우나"(코스·유닛)를 모두 나열한다.
합치는 일은 **서버가 한다**. 여러 줄을 동시에 펼칠 수 있고, 필터·페이지가 바뀌면 모두 접힌다.
(어휘 매핑 2,016건 → 표제어 1,734개)

### 4-3. 코스 ↔ 자료실 링크

| 방향 | 동작 |
|---|---|
| 유닛 학습 → 자료실 | 문법 "자료실에서 보기", 한자 글자 클릭, 어휘 단어 클릭 → **아직 새 탭**(AC-P-24 미전환, §11-5) |
| 어휘는 상세가 없어서 | `/library/vocabulary?q={단어}` 검색 상태로 연다 |
| 자료실 → 코스 | 한자·문법 상세의 "어디서 배우나" → 해당 유닛 학습 화면으로. 어휘는 아코디언 안의 "배우기 ›" |
| 확인 문제 오답 → 자료실 | 문항 유형에서 링크를 파생시킨다 |

## 5. 학습 도구

### 5-1. 실력 진단 (`/diagnosis`)

- **계단식**: 낮은 레벨부터 **단계당 3문항(어휘 1 · 한자 1 · 문법 1)**, **3중 2** 이상이면 다음 단계로.
- 계단은 `N5 → N4 → N3 → N2 → N1` **5단계**다. 코스명·레벨을 하드코딩하지 않고 `GET /api/courses`의 AVAILABLE 코스에서 계산한다.
- **입문(INTRO)은 계단에서 빠진다** — 한자가 0자라 3문항을 만들 수 없다. "1단계도 통과 못 함 → 입장 가능한 첫 코스"가 자연스럽게 입문을 가리킨다.
- 진행 중에는 **정오를 보여주지 않는다.** 결과 화면에 근거 표 + **[한 단계 아래부터 보기]** 가 있다.
- 진입점은 **홈과 코스 목록의 배너 2곳뿐** — GNB 메뉴가 아니다.
- **결과를 저장하지 않는다.**

### 5-2. 음성 읽어주기 (TTS)

- 브라우저 `speechSynthesis`를 쓴다. 서버·비용·키가 없다.
- 속도 **2단계**: 보통 `1.0` / 느리게 `0.7`. 선택은 `localStorage`(`jp.tts.v1`)에 로그인 무관으로 저장.
- 읽을 텍스트 = **`kana ?? 원문`** — 콘텐츠 제작 규칙의 kana 계약이 곧 발음 계약이다.
- **전역 단일 재생**: 새 재생은 항상 cancel 후 시작, 화면·스텝 이탈 시에도 cancel.
- **노출 게이트**: `lang`이 `ja`로 시작하는 음성이 하나도 없으면 **버튼을 아예 렌더하지 않는다**(안내도 없다).
- 붙어 있는 곳: 유닛 학습(회화 전체 듣기·문장·예문·어휘), 자료실 목록 행, 한자 상세, 문법 상세, 퀴즈 문항.

### 5-3. 콘텐츠 편집 모드 (로컬 전용)

- 스위치는 `app.editor.enabled`. **로컬 기본 `true`**, `application-prod.yml`이 `false`로 덮는다.
- 꺼진 환경에서는 `@ConditionalOnProperty`로 **컨트롤러·서비스 빈 자체가 만들어지지 않는다** → `/api/editor/**`가 미매핑 404.
- prod에서 `true`로 켜면 `RailwayDeploymentValidator`가 **기동을 거부**한다(fail-fast).
- 인증을 요구하지 않는다(로컬 전용이라는 전제 위의 의도된 예외 — SecurityConfig 주석에 명시).
- 고칠 수 있는 것: **한자 · 문법 · 어휘 · 회화**. 저장하면 **응답이 진실**이고, 유닛 응답을 다시 받지 않고 그 항목만 갈아끼운다.
- 편집 결과를 **시드 SQL로 옮겨 붙일 요약**으로 뽑아 준다.
- 붙어 있는 화면: 자료실 목록 행 · 한자 상세 · 문법 상세 · 유닛 학습.
- **이것은 관리자 권한이 아니다.** 계정 역할과 무관한 환경 스위치다.

## 6. 개인 데이터 — 진도 · 보관함

- **진도**: 유닛을 열면 마지막 위치(`courseId`·`unitNo`·`stepKey`)가 저장되고 다시 들어가면 이어진다. 정리 스텝 도달 시 자동 완료, 손으로 토글 가능.
- **보관함(`/bookmarks`)**: 한자·문법·어휘 3종 탭(`?tab=`). 자료실과 **같은 봉투·같은 항목 DTO**를 쓴다. `sort=RECENT|LEARNING`.
- **비로그인도 그대로 쓴다** — 서버에 익명 행을 만들지 않고 `localStorage`(`jp.guest.v1`)에만 둔다. 종류별 **200개 상한**.
- 로그인하는 순간 브라우저 기록이 **한 트랜잭션으로 계정에 합쳐진다**(`POST /api/me/merge`, 합집합).
- 비로그인 보관함 목록은 자료실 목록 API의 **`ids`(최대 200) + `sort=GIVEN`** 파라미터로 그린다.

## 7. 계정 · 인증

### 7-1. 로그인 방식

| 방식 | 경로 | 상태 |
|---|---|---|
| 로컬 회원가입 | `POST /api/users` | ✅ 아이디 4~20자, 비밀번호 4자 이상, 닉네임 2~20자, 이메일 형식. 아이디·이메일 중복 차단 (**닉네임 중복은 허용**) |
| 로컬 로그인 | `POST /api/login` (JwtLoginFilter) | ✅ |
| 카카오 OAuth2 | `/custom-oauth2/login/web/kakao` → `/login/oauth2/code/kakao` | ✅ |
| 구글 OAuth2 | `/custom-oauth2/login/web/google` → `/login/oauth2/code/google` | ✅ |
| 앱 네이티브 소셜 로그인 | `POST /api/oauth2/providers/{provider}/tokens` | ✅ API는 있으나 **호출하는 앱이 없다**(Flutter 미도입) |

### 7-2. 토큰

- JWT 2종: **access 30분**, **refresh 4시간**. 둘 다 `HttpOnly` 쿠키(`SameSite=Lax`, 운영은 `Secure=true`).
- `POST /api/tokens/refresh`는 **회전 방식**(검증 → 기존 삭제 → 신규 발급), 원자적.
- 웹은 쿠키로, 앱(Authorization 헤더)은 JSON 바디로 토큰을 받는 이중 경로.
- 프론트(`lib/http.js`)는 401 + `TOKEN_EXPIRED`일 때만 갱신하고, 동시 요청이 겹쳐도 갱신은 한 번만 나간다. 실패 시 `auth:expired`로 게스트 강등.
- 인증 실패 응답은 원인을 구분한다: `TOKEN_EXPIRED` / `INVALID_TOKEN` / `NOT_AUTHENTICATED`.

### 7-3. 역할 체계

- `user_roles`에 저장되지만 **실제로 존재하는 역할은 `USER` 하나뿐**이다(시드 111명 전원 USER).
- 코드 전체에 `ADMIN`, `hasRole(...)`, `@PreAuthorize` 사용처가 **하나도 없다**.
- 권한 검사는 전부 "작성자 본인인가"(id/username 비교) 방식이다.

### 7-4. 마이페이지 — 읽기 전용이 아니다 (2단계에서 확장)

| 화면 | 경로 | 할 수 있는 것 |
|---|---|---|
| 마이페이지 | `/mypage` | 프로필 + 무엇이 되고 무엇이 안 되는지(권한) 표시 |
| 프로필 수정 | `/mypage/edit` | 닉네임·이메일 등 수정(공백 트림 규칙 있음) |
| 비밀번호 변경 | `/mypage/password` | 로컬 계정만. 성공 시 **새 토큰 발급 + 다른 기기 세션 무효화** |
| 회원 탈퇴 | `/mypage/withdraw` | 미리보기(무엇이 지워지는지) → 탈퇴. **다른 기기 세션 즉시 끊김** |

- 탈퇴 시 남기는 것은 **재가입 차단용 로컬 아이디 문자열 하나**뿐이다.
- 소셜 계정은 비밀번호가 없어 비밀번호 변경이 막히고, 탈퇴 시 provider 식별자 연결을 끊는다.
- **아이디·비밀번호 찾기는 만들지 않기로 확정**됐다(이메일 발송 인프라가 붙는 별건).

## 10. 데이터 구조

### 10-1. 학습 콘텐츠 (핵심) — 시드 INSERT 행 수

```
course (11 = 일본어 6 + 영어 5)
  └─ course_unit (127 = 일본어 125 + 영어 2)  ── dialog (127) ── dialog_line (625)
        ├─ unit_grammar    (299)  ──→ grammar_point (299) ─┬─ grammar_example (605)
        │                                                   └─ grammar_rule    (359, 문법 87개분)
        ├─ unit_kanji      (1350) ──→ kanji (1350) ── kanji_word (1800)     ※ 일본어 전용
        ├─ unit_expression (12)   ──→ expression (12) ── expression_example (12)  ※ 영어 전용
        └─ unit_vocabulary (2046) ──→ vocabulary (2046)
```

- **콘텐츠는 페이지가 아니라 데이터다.** 코스/유닛은 문법·한자·어휘를 참조하는 얇은 매핑 층(플레이리스트 모델)이고, 자료실은 같은 데이터를 사전 뷰로 다시 보여줄 뿐이다.
- 매핑되지 않은 고아 콘텐츠 행이 **0건**이다(`unit_*` 행 수 = 콘텐츠 행 수). 3단계 이전에 있던 미매핑 픽스처 행은 사라졌다.
- **레벨은 `course.level_code`**에서 온다. 콘텐츠 테이블에 레벨 컬럼은 없다.
- **언어는 `course.language`** 한 컬럼으로만 갈린다(`JA` / `EN`). 콘텐츠 테이블은 공유한다.
- 회화(`dialog`)는 `course_unit`이 FK로 직접 물고 있어 유닛당 정확히 1개다.
- 시드 ID 대역: N5 `1~999`, N4 `1000~`, N3 `2000~`, N2 `3000~`, **입문 `4000~`**, **N1 `5000~`**, **영어 `9000~`(코스는 101~105)**.
- ⚠️ 공유 테이블의 컬럼명 `jp`(`grammar_example.jp`, `dialog_line.jp`)는 영어에서도 "원문" 자리로 쓰인다. rename은 일본어 응답 계약(필드명 `jp`)을 깨므로 하지 않았다.

### 10-2. 계정

```
users (111) ── user_roles (111, 전부 'USER')
            └─ refresh_entity (리프레시 토큰 저장)
```
