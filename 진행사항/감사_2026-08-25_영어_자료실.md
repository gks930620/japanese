**고치는 비용**: 작음(반나절 이하). `nav.js`에 `navItems(pathname)` 하나를 두고 `/en` 접두면 대상과 접두를 갈아 끼운다. `lib/nav.test.js`가 이미 있어 테스트 자리는 있다.

## H3. 자료실 퀴즈가 **50% 확률로** "이 조건으로는 문제를 낼 수 없어요(4개 이상 필요)" — 범위는 102개다

**재현** (화면 실측, 일본어 자료실 정상 경로)

1. `/library/vocabulary?q=하` → 목록 "총 1,734개 중 **102개**" ([이 조건으로 문제 풀기] 활성)
2. [이 조건으로 문제 풀기] → `/library/vocabulary/quiz?q=하`
3. 결과가 **뽑기 운에 따라 갈린다**:

| `Math.random()` | 화면 |
|---|---|
| 0.01 (첫 창) | "**'하' 어휘 102개 중에서 출제합니다**" + [문제 풀기] |
| 0.99 (마지막 창) | "**이 조건으로는 문제를 낼 수 없어요(4개 이상 필요)**" + [자료실로 돌아가기] |

**근거**: `frontend/src/pages/LibraryQuizPage.jsx:56-68`

```js
if (first && first.totalPages > 1) {
  const pick = Math.floor(Math.random() * first.totalPages);   // 마지막 창도 뽑힌다
  ...
  setPage({ ...other.data, totalElements: first.totalElements }); // content는 그 창, 총계는 전체
}
```

그리고 `:129` 판정이 **총계가 아니라 그 창의 길이**를 본다.

```js
{page && (page.content?.length ?? 0) < 4 && ( … "4개 이상 필요" … )}
```

API 실측: `GET /api/library/vocabulary?q=하&size=100` → `totalElements=102, totalPages=2`, **page 0 = 100건 / page 1 = 2건**.
꼬리 창을 뽑으면 `content.length = 2 < 4`가 된다.

**이 무작위 창 뽑기는 이전 QA 지적("늘 앞쪽 100개만 쓰면 모집단과 출제 범위가 어긋난다")의 수정으로 들어온 것**이다(같은 파일 `:54-55` 주석). 고치면서 꼬리 창을 안 봤다.

**일반화**: 조건에 맞는 항목 수가 `100k+1 ~ 100k+3`이면 언제든 재현된다. 지금 데이터에서 이 조건에 걸리는 것은 어휘 `q=하`(102개) 하나지만, **콘텐츠가 늘면 조합이 늘어난다**(레벨·품사·검색 조합 전부가 후보다).

**부수 증상**: 꼬리 창이 4개 이상일 때도 문제는 남는다 — "102개 중에서 출제합니다"라고 말해 놓고 실제 출제 모집단은 그 창 안의 항목뿐이다(오답 보기 포함).

**고치는 비용**: 매우 작음. 뽑는 창을 `totalPages - 1` 대신 **4건 이상이 보장되는 창**으로 한정하거나, `< 4` 판정을 `page.totalElements`(전체)로 바꾸고 창이 모자라면 다시 뽑는다.
