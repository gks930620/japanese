# 높음

## H1. 실력 진단이 입문 코스를 **구조적으로** 추천할 수 없다 — 코드 주석이 스스로를 반증한다

**상태**

`frontend/src/lib/diagnosis.js:17`

```js
export const STAGE_LEVEL_CODES = ["N5", "N4", "N3", "N2", "N1"];
```

`stagePlan()`(같은 파일 32행)이 이 배열로 코스를 거르므로 **계단에 입문(INTRO)이 없다.** 여기까지는 의도된 설계다 — 단계마다 한자 1문항이 필요한데 입문은 한자가 0자다.

문제는 그 다음이다. 같은 파일 `10~13행` 주석이 이렇게 정당화한다:

```
"1단계도 통과 못 함 → 입장 가능한 첫 코스"가 자연스럽게 입문을 가리킨다(계약 §A-2).
```

**이 문장은 사실이 아니다.** `recommend()`(`diagnosis.js:86`)는 `plan[recommendedIndex]`를 반환하는데 `plan`에 입문이 없다. 실제 `/api/courses` 응답으로 실행한 결과:

```
stagePlan  : [{id:2,N5}, {id:3,N4}, {id:4,N3}, {id:5,N2}, {id:6,N1}]
1단계 탈락 → {"recommendedCourseId":2, "stepDownCourseId":null, "allPassed":false}
plan에 입문 포함?  false
```

**히라가나를 전혀 모르는 사람이 진단을 보면 입문(코스 0)이 아니라 왕초보(N5, 코스 2)로 보내진다.** 재료 로딩 실패 시의 대체 경로도 같다 — `DiagnosisPage.jsx:156-159`의 `firstCourse = plan[0]`이라 "일단 **왕초보**부터 시작하기"가 뜬다.

즉 **입문 코스는 진단이라는 경로로는 도달할 수 없다.** 진단은 이 제품의 핵심 가치("어디서 시작할지 사이트가 정해 준다")를 담당하는 기능이고, 입문 코스는 그 가치의 가장 아래 칸이다.

**왜 안 잡혔나**: `frontend/src/lib/diagnosis.test.js`가 `recommendedCourseId === 2`를 단언하는데, **그 픽스처에서는 입문이 `PREPARING`이라** 지금도 통과한다(M1 참조). `diagnosis.intro.test.js`는 입문 대체 서사를 산문으로 적고 `stagePlan`만 검증한다 — `recommend()`를 **입문이 AVAILABLE인 상태로** 부르는 테스트가 없다.

**고치는 비용**: 작음(반나절 이하). `recommend()`에 "1단계도 통과 못 했을 때는 계단 밖의 더 낮은 AVAILABLE 코스"를 넘기는 인자를 두거나, 결과 화면이 `entryCourseNo()`(`lib/courses.js` — 이미 입문을 올바르게 계산한다)를 쓰게 하면 된다. 계약 변경이므로 senior-dev 경유.

## H2. 퀴즈 오답 선택지가 **낮은 레벨 문법에서만** 나온다 — N1 학습자는 문제를 읽지 않고 정답을 고를 수 있다

**상태**

`frontend/src/pages/UnitStudyPage.jsx:605`

```js
callPublicApi("/api/library/grammar?size=100")
```

레벨 필터가 없다. 자료실 문법은 **학습 순서(LEARNING)** 정렬이므로 앞에서 100개를 자르면 낮은 레벨만 담긴다. 실측 응답:

```
returned: 100 / total: 295 / levels: {"INTRO":20, "N5":44, "N4":36}
```

**N3·N2·N1 문법 184개는 오답 후보 풀에 단 하나도 들어가지 않는다.**

게다가 `frontend/src/lib/quiz.js:171`이 `others`를 **평평한 배열 하나**로 넘겨 유닛 문법과 풀 100개를 균등 셔플하므로, 오답의 대부분이 INTRO/N5/N4에서 나온다. 코스 6(N1) 유닛 1에서 실제로 생성된 문제:

```
これをください[INTRO] | 〜たり〜たりする[N4] | 〜んとする[N1·정답] | 〜たほうがいい[N4]
```

N1 학습자에게 이건 문제가 아니라 **레벨 맞히기**다. N3·N2도 정도만 덜할 뿐 같은 성격이고, 입문 유닛만 상대적으로 멀쩡하다(풀이 INTRO 20개로 시작하기 때문).

**고치는 비용**: 작음(반나절). 자료실 API가 `level=` 파라미터를 이미 지원한다. 다만 **유닛 응답의 문법 항목에는 `level` 필드가 없어서** 코스의 `levelCode`를 `UnitStudyPage`까지 끌어와야 한다 — 그게 이 건의 실제 작업량이다.

## M2. 코스 상세 화면이 입문 코스에 "한자 **0자**"를 11곳에 그린다 — 유닛 학습 화면은 같은 상황에서 숨긴다

같은 데이터에 대해 두 화면이 반대로 동작한다.

**숨기는 쪽** — `frontend/src/pages/UnitStudyPage.jsx:332`, `:458`

```jsx
{!latin && data.kanjis.length > 0 && ( ... 한자 요약 ... )}
{data.kanjis.length > 0 ? ` · 한자 ${data.kanjis.length}자` : ""}
```

**그리는 쪽** — `frontend/src/pages/CourseDetailPage.jsx:103`, `:144` (조건 없음)

```jsx

...
{en ? `표현 ${unit.expressionCount}` : `한자 ${unit.kanjiCount}자`}
```

실측 응답(`GET /api/courses/1`):

```

```
