# 사용자 관점 점검 — 2026-09-03

**무엇을 봤나**: 빌드 성공·테스트 통과가 아니라 **화면 상태 · 사용자 불편 · 비즈니스 로직**.
**어떻게 봤나**: 로컬 서버(`localhost:8083`)를 켜 둔 채 **실제 React 페이지를 jsdom에 렌더해 살아 있는 API로 호출**하는
임시 하네스를 만들어 화면을 눌러 봤다(**API 목킹 없음** — 진짜 응답으로 그린 화면이다). API는 curl로 따로 두들겼다.
**보지 않은 것**: 색·간격·그림자 등 시각 표현 — 디자인 킷 교체(Halo → Lets)가 예정돼 있어 제외했다.

> **표기 규칙**
> **[결함]** 제품이 기획·문서·**자기 자신**과 어긋난 것 — 고쳐야 한다
> **[불편]** 동작은 하는데 사용자가 손해 보는 것 — 판단해서 고친다
> **[취향]** 갈릴 수 있는 것 — 참고만. 고칠 의무 없음
> 근거는 **재현함**(실제로 눌러 봤다) / **코드 확인**(코드를 읽어 확인)으로 구분해 적었다.

## 1. 치명

### D-1. [결함] 자료실 퀴즈(한자·문법)가 아예 열리지 않는다 — **재현함**

**증상**
`/library/kanji/quiz` · `/library/grammar/quiz`로 들어가면 퀴즈 화면이 아니라
**"？ 찾을 수 없는 항목이에요 / 주소가 바뀌었거나 없는 한자·문법이에요"** 404 카드가 뜬다.
`/library/vocabulary/quiz`만 정상으로 열린다.

**재현**
1. `/library/kanji`(또는 `?level=N5`)를 연다.
2. 결과 개수 줄 오른쪽 **[이 조건으로 문제 풀기]** 를 누른다. (링크 주소는 `/library/kanji/quiz?level=N5`가 맞다)
3. 퀴즈 시작 화면 대신 한자 **상세** 404 카드가 나온다. 문법 탭도 같다.
4. 주소창에 직접 `/library/grammar/quiz`를 넣어도 같다.

**원인(코드 확인)** — `frontend/src/App.jsx`
```
<Route path="/library/kanji/:kanjiId"   element={<LibraryKanjiDetailPage />} />   // 먼저 선언
<Route path="/library/grammar/:grammarId" element={<LibraryGrammarDetailPage />} />
<Route path="/library/:type/quiz"       element={<LibraryQuizPage />} />          // 나중에 선언
```
React Router의 경로 점수가 **동점**(`정적+정적+동적` vs `정적+동적+정적`)이라 **먼저 선언된 쪽**이 이긴다.
그래서 `quiz`가 `:kanjiId` 값으로 먹히고, 상세 화면이 `GET /api/library/kanji/quiz`를 호출해
서버가 `400 TYPE_MISMATCH`(`파라미터 타입이 올바르지 않습니다: kanjiId`)를 주며 404 카드로 떨어진다.
**어휘만 멀쩡한 이유는 어휘에 상세 라우트가 없어서**다 — 즉 우연히 살아 있다.

**사용자에게 무엇이 문제인가**
자료실 세 탭 중 **두 탭에서 [이 조건으로 문제 풀기] 버튼이 막다른 길**이다.
게다가 도착 화면이 "없는 한자·문법이에요"라고 말해, 사용자는 **자기가 건 검색 조건이 잘못됐다고 오해**한다.
버튼을 눌러 도달한 곳이 "그런 건 없다"고 답하는 것은 제품이 자기 버튼을 부정하는 것이다.

**왜 테스트로 안 잡혔나(같이 봐야 할 것)**
`LibraryQuizPage.test.jsx`류는 퀴즈 **컴포넌트**를 직접 렌더한다. **App의 라우트 표를 통과시키는 테스트가 없다.**
고칠 때 라우트 순서만 바꾸지 말고 **"`/library/{type}/quiz` 주소가 퀴즈 화면을 그린다"를 App 라우팅 수준에서 고정하는 테스트**를 함께 넣어야 같은 사고가 반복되지 않는다.

**제안** (판단은 senior-dev)
`/library/:type/quiz`를 상세 라우트보다 **위로 올리거나**, 상세 라우트를 `/library/kanji/:kanjiId(\d+)`처럼 숫자로 좁힌다.
담당: **frontend-dev** (테스트 선작성은 senior-dev)

## 2. 높음

### D-2. [결함] "이어서 학습하기"가 화면마다 **다른 유닛**을 가리킨다 — **재현함**

**증상**
같은 순간, 같은 사용자에게 제품이 두 가지 "이어서"를 말한다.

| 화면 | 문구 | 실제로 가는 곳 |
|---|---|---|
| 홈 · 마이페이지 | "왕초보(JLPT N5) 코스 · **유닛 7** 학습 중이었어요" → [이어서 학습하기] | `/courses/2/units/**7**` |
| 코스 상세 `/courses/2` | [**유닛 3** 이어서 학습하기] (+ 유닛 03에 **여기부터** 배지) | `/courses/2/units/**3**` |

**재현** (로그인/비로그인 모두 같다)
1. 코스 2(왕초보)의 유닛 1·2를 끝까지 본다(정리 스텝에 닿으면 자동 완료).
2. 코스 상세 목록에서 **유닛 7을 눌러** 들어간다(잠금이 없으므로 정상 조작이다). 다 보지 않고 나온다.
3. **홈** → "유닛 7 학습 중이었어요 / [이어서 학습하기]".
4. **코스 상세로 들어간다** → 큰 버튼이 [**유닛 3** 이어서 학습하기], **여기부터** 배지도 유닛 3에 붙는다.
   내가 마지막으로 있던 **유닛 7에는 아무 표시가 없다.**

**원인(코드 확인)** — 두 화면이 서로 다른 정의를 쓴다. 둘 다 문구는 "이어서 학습하기"다.
- 홈·마이페이지: `frontend/src/lib/resume.js` → **마지막 위치(lastPosition)**
- 코스 상세·코스 카드: `frontend/src/lib/progressView.js`의 `nextUnitNo()` → **완료하지 않은 가장 앞선 유닛**

각각의 근거 문서는 있다(판정 B-H3 / AC-P-15·16). **둘을 나란히 놓고 판정한 문서가 없다.**

**사용자에게 무엇이 문제인가**
이 제품의 약속은 "**순서 고민하지 말고 다음만 누르세요**"다. 그 약속의 실행 버튼이 **화면마다 다른 답**을 준다.
사용자는 "내가 어디까지 했더라"를 제품에게 물으려고 왔는데, 제품이 두 가지로 답하면 **결국 자기가 판단해야 한다** — 핵심 가치가 무너진다.
게다가 코스 상세는 사용자가 실제로 머물렀던 유닛 7을 **화면에서 지운다**(표시가 없다).

**제안** (결정은 product-planner + senior-dev)
"이어서"의 정의를 **하나로 못 박고** 두 모듈이 그 하나를 쓰게 한다. 정의가 둘 다 필요하다면 **문구를 갈라야** 한다 —
예: 마지막 위치는 "**보던 곳으로**", 미완료 최전선은 "**다음 유닛부터**". 같은 말로 다른 곳에 보내지 않는 것이 핵심이다.
담당: **frontend-dev**(구현) / 정의는 **product-planner·senior-dev**
→ **결정됨(2026-09-03)**: `결정_2026-09_이어서_확인문제.md` §1 — "이어서" = 마지막 위치(홈·마이페이지만), 코스 상세·카드는 "다음 유닛". 인수 조건 AC-R-1~8.

### D-3. [결함] **확인 문제가 기본 동선에서 도달할 수 없다** — 그런데 "스텝 8 / 8"이라고 말한다 — **재현함**

**증상**
유닛 학습에서 [다음 ›]만 눌러 진행하면 **확인 문제를 한 번도 만나지 못한다.**
정리 스텝에 도착하는 순간 [다음 ›] 버튼이 사라지고 그 자리에 **[다음 유닛 ›]** 이 들어와, 유닛 밖으로 내보낸다.
그런데 같은 줄의 위치 표시는 **"스텝 7 / 8"** 이라고 말한다 — 남은 8번째 스텝으로 갈 버튼이 화면에 없다.

**재현**
1. `/courses/2/units/2`를 연다.
2. [다음 ›]만 반복해서 누른다. 문법①→문법②→문법③→회화→한자→어휘→**정리**.
3. 정리 스텝에서 버튼을 본다 → `‹ 이전` / `스텝 7 / 8` / **`다음 유닛 ›`**. **[다음 ›]이 없다.**
4. 확인 문제는 **위쪽 스텝 칩을 직접 눌러야만** 열린다(칩을 누르면 정상 동작한다 — "10문제" 안내와 4지선다가 나온다).

**원인(코드 확인)** — `frontend/src/pages/UnitStudyPage.jsx`
```
{!isSummary && !isQuiz && ( <button …>다음 ›</button> )}
{isSummary && <AdvanceLink … />}          // AdvanceLink = 다음 유닛 / 다음 코스 / 코스 목록
```
정리 스텝의 전진 버튼이 **유닛 안의 다음 스텝**이 아니라 **다음 유닛**으로 배선돼 있다.

**사용자에게 무엇이 문제인가**
- 확인 문제는 이 제품이 가진 **몇 안 되는 능동 학습 도구**인데, "다음만 누르면 된다"는 공식 동선을 그대로 따르면 **평생 못 본다.**
- 진행 표시(7/8)와 조작(다음 유닛)이 어긋나 **"버튼이 없어진 줄 알았다"** 는 오해를 만든다. 스텝이 8개라고 세어 놓고 8번째로 갈 길을 안 주는 것은 화면이 자기 말을 어기는 것이다.
- 마지막 유닛에서는 더 나쁘다: 정리 스텝의 버튼이 **[다음 코스: 왕초보(JLPT N5) 시작하기 ›]** 라, 코스의 **마지막 총정리 유닛의 확인 문제**를 건너뛰고 다음 코스로 넘어간다.

**제안**
① 정리 스텝의 전진을 **확인 문제**로 두고, [다음 유닛]은 확인 문제 스텝에서 준다(확인 문제 스텝에는 이미 [다음 유닛 ›]이 있다), 또는
② 확인 문제를 스텝 수에서 빼고 "선택 과제"로 분명히 드러낸다(그러면 "7/7"이 되어 표시도 맞는다).
**둘 중 무엇이든, 세는 스텝 수와 갈 수 있는 스텝 수는 같아야 한다.**
담당: **frontend-dev** / 동선 결정은 **product-planner**
→ **결정됨(2026-09-03)**: `결정_2026-09_이어서_확인문제.md` §2 — 확인 문제를 정리 **앞**으로, 정리가 마지막이고 [다음 유닛]은 정리에만. 인수 조건 AC-Q-1~8.

## 3. 중간

### D-4. [결함] 코스 목록의 안내 문구가 **자기 화면의 배지와 반대**로 말한다 — **재현함**

**증상** `/courses`를 진도 없이 열면 한 화면 안에서 두 가지 시작점을 말한다.
- 상단 안내 띠: "✎ 처음이면 **왕초보(N5)부터** 시작하세요"
- 바로 아래 카드 배지: **입문(코스 0)** 카드에 "**여기서 시작하세요**"

**재현**: 시크릿 창으로 `/courses`를 연다(진도 0). 두 문장이 동시에 보인다.

**원인(코드 확인)** `frontend/src/pages/CoursesPage.jsx:38`에 문구가 **하드코딩**돼 있다.
반면 배지는 `lib/courses.js`의 `entryCourseNo()`가 계산하며, 그 파일 주석은 이렇게 적혀 있다 —
`"N5"를 하드코딩하지 않는다: 입문(코스 0)이 열리면 자동으로 그쪽이 시작점이 된다.`
**코스 0이 열린 지금, 계산은 따라왔고 문구만 안 따라왔다.**

**사용자에게 무엇이 문제인가** 첫 화면에서 "어디부터?"에 두 답을 준다. 이 제품이 없애 주겠다고 한 바로 그 고민을 첫 화면이 만든다.

**제안** 안내 문구도 `entryCourseNo()` 결과에서 만든다. 담당: **frontend-dev**

### D-5. [결함] 커뮤니티만 **자료실이 세운 빈 화면·오류 규칙을 안 지킨다** — **재현함**

같은 제품 안에서 "없음"과 "오류"를 말하는 방식이 자료실/코스와 커뮤니티가 다르다.

| 상황 | 자료실 (좋은 쪽) | 커뮤니티 (문제) |
|---|---|---|
| 검색 결과 0건 | "**'zzzzzz' 검색 결과가 없어요** / 글자·훈음·음독·훈독 중 다른 것으로 찾아보세요" + **[검색·필터 초기화]** | "**게시글이 없습니다** / 첫 번째 게시글을 작성해보세요!" |
| 없는 항목 열기 | "**찾을 수 없는 항목이에요** / 주소가 바뀌었거나 없는 한자·문법이에요" + [자료실로][홈으로] | "**게시글을 불러오지 못했습니다** / 존재하지 않는 게시글입니다: 99999" |
| 목록 통신 실패 | `ApiErrorCard` + **[다시 시도]** | "목록을 불러오지 못했습니다" — **재시도 없음** |

**재현**
1. `/community?keyword=zzzzzzq` → "게시글이 없습니다"라고만 한다. **검색 때문에 0건인지 게시판이 빈 것인지 알 수 없고**, 조건을 지우는 버튼도 없다.
2. 그 화면은 비로그인에게도 "**첫 번째 게시글을 작성해보세요!**"라고 한다. 비로그인에겐 **[글쓰기] 버튼 자체가 없다**(`CommunityListPage.jsx:81` `isAuthenticated &&`). **할 수 없는 일을 시킨다.**
3. `/community/detail?id=99999` → "**불러오지 못했습니다**". 이건 통신 실패가 아니라 **없는 글**이다.
   `설계/08` C-12 ④가 정한 "주소가 틀린 것은 통신 실패가 아니다"에 어긋난다. (다행히 [다시 시도]는 없고 [커뮤니티 목록으로]가 있다.)

**사용자에게 무엇이 문제인가** 같은 제품이 화면마다 다른 말투로 실패를 알리면, 사용자는 **매 화면 처음부터 해석**해야 한다.
특히 검색 0건을 "게시글이 없습니다"로 뭉개면 **검색어를 지워 보면 된다**는 다음 행동이 떠오르지 않는다.

**제안** 커뮤니티 목록·상세를 자료실이 이미 쓰고 있는 상태 카드(`StateCards.jsx` / 0건 문구 규칙)로 맞춘다.
0건은 **조건 때문인지 아닌지**를 갈라 말하고, 없는 글은 "**찾을 수 없는 글이에요**"로 바꾼다.
담당: **frontend-dev**

### D-6. [불편] 404 화면이 **어디서 왔든 코스 얘기만** 한다 — **재현함**

**재현** `/nope/nope`, `/community/typo`, `/mypage/typo` 어디로 가든 같은 화면이 나온다:
"？ 찾을 수 없는 페이지예요 / 주소가 바뀌었거나 **없는 코스·유닛이에요**" + [코스 목록으로] [홈으로]

**무엇이 문제인가** 커뮤니티나 계정 주소를 잘못 친 사람에게 "없는 코스·유닛"이라고 답한다.
사용자는 **자기가 뭘 잘못했는지 모른 채** 관계없는 코스 목록으로 안내받는다.
(단 [다시 시도]를 두지 않고 나갈 길을 준 것은 C-12 ④를 잘 지킨 것이다.)

**제안** 전역 404의 설명은 대상 없이 쓰고("주소가 바뀌었거나 없는 페이지예요"), 코스·유닛 전용 문구는
코스 경로에서 뜨는 카드에만 남긴다(그 카드는 이미 따로 있다). 담당: **frontend-dev**

### D-7. [불편] 자료실 목록에 **끝으로 가는 길이 없고, 몇 쪽인지도 안 알려준다** — **재현함 + 코드 확인**

**증상** 어휘 1,734개(쪽당 50 = 35쪽), 한자 1,350자(쪽당 60 = 23쪽)인데 페이지 버튼은
`‹ 1 2 3 4 5 ›` 형태로 **다섯 개만** 보인다. **총 쪽수 표기도, 처음/끝 버튼도 없다.**

**원인(코드 확인)** `frontend/src/components/Pagination.jsx` — 창 크기 5 고정, 처음·끝 버튼 없음.

**무엇이 문제인가** "が로 시작하는 어휘 뒤쪽을 보고 싶다" 같은 훑기가 **클릭 예닐곱 번**을 요구한다.
더 나쁜 것은 **끝이 어디인지 모른다**는 점이다 — 총 개수("총 1,734개")는 알려주면서 쪽수는 안 알려주니
사용자는 자기가 어디쯤인지 가늠할 수 없다. 자료실은 **사전처럼 훑는 화면**이라 이 비용이 그대로 체감된다.
(검색·필터가 잘 돼 있어 치명적이진 않다. 그래서 중간이다.)

**제안** `n / 35` 표기 추가 + 끝 쪽 버튼. 담당: **frontend-dev**(디자인 판단은 designer)

### D-8. [결함] 커뮤니티에 **인형뽑기 게시글**이 들어 있다 — **재현함**

**재현** `/community`를 열면: "올해 목표: **인형 100개 뽑기**!", "**인형뽑기** 대회 있나요?", "포켓몬 인형 파는 곳" 등 10건 + 3쪽.

**무엇이 문제인가** 일본어 학습 사이트에 **완전히 무관한 보일러플레이트 시드**가 그대로 남아 있다.
지금 이 제품을 처음 보는 사람에게는 "이 사이트는 뭐 하는 곳이지?"가 되고, **배포 시 이 시드가 함께 올라가면 그대로 사고**다.
(`설계/07 §1`에 따라 운영은 시드를 수동 적재하므로 **자동으로 올라가지는 않는다** — 그래서 치명이 아니라 중간이다.
다만 "적재하지 않기"가 **사람의 기억에 의존**한다는 점이 위험이다.)

**제안** ① 학습 사이트 맥락의 시드로 교체하거나 ② 커뮤니티 시드를 로컬 전용으로 분리한다.
배포 체크리스트에 "**커뮤니티 시드 미적재 확인**"을 한 줄 넣는다. 담당: **backend-dev** / 절차는 **devops**

### D-9. [결함] 가입 화면이 **비밀번호 "6자 이상"** 이라고 하는데 실제 규칙은 **4자 이상** — **재현함**

**증상** `/signup`의 비밀번호 칸 placeholder가 **"비밀번호 (6자 이상)"** 이다.
그런데 실제로는 4자로 가입이 되고(서버 검증 `비밀번호는 4자 이상이어야 합니다`),
`/mypage/password` 화면은 같은 항목을 **"4자 이상"** 이라고 안내한다.

**재현**
1. `/signup` → 비밀번호 칸의 안내가 "6자 이상".
2. 비밀번호를 `1234`(4자)로 넣고 나머지를 채워 가입 → **성공한다(201)**.
3. `/mypage/password`를 연다 → 새 비밀번호 칸 안내가 **"4자 이상"**.

**사용자에게 무엇이 문제인가** 제품이 같은 규칙을 두 화면에서 다르게 말하고, 그중 **하나는 사실이 아니다.**
"6자 이상"을 믿은 사람은 5자 비밀번호를 쓸 수 있는데도 포기하고, 4자로 통과한 사람은 안내가 뭐였는지 헷갈린다.
같은 화면의 **아이디(4~20자)·닉네임(2~20자) 규칙은 아예 적혀 있지 않아**, 제출 버튼을 눌러 서버에게 물어봐야 안다.

**참고** `진행사항/README.md`가 "배포 시점 QA에서 **비밀번호 최소 4자 재검토**"를 남겨 뒀다(`설계/08 F-23`).
**지금이 그 시점이다.** 4로 갈지 6으로 갈지 사람이 정하고, 정한 값을 **세 곳(가입 안내·변경 안내·서버 검증)에 같이** 반영해야 한다.
담당: **frontend-dev**(문구) + **backend-dev**(값이 바뀐다면) / 값 결정은 **사용자·product-planner**

## 5. 좋았던 점 — **지켜야 할 것들**

고칠 것만 적으면 다음 사람이 **잘 돼 있던 것을 모르고 부순다.** 아래는 실제로 눌러 보고 좋았던 것들이다.

**① 자료실의 "0건" 처리는 이 제품에서 가장 잘 된 화면이다** — 다른 화면의 기준으로 삼을 만하다.
- 무엇 때문에 0건인지 **되읽어 준다**: `검색 "zzzzzz" ✕` 칩 + `총 1,350자 중 0자`
- **탭마다 다른 힌트**를 준다 — 한자: "글자·훈음·음독·훈독 중 다른 것으로", 어휘: "한자 대신 읽는 법(たてもの)이나 한국어 뜻으로도", 문법: "물결표(〜) 없이 てから처럼"
- 다음 행동을 준다: **[검색·필터 초기화]**
- 결과가 1건일 때 [이 조건으로 문제 풀기] 옆에 "**문제를 내려면 4개 이상 필요해요. 조건을 넓혀 보세요**" — 버튼을 없애지 않고 **이유를 말한 뒤** 막는다.

**② 되돌릴 수 없는 조작에 경고가 제대로 붙어 있다.**
- 학습 기록 초기화: "완료한 **1개** 유닛 기록을 지울까요? / 완료 표시와 이어보기 위치가 지워져요. **보관함은 그대로 남습니다.** 되돌릴 수 없어요." — **지워지는 것과 남는 것을 갈라 말한다.**
- 탈퇴: 지워지는 것(학습 기록)과 **남는 것**(커뮤니티 글 2개·댓글 2개 → '탈퇴한 회원')을 나눠 보여주고, "먼저 지우고 싶다면 **[내가 쓴 글 찾기]**"까지 준다. + "같은 아이디로 다시 가입할 수 없어요" + 비밀번호 확인 + 체크박스.

**③ 비로그인 → 로그인 합치기가 정직하다.**
"이 브라우저에 저장된 학습 기록이 있어요 — **완료 2유닛 · 보관함 3개** / 내 계정으로 가져올까요?
**다른 사람이 쓰던 기록이면 [내 기록 아니에요]를 눌러 주세요.**" → [합치기] 뒤 "**합쳤어요 — 완료 3유닛 · 보관함 3개**".
자동 병합하지 않고, **남의 기기 시나리오까지** 배려하고, **결과를 수치로** 알려준다.

**④ 없는 것을 사과하지 않는다(C-12 ①)가 실제로 지켜지고 있다.**
입문 코스 상세의 집계 줄은 `유닛 10 · 문법 20 · 어휘 약 150개` — **"한자 0자"를 그리지 않는다.**
한자 자료실 레벨 칩에도 입문이 없다. 입문 유닛 학습에는 한자 스텝 자체가 없다(스텝 6개).

**⑤ 학습 화면의 오류·로딩이 안정적이다.**
없는 코스/유닛/한자는 전부 **[다시 시도] 없이** 404 카드 + 나갈 길 두 개([코스 목록으로]/[홈으로], [자료실로]/[홈으로]).
목록·상세·유닛 학습 모두 **스켈레톤**이라 데이터가 들어와도 레이아웃이 튀지 않는다.
자료실 목록은 페이지 전환 중에도 **이전 목록을 유지**(`list-loading`)해 화면이 비지 않는다.

**⑥ 영어 준비중 코스 상세가 모범적이다.**
"🚧 아직 준비중인 코스예요 / 일상 말하기 코스는 지금 만들고 있어요. / **지금은 다시 세우기 코스를 시작할 수 있어요 →** / 영어 코스 목록으로"
— 없는 것을 알리되 **갈 수 있는 곳을 같이 준다.**

**⑦ 자료실 상세의 "어디서 배우나"가 학습으로 되돌려 준다.**
한자 상세 아래 "왕초보(N5) 코스 · 유닛 1 저는 ○○입니다 / **[이 유닛에서 배우기 ›]**" —
부록(자료실)에서 본류(코스)로 돌아오는 길이 있다. 자료실이 막다른 길이 아니다.

**⑧ 로그인 실패·잠금 문구가 다음 행동을 말한다.**
"아이디 또는 비밀번호가 일치하지 않습니다." / (5회 초과 시) "로그인 시도가 너무 많아요. **15분 뒤에** 다시 시도할 수 있어요."
— "잠시 후"로 뭉개지 않는다.

**⑨ 서버 API가 경계값에서 흔들리지 않는다.** (curl 직접 확인)
없는 코스·유닛·음수·0·문자 id → 전부 적절한 404/400 + `errorCode` 구분. 완료 토글 **동시 3연타 → 전부 200, 결과 1건**(멱등).
준비중 코스 완료 시도 → `COURSE_PREPARING`. `stepKey` 형식 위반 → 필드 단위 `VALIDATION_ERROR`.

## 7. 확인 못 한 것 — **"통과"가 아니다**

| 항목 | 왜 못 했나 |
|---|---|
| **실기기·실브라우저 렌더** | 이 점검은 jsdom에 실제 페이지를 렌더해 **살아 있는 API**로 확인했다. DOM·데이터·분기는 진짜지만 **레이아웃·스크롤·모바일 햄버거·다크모드는 화면으로만 확인 가능**하다 |
| **음성(TTS)** | jsdom에 `speechSynthesis`가 없다. 재생·정지·속도·화면 이탈 시 취소는 **브라우저에서 사람이** 확인해야 한다 |
| **두 탭 동시 조작** | 서버 PUT이 멱등이라 데이터는 안전한 것을 확인했지만, **두 탭의 화면이 서로 어긋난 상태로 남는지**는 실제 브라우저 두 개로 봐야 한다 |
| **파일 업로드(커뮤니티 첨부)** | 10MB/50MB 한도와 413 문구는 실제 파일로 확인해야 한다 |
| **소셜 로그인(카카오·구글)** | 외부 서비스 왕복이라 로컬에서 확인 불가 |
| **느린 네트워크에서의 연타** | 지연 주입 수단이 없었다. 버튼 중복 클릭 방지(`loading` 잠금)는 코드에 있으나 **체감 확인은 못 했다** |
| **자료실 퀴즈 전체 흐름** | **D-1 때문에 한자·문법 퀴즈에 도달 자체가 불가능**했다. 고친 뒤 다시 봐야 한다 |

## 8. 다시 볼 때 순서

1. **D-1**(자료실 퀴즈 라우트) — 고치고 나면 **자료실 퀴즈 전체 흐름을 처음부터** 다시 본다.
2. **D-2·D-3** — "이어서"의 정의와 스텝 동선은 **사람이 정해야** 하는 문제다. 정한 뒤 구현·재확인.
3. **D-9** — 비밀번호 최소 길이를 지금 확정한다(운영 계정 0개인 지금이 가장 싸다).
4. 나머지는 디자인 교체(Halo → Lets) 작업과 함께 처리해도 된다 — **다만 D-5(커뮤니티 문구)는 문구 문제라 디자인 교체로 저절로 고쳐지지 않는다.**

> **점검 중 만든 데이터는 되돌려 놨다**: `user4`의 진도·보관함은 점검 전 상태(0건)로 초기화했고,
> 확인용으로 만든 계정 하나는 탈퇴시켰다. 프로젝트 파일은 이 문서 외에 **아무것도 고치지 않았다.**
