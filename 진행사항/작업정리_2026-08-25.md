## 7. 운영할 때 주의할 것

### ⚠️ 배포 전 필수 — 콘텐츠는 자동으로 안 들어갑니다

운영 서버는 시드 SQL을 자동 실행하지 않습니다. **적재하지 않고 배포하면 사이트는 뜨는데 코스 목록이 텅 빕니다.**
첫 배포 후 아래 **15개 파일을 순서대로** 운영 DB에 한 번 실행해야 합니다.

```
data-courses.sql
data-course-content.sql        data-course-units.sql         (N5)
data-course-n4-content.sql     data-course-n4-units.sql
data-course-n3-content.sql     data-course-n3-units.sql
data-course-n2-content.sql     data-course-n2-units.sql
data-course-intro-content.sql  data-course-intro-units.sql   ← 입문
data-course-n1-content.sql     data-course-n1-units.sql      ← N1
data-course-en-content.sql     data-course-en-units.sql      ← 영어
```

- `*-content.sql`이 반드시 같은 코스의 `*-units.sql`보다 **먼저**입니다.
- `data-h2-reset-identity.sql`은 **실행하면 안 됩니다** — 로컬 전용입니다.
- `설계/07_운영_배포.md` §1의 목록은 **2026-08-25에 같은 15개로 고쳤습니다**(그 전에는 N5~N2 8개만 적혀 있었습니다). 단일 기준은 `application.yml`의 `sql.init.data-locations`입니다.

### 로컬 개발

- 화면을 고치면서 볼 때는 `npm run dev`(5173)를 씁니다.
- 서버(`bootRun`)로 프론트 변경을 확인하려면 **먼저 `gradlew copyFrontendBuild`**를 한 번 실행해야 합니다.
- 로컬은 **편집 모드가 기본 켜짐**입니다. 운영에서는 자동으로 꺼지고, 억지로 켜면 기동이 거부됩니다.

### 그 밖에

- **사이트명 `日本語 학습`은 정식명으로 확정**됐지만, 코드 주석에는 아직 "미확정"으로 남아 있습니다. 이름을 바꾸려면 `frontend/src/constants/site.js`와 `frontend/index.html`의 `<title>` 두 곳입니다.
- 커뮤니티 **첨부파일은 로그인 없이 열람 가능**합니다(공개 게시판이므로 의도된 동작). 업로드·삭제는 로그인 + 본인 확인이 걸려 있습니다.
- 콘텐츠를 고칠 때는 **로컬 시드 SQL과 운영 DB를 함께** 고쳐야 합니다. 관리자 화면이 없으므로 이것이 유일한 경로입니다.

### 가장 심각했던 것 — 운영에 인증 없는 H2 콘솔

세 조건이 겹쳐 있었다: `runtimeOnly h2`로 **운영 jar에 H2가 실리고**, 기본 설정의 `console.enabled: true`를 **prod가 덮지 않고**, 보안설정이 `/h2-console/**`를 **permitAll**. 콘솔은 접속자가 **임의 JDBC URL**을 넣을 수 있어 RCE 경로다.

설정 한 줄로 끄지 않고 **세 겹**으로 막았다(편집 모드와 동일한 자세): prod 명시 비활성 · 켜진 채 prod면 **기동 거부** · 콘솔이 켜졌을 때만 보안 규칙 등록. **로컬 `/h2-console`은 그대로 열린다**(가드 테스트로 고정). 배포 전이라 노출은 없었다.

### 인증

| # | 문제 | 처리 |
|---|---|---|
| jti 부재 | 같은 초 발급 토큰이 **바이트 단위로 동일** → 비밀번호를 바꿔도 옛 리프레시가 **되살아남** | `jti` 도입. 이걸 고치자 "옛 리프레시 폐기" 건도 구현 변경 없이 해결 |
| `tv` 관대 기본값 | 없으면 0으로 간주 | **-1**(실제 값과 절대 불일치)로. 근거: 배포 0회 = 호환 대상 0개 |
| 시도 제한 없음 | 15회 실패 후에도 즉시 통과 | 5회/15분. **비밀번호 대조 전** 검사, **잠긴 요청은 실패로 세지 않음**(차단 자가연장 방지). 라이브러리 도입 0 |
| `username` 노출 | 비로그인 `GET /api/communities`가 **로그인 아이디**를 통째로 반환 | 응답에서 제거. 소유자 판정은 `userId` |

> ⚠️ **비밀번호 4자 규칙은 건드리지 않았다** — 사용자가 의도한 결정(시드 테스트 계정용, 실사용자는 소셜 로그인).

### 회귀를 하나 만들고 잡았다

`jti`가 붙어 토큰이 258자가 되면서 `refresh_entity.token`(255)을 넘겨 **로그인이 500으로 터졌다.** 인증 8건이 동시에 깨져 즉시 드러났고 컬럼을 512로 늘렸다. 테스트가 없었으면 배포 후 "로그인이 안 된다"로 발견될 종류다.

### 화면

- **영어 GNB가 일본어로 데려갔다** — `NAV_ITEMS` 하드코딩. 영어 자료실에서 "자료실"을 누르면 한자 1,350자 목록으로 갔고 활성 표시도 안 켜졌다
- **영어 유닛에서 퀴즈·음성 제거** — 화면정의서와 테스트가 정면 충돌했고 **문서가 이겼다**. 켜져 있는 동안 영어 유닛이 **일본어 조판·ja 음성**으로 렌더되고 있었다
- **자료실 퀴즈가 50% 확률로 안 열렸다** — 무작위 창 뽑기(편향 회피)는 옳고 **꼬리 창(4건 미만)만** 걸러 해결
- **`username` 제거의 여파** — 소유자 판정이 `undefined === undefined`가 되어 **전원에게 남의 글 수정·삭제 버튼**이 뜰 뻔했다. `userId` 기반으로 고치고 회귀 테스트 신설
- **첨부 실패 시 "작성 실패"** — 본문은 저장됐는데 실패라 말해 사용자를 **중복 글 작성으로 유도**했다(서버에 중복 방지 없음)

### 문서가 코드와 어긋난 것

`설계/03`이 **"레벨 컬럼은 없다, `course_no`에서 파생한다"**고 말하고 있었다 — 코드와 정반대이고, 이대로 시드를 쓰면 INSERT가 실패한다. 반전 이유까지 본문에 박았다: **언어가 둘이 되면 `course_no → level`이 함수가 아니다**(일본어 1=N5, 영어 1=E1). `course_no` 단독 UNIQUE도 복합 `UNIQUE(language, course_no)`로 정정. `설계/04`에는 누락 엔드포인트 18개를 채웠다.

### 새 규칙 (설계/08)

- **C-15 유일성은 시각이 아니라 식별자로 보장한다** — 곁가지: JWT 저장 컬럼은 512 이상(넘치면 기능이 아니라 **인증 전체**가 죽는다)
- **C-16 관대한 기본값에는 유효기간을 함께 정한다** — 대상과 폐기 조건을 못 적으면 호환이 아니라 **검증을 건너뛰는 구멍**이다
- **B-11 보강** — 동시성 방어를 둘로: 예방(행 잠금)은 사용자 데이터, 번역(제약 위반 → 409)은 그 밖
- **D-3** 리프레시 회전 × 비밀번호 변경 경합은 **감수한 위험**(재검토 조건 명시)
- **F-11 정정** — 결론은 맞았고 **근거가 틀렸다**

### 다음 감사를 위해

이번 라운드에 **"문서가 맞고 코드가 어긋난 채 테스트가 코드 쪽을 고정하고 있던"** 유형이 셋이었다(영어 퀴즈·F-11·진단 추천).

### 사용자 결정 대기

**운영에서 로컬 회원가입을 닫고 소셜 로그인만 허용할지** — 약한 비밀번호 계정이 운영에 생기는 것을 원천 차단하는 유일한 방법이고 기술적으로는 프로파일 한 줄이지만, **가입 수단을 없애는 것은 기획 결정**이다.
