## 0. 무엇이 바뀌나 (한 문단)

사용자 요구: *"처음부터 입문⇒N1 가는 게 귀찮다. 입문~N1 중 고를 수 있게 하고, 통과하면 '이 레벨은 충분합니다. 다음 레벨에 도전해보세요' 떴으면 좋겠다."*
→ **계단(입문부터 자동으로 올라감)이 사라진다.** 레벨을 고르고 → 그 레벨 6문항을 풀고 → **통과든 미달이든 결과 화면에서 멈춘다.**
이어서 할지는 결과 화면에서 **사용자가 고른다.** 여러 판을 치면 판정표에 기록이 쌓인다.

함께 들어온 요구: *"테스트별로 문법, 어법, 단어어휘가 잘 나뉘어져 있으면 좋겠어."*
→ 레벨 화면의 6문항을 **갈래(단어·문법·문장)로 묶어** 보여준다. 순서는 이미 고정이었고(09 §3-3), **없던 것은 구분**이다.

**화면은 넷 + 로딩**: 시작(레벨 선택) · 레벨 화면 · 결과(통과/미달) · 실패 카드 (+ 스켈레톤).
넷 다 `.diag-wrap > .quiz-card` **한 장**이다. 판과 판 사이에 중간 화면은 없다.

## 1. 와이어프레임

### 1-1. 시작 화면 — 어느 레벨부터 볼지 고른다

```
.diag-wrap > .quiz-card

  실력 진단                                         ← .step-caption (3단 라벨)
  어디서 시작할지 알아볼까요                           ← .step-title (1단)

  한 레벨에 6문항, 한 화면에서 한 번에 제출해요.          ┐ 2단 — 읽으라고 있는 글
  통과하면 그다음 레벨에 도전할 수 있어요.               │ 기본 <p> (--t-md · --text)
  어느 레벨인지 모르겠으면 그대로 시작하세요.            ┘  (문구는 기획서를 따른다)

  ┌ .diag-levels (fieldset — 면 없음, 테두리 없음) ─────────┐
  │ 어느 레벨부터 볼까요       ← legend, 3단 라벨            │
  │ ◉ 입문(문자)             ← .quiz-choices > .quiz-choice │
  │ ◯ 왕초보(JLPT N5)           (라벨 + type="radio")       │
  │ ◯ 초급(JLPT N4)     통과  ← 이미 친 레벨만 .diag-level-mark│
  │ ◯ 중급(JLPT N3)                                        │
  │ ◯ 중상급(JLPT N2)                                       │
  │ ◯ 고급(JLPT N1)                                         │
  └────────────────────────────────────────────────┘

  결과는 저장되지 않아요.                             ← .quiz-note (--t-sm · --muted)

  [ 시작하기 ]                                      ← .quiz-result-actions · .k-btn--primary, 화면에 하나
```

- 목록은 `stagePlan`이 준 **입장 가능한 레벨만**(1~6줄, 가변). 준비중 레벨 줄은 **만들지 않는다.**
- 한 줄의 글은 **`{title}({levelLabel})`** — 둘 다 API 값. 코드(`N5`)를 노출하지 않는다.
- **기본 선택 = 목록의 첫 줄.** 아무것도 안 고른 상태가 없으므로 [시작하기]가 `disabled`가 되는 일이 없다.
- 이미 친 레벨만 줄 오른쪽 끝에 판정 낱말(`.diag-level-mark`). 이미 친 레벨도 **다시 고를 수 있다**(잠그지 않는다).

### 1-2. 레벨 화면 — 6문항이 한 화면에, 갈래로 묶여서

```
.diag-wrap > .quiz-card   (640px 중앙, 회색 면 — 카드는 한 장이다)

  초급(JLPT N4) · 6문항                  ← .quiz-progress (--t-sm --muted, tabular-nums)

  단어·어휘                              ← .diag-group-title (--t-md · --w-bold · --text)
  ┌ .diag-question (fieldset — 면 없음, 테두리 없음) ─────┐
  │ 1. 이 단어의 뜻은?        ← legend, 3단 라벨           │
  │ 学生                     ← .quiz-prompt.jp, 1단       │
  │ がくせい                 ← .quiz-prompt-sub.jp        │  ※ kana 줄은 N4·N3에서만.
  │ ◯ 학생                   ← .quiz-choices > .quiz-choice │    N5면 지문이 「がくせい」 한 줄이다
  │ ◯ 선생님                                             │
  │ ◯ 회사원                                             │
  │ ◯ 친구                                               │
  │ ─────────────────  ← 구분선 1px --border (마지막 보기 위) │
  │ ◯ 모르겠어요             ← 언제나 맨 아래              │
  └──────────────────────────────────────────────┘
        ↕ --sp-6 여백만 — **같은 갈래 안에는 선이 없다**
  (2번 · 3번 문항, 같은 모양)

  ────────────────────────────────────  ← **갈래 사이에만** 1px --border (위아래 --sp-8)
  문법
  (4번 · 5번 문항)

  ────────────────────────────────────
  문장
  (6번 문항)

  아직 2문항을 고르지 않았어요 — 그대로 제출하면 모름으로 처리돼요.   ← .quiz-note, 미응답 0이면 줄 자체가 없음

  [ 제출하고 결과 보기 › ]               ← .quiz-result-actions, 버튼 하나
```

- **제출 버튼 라벨은 하나다** — `제출하고 결과 보기 ›`. *"제출하고 다음 단계로 ›"* 분기는 폐기.
- **문항 번호는 전체 통번호 1~6.** 갈래마다 1로 되돌리지 않는다.
- **갈래가 0문항이면 제목째 렌더링하지 않는다.** N2·N1은 갈래 2개가 정상이다.
- 갈래 선은 **렌더된 갈래 사이에만** 생긴다(`+` 인접 선택자라 첫 갈래 위에 뜨지 않는다).

### 1-3. 결과 화면 — 한 화면, 두 변형

```
.diag-wrap > .quiz-card        ── 통과 ──────────────────────────

  진단 결과                                        ← .step-caption
  이 레벨은 충분해요                                 ← .diag-headline — 화면에서 가장 큰 글자
  중상급(JLPT N2) 문항을 5 / 6 맞혔어요.               ← 본문 한 줄 (판이 1개일 때 = 표 대신)

  [ 다음 레벨 도전하기 › ]  [ 중상급(JLPT N2) 코스로 시작하기 ]  [ 다시 진단하기 ]
  이 결과는 저장되지 않아요. 새로고침하면 사라져요.    ← .quiz-note


.diag-wrap > .quiz-card        ── 미달 ──────────────────────────

  진단 결과                                        ← .step-caption
  여기는 아직 새로운 게 많아요                        ← .diag-headline
  중상급(JLPT N2) 문항을 2 / 6 맞혔어요.

  ┌ 레벨 │ 정답 수 / 문항 수 │ 판정 ┐             ← 두 판째부터. 친 판만 행, 레벨 순
  │ 중급(JLPT N3)  │  5 / 6  │ 통과 │
  │ 중상급(JLPT N2)│  2 / 6  │ 미달 │
  └───────────────────────────┘

  [ 초급(JLPT N4) 코스 시작하기 › ]  [ 한 단계 아래로 해보기 ]  [ 다시 진단하기 ]
  이 결과는 저장되지 않아요. 새로고침하면 사라져요.
```

**버튼 배치** — 어느 변형에서도 **primary는 하나**다(근거는 05 §15-2).

| 변형 | primary | secondary | ghost |
|---|---|---|---|
| **통과** | **[다음 레벨 도전하기 ›]** | [{이 레벨} 코스로 시작하기] | [다시 진단하기] |
| **미달** | **[{추천 코스} 시작하기 ›]** | [한 단계 아래로 해보기] | [다시 진단하기] |

- 순서는 primary → secondary → ghost 고정. ≤768px에서 셋이 세로 100%로 쌓인다(`.quiz-result-actions` 기존 규칙).
- **버튼이 하나 빠지면 다음 순위가 primary를 물려받는다.** 버튼이 둘이 되는 것이지 primary가 둘이 되지 않는다.
- ~~**판이 1개면 판정표를 그리지 않는다.** 두 판째부터 표가 생기고 **그 순간 위의 본문 한 줄은 사라진다.**~~
  → ⚠️ **폐기(2026-09-15 senior-dev 판정)**: **행이 하나여도 표를 그린다**(기획 D12 · A32 · 09 §3-7). 기획이 확정한 결과 문구(§14-3)에는
  *"n / 총 맞혔어요"* 줄이 없어서, 첫 판에서 표를 빼면 **정답 수가 화면 어디에도 남지 않는다**(A19의 네 가지 사실 위반).
  위 와이어프레임의 "본문 한 줄 (판이 1개일 때 = 표 대신)"과 "두 판째부터" 주석도 같은 이유로 낡았다.
- 표는 **레벨 순(낮은 것 → 높은 것)**, 같은 레벨 재도전은 행을 늘리지 않고 **최근 결과로 덮는다.**
- 판정 열은 **낱말**이다(통과/미달 둘 다). 색·배지를 쓰지 않는다. 최종 낱말은 기획이 정한다(§6).

### 1-4. 실패 카드 (재료 부족 · 호출 실패 공용)

```
.diag-wrap > .quiz-card

  실력 진단                                        ← .step-caption
  문제를 준비하지 못했어요.

  [ 일단 {첫 코스}부터 시작하기 › ]  [ 다른 레벨 고르기 ]  [ 다시 시도 ]
```

- `--err` 면·아이콘을 **깔지 않는다** — 사용자가 뭘 잘못한 게 아니다.
- primary는 **언제나 학습으로 나가는 버튼**이다(다시 눌러도 같은 곳에 머무를 수 있는 버튼을 주 버튼으로 두지 않는다).
- `[다른 레벨 고르기]`가 `[다시 시도]`보다 위인 이유: **재료 사정이 레벨마다 다르므로** 성공 확률이 높다.
- **판정표를 얹지 않는다.** 기록은 사라지지 않는다 — `[다른 레벨 고르기]`로 돌아가면 시작 화면 목록의 판정 표시가 그대로 있다.

## 2. 상태별 UI — 빠뜨리면 안 되는 것들

| 상황 | 화면 |
|---|---|
| **코스 목록 로딩 중** | `.diag-wrap` 카드 한 장 + `.k-skeleton` 줄 2개, `<section aria-hidden="true">`. 현행 그대로 |
| **코스 목록을 못 부름** | 진단 화면을 그리지 않고 기성 `ApiErrorCard`(05 §8) — 레벨 목록을 만들 재료가 없다 |
| **입장 가능한 레벨이 0개** | 시작 화면을 그리지 않고 **실패 카드**. 코스가 하나도 없으면 그 카드에 **[다시 시도]만** 남는다(primary가 될 코스가 없다) |
| **문항 준비 중**(레벨을 고르고 [시작하기]를 누른 뒤) | 카드 한 장 + `.k-skeleton` 줄 3개(`sk-line w40` · `sk-line w70` · `sk-row`), `aria-hidden`. **시작 화면 자리를 그대로 갈아끼운다** — 화면 전환이라 05 §8의 "갱신 로딩은 흐리게"가 아니라 스켈레톤이다 |
| 고른 레벨이 **3~5문항**만 만들어짐 | **평소와 똑같은 레벨 화면.** 문항이 그 수만큼 서고 진행 줄이 *"· 4문항"* 이라 말한다. **사과 문구·경고 띠 없음** — 사용자가 모르는 사정을 굳이 알리면 제품이 고장 난 것처럼 보인다. 갈래가 비면 그 갈래는 제목째 없다 |
| 고른 레벨이 **3문항 미만**(= 문제 준비 실패) | **실패 카드**(§1-4) |
| **호출 실패**(네트워크·5xx) | **같은 실패 카드.** 문구도 같다 |
| **통과 + 더 올라갈 레벨이 없음**(가장 높은 레벨 통과) | 통과 변형에서 **[다음 레벨 도전하기]가 미렌더**되고 **[이 코스로 시작하기]가 primary를 물려받는다.** 버튼 2개(primary + ghost). 준비중 코스가 **실제로 있을 때만** *"그 위 코스는 지금 준비하고 있어요"*(`.muted-text`) 한 줄. 축하 연출·오렌지 배지를 새로 만들지 않는다 |
| **미달 + 더 내려갈 레벨이 없음**(가장 낮은 레벨 미달) | 미달 변형에서 **[한 단계 아래로 해보기]가 미렌더**. 버튼 2개(primary [첫 코스 시작하기] + ghost). 머리글은 *"여기부터 시작하면 돼요"* 쪽 톤 — **가장 낮은 레벨 미달은 진단의 정상적인 결론이다**(문구는 기획) |
| **모든 문항 미응답으로 제출** | 막지 않는다. 미달 결과 화면이 정상적으로 뜬다 — 확인 모달·경고 없음 |
| **빈 갈래**(N2·N1의 문장 / 재료 부족) | 그 갈래 블록을 **통째로 미렌더.** 제목만 덩그러니 남기지 않는다. "0문항"·"이 레벨에는 문장 문항이 없어요"를 만들지 않는다 |
| **갈래가 1개만 남음** | 그래도 **제목은 그린다.** 제목은 구분 장치가 아니라 이름표이고, 화면 구조가 레벨마다 달라지지 않는 편이 낫다 |

**한 판 모델에서 사라진 분기 (⚠️ 구현 시 주의)**

- **"첫 단계 / 2단계 이후" 구분이 없다.** 판마다 독립이므로 **문항을 못 만들면 언제나 실패 카드**다.
  앞 판의 기록이 있어도 결과 화면으로 넘기지 않는다 — 이 판은 판정이 없다.
- 폐기 문구: *"{레벨} 단계는 문제를 준비하지 못해 여기까지로 판단했어요."*
- **제출 → 결과 사이에 로딩이 없다.** 채점이 로컬이고 다음 문항을 부르지 않는다.
- **[다시 진단하기]는 시작 화면으로 돌아가되 판정표 기록은 유지한다.** 기록을 지우는 길은 새로고침뿐이고,
  그 사실은 *"이 결과는 저장되지 않아요"* 한 줄이 이미 말한다 — 초기화 버튼을 새로 만들지 않는다.
- 모든 갈래에서 **상단 안내 띠는 한 번에 하나**다.

## 3. 탈락 시안 — 다시 제안하지 말 것

### 3-1. 레벨 선택의 형태

| 탈락 형태 | 왜 안 되나 |
|---|---|
| 셀렉트(`.k-select`) | 6개가 **접혀 있어** 무엇을 고를 수 있는지 안 보인다. 열고 → 스크롤하고 → 고르는 3동작이라 **고르는 수고가 늘어난다** |
| 2열 카드 그리드 | 읽는 순서가 Z자로 꺾여 **"낮은 것 → 높은 것"이라는 유일한 정보가 사라진다.** 줄도 어긋난다(05 §19-5) |
| 6개 버튼(누르는 즉시 시작) | 진단은 한 주소 안의 상태 전환이라 레벨 화면에서 **뒤로 갈 곳이 없다** — 오조작을 새로고침으로만 되돌리게 된다. 또 05 §3-2(화면당 primary 1개)를 깬다 |
| 레벨 목록을 회색 면으로 묶기 | 면 계층이 이미 셋이라 **흰 알약이 묻힌다**(05 §19-7). 근거는 아래 3-3 |

**채택**: 세로 알약 스택(`.quiz-choices`/`.quiz-choice` + 라디오) + 기본 선택 + [시작하기] primary.
비용은 탭 두 번이고, 이 개편이 없애려는 수고는 *"30문항을 먼저 푸는 것"* 이지 탭 한 번이 아니다.

### 3-2. 갈래 구분의 수단

| 탈락 | 왜 안 되나 |
|---|---|
| 문항 선 **유지** + 갈래 선 **추가** | 같은 굵기 1px 선이 두 겹이라 **묶음이 안 읽힌다.** 한 화면에 선이 7개가 된다 |
| 갈래 선만 `--border-strong`으로 굵게 | 640px 한 단에 굵기가 다른 선이 섞이면 **표처럼 보인다**(05 §13 "고밀도 관리자 표" 회피) |
| 선 없이 여백 차이만(`--sp-6` vs `--sp-10`) | 스크롤하며 읽을 때 경계가 흐려진다. 선은 "있다/없다"라 **굵기 차보다 강한 신호**다 |
| 갈래마다 아이콘·색·번호 원판 | 05 §19-4 — 강조 수단은 하나. 코스 목록에서 이미 뺀 장식이다 |

**채택**: 구분 장치를 **더하지 않고 옮겼다.** 같은 갈래 안 문항 사이 = 여백만, 갈래 사이 = 선 + 큰 여백 + 제목.
선이 5개 → 2개로 줄고, 남은 선의 뜻은 하나다: *"여기서 갈래가 바뀐다."*

### 3-3. 갈래·레벨 목록을 면으로 묶기 (⚠️ 가장 하고 싶어지는 일)

면 계층이 이미 **세 겹**이다 — 페이지 `--bg`(흰) → 카드 `--card-bg`=`--surface-alt`(회색) → 보기 알약 `--surface-inset`(카드 안에서 `--surface` = 흰).
네 번째 면은 **카드와 알약 사이**에 끼어야 하는데:

- 쓸 수 있는 값이 `--surface-hover`(#eef0f9)·`--bg-sunken`(#f2f3fb)뿐이고, 둘 다 `--surface-alt`(#f5f6fa)와 **눈으로 구별되지 않으면서**
  그 위에 얹힌 **흰 알약의 대비만 깎는다.** 얻는 것 없이 잃기만 한다(05 §19-7 조용한 실종).
- `--point-soft`는 **"고른 것"이라는 뜻을 이미 갖고 있다**(05 §19-3 — 면 색은 역할당 하나씩).
- 결정적으로 `--surface-inset`은 **상속으로 계산되는 토큰**이다(05 §19-7-1). 중간에 면을 끼우면 그 안 알약 **30개(6×5)** 를 직접 다시 칠해야 하고,
  그 순간 면 계층이 구조에서 절차로 되돌아간다.

### 3-4. 결과 화면의 통과/미달 표현

| 탈락 | 왜 안 되나 |
|---|---|
| 통과 `--ok` / 미달 `--err`·`--warn` 글자색·면 | ① 05 §2 — 의미색은 **상태 표시용**이고 여기는 상태가 아니라 **다음 행동의 근거**다 ② 통과를 초록으로 칠하는 순간 미달이 자동으로 빨강의 자리를 갖는다 — **진단이지 시험이 아니다** ③ `.diag-headline`은 §19-2의 1단이고 1단의 색은 `--text`다 |
| 통과 시 폭죽·체크마크·일러스트 | 진단은 머무는 곳이 아니라 지나가는 문이다. 연출은 방을 만든다 |
| 갈래별 정답 수·정답률 열 | 2~3문항짜리 갈래 점수는 사실상 **문항별 정오 노출**이고(09 §3-1 위반), 판정에 쓰지 않는 숫자를 화면에 두지 않는다(05 §19-6) |
| ~~판 1개인데 1행 판정표~~ | ~~머리글이 이미 레벨·판정을 말했다 — 같은 말 두 번(05 §19-6)~~ → ⚠️ **뒤집힘(2026-09-15)**: 머리글은 판정만 말하고 **정답 수는 표에만 있다**(확정 문구 §14-3). 표를 빼면 같은 말 두 번이 아니라 **한 번도 안 하는 것**이 된다 → A32대로 한 행도 그린다 |

### 4-2. 새로 필요한 것 — 새 클래스 4개 + 기존 규칙 1줄 수정

새 클래스: `.diag-levels` · `.diag-level-mark` · `.diag-group` · `.diag-group-title`

**① `.diag-levels`** — 시작 화면의 레벨 선택 `<fieldset>`. **값을 새로 쓰지 않는다.**
`.diag-question`이 이미 가진 라벨형 보기 규칙의 **선택자 목록에 `.diag-levels`를 더한다**(6개 규칙):

```css
.diag-question, .diag-levels { border: 0; margin: 0; padding: 0; min-width: 0; }
.diag-question > legend, .diag-levels > legend { /* 기존 3단 라벨 값 그대로 */ }
.diag-question .quiz-choice, .diag-levels .quiz-choice { display:flex; align-items:center; gap:var(--sp-3); }
.diag-question .quiz-choice input[type="radio"],
.diag-levels   .quiz-choice input[type="radio"] { flex:0 0 auto; margin:0; accent-color:var(--point); }
.diag-question .quiz-choice:hover, .diag-levels .quiz-choice:hover { box-shadow:none; }
.diag-question .quiz-choice:focus-within, .diag-levels .quiz-choice:focus-within { box-shadow:var(--sh-point); }
.diag-question .quiz-choice:has(input:checked),
.diag-levels   .quiz-choice:has(input:checked) { background:var(--point-soft); }

/* 안내 문단과 목록 사이 숨 — 이 클래스가 새로 갖는 유일한 값이다.
   ⚠️ 위 리셋(margin:0)과 특이도가 같으므로 **반드시 뒤에 둔다** — 순서를 바꾸면 조용히 사라진다 */
.diag-levels { margin-top: var(--sp-5); }
```

**② `.diag-level-mark`** — 이미 친 레벨 줄의 판정 한 낱말. **알약 안 오른쪽 끝, 3단 라벨.**

```css
.diag-levels .quiz-choice > .diag-level-mark {
  margin-left: auto;            /* 알약이 이미 flex다 — 오른쪽 끝으로 */
  font-size: var(--t-sm);       /* 알약 본문(--t-md)보다 한 급 아래 */
  color: var(--muted);          /* 05 §19-2 보조 텍스트 최소선. --muted2 금지 */
}
```

굵기는 지정하지 않는다 — 알약의 `--w-bold`를 그대로 상속받는 3단 라벨이다. **면·배지·의미색을 쓰지 않는다.**

**③ `.diag-group` / `.diag-group-title`** — 레벨 화면의 갈래 묶음.

```css
/* 갈래 사이에만 선이 있다. 첫 갈래 위에는 없다 — 빈 갈래를 미렌더해도 선이 뜨지 않는다 */
.diag-group + .diag-group {
  margin-top: var(--sp-8);
  padding-top: var(--sp-8);
  border-top: var(--bw) solid var(--border);
}
/* legend(--t-sm·--muted)와 지문(--t-xl) 사이 — 크기·명도 두 축으로 갈린다 */
.diag-group-title {
  margin: 0 0 var(--sp-3);
  font-size: var(--t-md);
  font-weight: var(--w-bold);
  color: var(--text);
}
```

**④ 기존 규칙 1줄 수정** — 문항 사이에서 **선을 뺀다**(선은 갈래 사이로 옮겨 갔다):

```css
/* before */  .diag-question + .diag-question { margin-top:var(--sp-6); padding-top:var(--sp-6); border-top:var(--bw) solid var(--border); }
/* after  */  .diag-question + .diag-question { margin-top: var(--sp-6); }
```

**새 미디어쿼리는 없다.** 640px 한 단이라 ≤768px에서도 배치가 같고, 버튼 줄의 기존 `.quiz-result-actions` 규칙이 세 버튼을 알아서 세로로 세운다.

### 4-3. ⚠️ 함정 세 개 — 여기서 조용히 깨진다

1. **`.diag-levels`를 [모르겠어요] 구분선 규칙에 더하지 마라.**
   `.diag-question .quiz-choices > .quiz-choice:last-child(::before)`에 `.diag-levels`를 더하면
   **마지막 레벨(고급 N1) 위에 선이 그어진다.** 같은 클래스를 세 화면이 공유할 때의 기본 실수다.
   같은 이유로 `.diag-question + .diag-question` 여백 규칙에도 더하지 않는다(레벨 목록은 fieldset이 한 장뿐이다).
2. **선택자를 `.quiz-choice:has(input[type="radio"])`로 일반화하지 마라.**
   특이도가 (0,2,0) → (0,2,1)로 올라가 **유닛 확인 문제·자료실 퀴즈 쪽 버튼 규칙과의 우선순위가 조용히 뒤집힌다**(05 §19-7-2와 같은 계열).
   화면 전용 규칙은 화면 전용 클래스 안에 둔다.
3. **`.diag-levels { margin-top }`은 리셋(`margin:0`)보다 뒤에 둬라.**
   특이도가 같으므로 순서가 이긴다. 앞에 두면 여백이 조용히 사라진다.

### 4-4. 마크업 요약 (요소 선택)

| 블록 | 요소 |
|---|---|
| 레벨 선택 | `<fieldset class="diag-levels">` + `<legend>` + `<div class="quiz-choices">` + `<label class="quiz-choice"><input type="radio" name="diag-level">…</label>` |
| 이미 친 레벨 표시 | 라벨 안 마지막 자식 `<span class="diag-level-mark">` |
| 갈래 묶음 | `<section class="diag-group">` + `<h2 class="diag-group-title">` — **중첩 `<fieldset>`으로 만들지 않는다**(문항마다 이미 fieldset/legend가 있어 낭독기가 그룹을 두 겹으로 읽는다) |
| 문항 | 기존 `<fieldset class="diag-question">` + `<legend>{번호}. {질문}</legend>` 그대로 |
| 판정표 | `.k-tablewrap` > `.k-table`, 레벨 열은 `<th scope="row">`, 가운데는 **`정답 수 / 문항 수`를 한 칸에** |

## 5. 05 §19-8 체크리스트 통과 확인 *(이 설계로 한 항목씩)*

| 항목 | 이 설계에서 |
|---|---|
| 읽어야 할 글이 가장 크고 진한가 | 레벨 화면: 지문 `--t-xl` > 보기 `--t-md` > 갈래 제목 `--t-md`(색으로 물러남) > legend `--t-sm --muted`. 결과: `.diag-headline` 26px가 최대 |
| 굵기를 제목에만 썼나 | 이 화면은 **지문을 굵히지 않기로** 이미 정했다(일본어 자형). 비어 있는 굵기 축을 라벨(legend·갈래 제목·알약)이 쓰고, 위계는 **크기·명도**가 만든다 |
| 보조 텍스트가 `--muted`인가 | `.quiz-note` · legend · `.diag-level-mark` 전부 `--muted`. **`--muted2` 0곳** |
| 카드가 페이지와 다른 면인가 | `.quiz-card` = `--card-bg`(`--surface-alt` 회색), 페이지 `--bg` 흰 |
| 면을 칠했다면 그 위 색을 전부 봤나 | **새로 칠한 면이 0개다.** 레벨 목록·갈래 어디에도 새 면을 만들지 않았다(§19-7 회피의 가장 확실한 방법) |
| 같은 종류 중 한 장만 튀지 않는가 | 레벨 6줄·문항 6장이 여백·크기·보기 개수까지 전부 같다. 갈래가 달라도 문항 블록은 같다 |
| 강조 수단이 하나뿐인가 / hover와 겹치지 않는가 | 선택 = 면 `--point-soft` 하나. hover는 글자색 `--point`뿐이고 **그림자는 꺼져 있다** — 겹치지 않는다 |
| 길이가 다른 글 아래 요소가 같은 높이인가 | 세로 스택이라 맞출 상대가 없다. 리듬은 `--sp-6`·`--sp-8` 고정 여백이 만든다(kana 줄 유무를 맞추지 않는 판단과 같다) |
| 아이콘·글리프가 옆 글과 높이가 맞는가 | 네이티브 라디오 + `align-items:center`. 커스텀 글리프를 만들지 않았다 |
| 헤더·본문 왼쪽 선이 맞는가 | `.diag-wrap` 640px 한 단 — 모든 줄이 같은 왼쪽 선이다 |
| 같은 정보를 두 번 말하지 않는가 | **판 1개일 때 판정표를 그리지 않는다**(머리글과 중복) · 번호를 갈래마다 되돌리지 않는다 · 시작 화면에 판정표를 얹지 않는다 |
| 감춘 것을 낭독기는 읽는가 | 감춘 것이 없다. **미렌더**만 있다(빈 갈래·없는 버튼·준비중 레벨) — 화면에도 DOM에도 없다 |
| 인셋에 `--surface-inset`을 쓰는가 | 알약이 그 토큰만 본다. **중간에 면을 끼우지 않았으므로** 상속 계산이 그대로 맞는다 |
| 공용 기본값 특이도가 0인가 | 공용 규칙을 새로 만들지 않았다. `.diag-levels`는 **선택자 목록에 더하는** 방식이라 기존 특이도가 변하지 않는다 |
| 라벨이 `--t-sm` 이상인가 | legend·`.quiz-note`·`.diag-level-mark` = `--t-sm`(최소선). 그 아래로 내려간 글자 없음 |
| 새로 쓴 토큰이 실재하는가 | §4 머리의 ⚠️ 목록에서 `tokens.css`·`project-tokens.css`를 직접 확인했다. **새 토큰 0개** |
| 이유가 사라진 규칙을 남겼나 | 계단 모델 문장 4개를 지웠다: *"최대 {n}단계까지 올라갑니다"* · *"제출하고 다음 단계로"* · *"{레벨} 단계는 …여기까지로 판단했어요"* · 첫 단계/2단계 분기 |
